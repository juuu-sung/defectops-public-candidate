# DefectOps 검사 워크스페이스

트랜지스터 사진을 검사하고 원본과 이상 지도를 비교하는 Three.js 작업대입니다. **실제 사진 검사**에서는 기존 DefectOps PatchCore API가 선택한 사진의 점수와 지도를 계산합니다. **합성 시연**에서는 세 가지 고정 사례로 사람의 관찰이 SOP·승인·모의 티켓까지 이어지는 과정을 체험합니다.

## 실행

Mac에서 실제 사진을 검사할 때는 연구실의 모델과 보정 파일을 한 번 복사하고 로컬 모델 서버를 실행합니다. 필요한 두 폴더와 복사·실행 명령은 [Mac에서 기존 모델 실행하기](../../docs/patchcore-local-api.md#mac에서-기존-모델-실행하기)에 있습니다. 같은 Mac의 다른 터미널에서 프로젝트 루트로 이동해 작업대를 시작합니다.

```sh
artifacts/envs/patchcore-cpu/bin/python output/defectops-inspection-lab/serve_lab.py
```

작업대는 기본적으로 같은 Mac의 8000번 포트에 연결합니다. 다른 주소로 이미 연결해 둔 API를 사용하려면 작업대를 시작할 때 `--api-url`에 해당 기본 주소를 지정합니다. 합성 시연만 실행할 경우 작업대 폴더 안에서 `python3 -m http.server 8791 --bind 127.0.0.1`을 사용할 수 있습니다. 각 서버는 실행한 터미널에서 `Ctrl+C`로 종료합니다. [실제 사진 검사 열기](http://127.0.0.1:8791/?mode=live) · [합성 시연 열기](http://127.0.0.1:8791/)

## 실제 사진 검사

1. **실제 사진 검사**에서 **모델 준비됨 · CPU**를 확인합니다. 작업대보다 모델 서버를 늦게 켰다면 **연결 다시 확인**을 누릅니다.
2. **트랜지스터 사진 선택**에서 1024 × 1024 RGB PNG 한 장을 고릅니다. 최대 크기는 50 MiB입니다. 프로젝트 데이터의 `data/transistor/test/bent_lead/000.png`로 연구실 기록과 같은 사진을 검사할 수 있습니다.
3. 미리보기에서 사진을 확인한 후 **실제 추론 실행**을 누릅니다. 서버가 반환한 이상 점수, 경고 기준, 검사 ID가 표시됩니다. 기준 이상이면 모델 경고이며 제품 판정에는 작업자의 검토가 필요합니다.
4. **원본·지도 비교하기**에서 이상 지도와 **원본에 겹쳐 보기**를 전환합니다. 사진을 누르면 원본 크기로 열립니다. 검사 ID가 포함된 현재 주소를 다시 열면 저장된 결과를 조회합니다.

GPU와 CPU를 대조한 검사 링크에서는 **GPU · CPU 비교**로 두 장비의 지도, 검사 원본과 픽셀별 점수 차이를 볼 수 있습니다. 두 이상 지도는 같은 색상 눈금을 사용하고, 점수 차이 그림에는 별도 눈금이 표시됩니다.

공식 정답과 대조한 미탐 검사 링크에서는 **정답 마스크 겹쳐 보기**가 원본과 맥북의 이상 지도에 같은 결함 영역을 민트색으로 표시합니다. **미탐 사진**에서 파일을 바꿀 수 있습니다. 아래 비율은 256 × 256 지도에서 모델의 픽셀 경고 기준에 도달한 정답 결함 픽셀의 비율입니다. 사진 한 장의 경고 여부에는 별도의 이미지 점수 기준을 적용합니다.

**사진 경고 기준 실험**에서 새로 경고된 정상 사진 15장을 선택할 수 있습니다. 각 사진에는 맥북 CPU와 연구실 GPU 점수, 기존 기준과 시험 기준의 경고 여부, 맥북에서 계산한 이상 지도가 함께 표시됩니다. [100장 전체 결과](../../reports/transistor-inspection-100/)

**불량·정상 이상 지도 비교**에서는 왼쪽에 `misplaced/002.png`를 고정하고 오른쪽에서 정상 사진 14장을 바꿔 볼 수 있습니다. **이상 영역**은 보정된 픽셀 기준을 넘거나 같은 곳을 원본 위에 분홍색으로 표시합니다. **이상 지도**는 두 검사의 연속 점수를 같은 색상 눈금으로 보여줍니다. 면적은 256 × 256 모델 지도에서 셉니다.

과거 실험의 지도를 다시 열려면 해당 장비의 `artifacts/inspections/`와 `artifacts/analyses/`에 저장된 검사·비교 자료가 필요합니다. 점수 실험은 해당 실험 폴더의 `per-image.csv`에서 `trial_gallery_url`, 면적 실험은 `comparison_url`을 여세요. 공개 저장소에서는 사진별 수치와 각 기준의 판정을 바로 볼 수 있습니다. [사진별 CPU·GPU 비교표](../../reports/transistor-inspection-100/per-image.csv)

원본·지도·검사 JSON은 모델이 실행된 컴퓨터의 `artifacts/inspections/<검사 ID>/`에 저장됩니다. Mac 실행 예시는 `--no-review-registration`을 사용해 시연 검사를 SQLite 검토 목록에 자동 등록하지 않습니다. 등록이 켜진 API에 연결하면 결과에 그 API의 등록 상태가 표시됩니다.

## 합성 시연 약 3분 동안 체험하기

| 사례 | 볼 곳 | 기록 예시와 후속 흐름 |
| --- | --- | --- |
| CASE 01 · 리드 외관 이상 | 왼쪽 리드의 굽힘과 몸체 상단의 지도 반응 위치가 다릅니다. | 이상 징후가 보임 → 리드 굽힘 모의 SOP r2 → 추가 확인 요청 초안 → 모의 승인 또는 반려 → 승인 시 모의 티켓 |
| CASE 02 · 정상 외관 재확인 | 예시 점수 0.71은 기준 0.65를 넘지만 원본에서 뚜렷한 외관 이상이 보이지 않습니다. | 눈에 띄는 이상 없음 → 외관 검토 종료. 제품 합격을 확정하지 않습니다. |
| CASE 03 · 검사 범위 가림 | 예시 점수 0.43은 기준 미만이고, 가림판 아래의 리드 형상은 보이지 않습니다. | 판단 보류 → 가린 위치와 이유 기록 → 사진 재확인 필요 |

1. CASE 01에서 **시연 시작**을 누릅니다. AI 이상탐지에서 원본과 지도를 비교한 후 **결과 확인하고 검토하기**를 누릅니다.
2. 작업자 검토에서 직접 쓰거나 **예시 의견 불러오기**를 눌러 문장을 고친 뒤 저장합니다. 작성자 역할, 시각, 검토 개정 번호가 남습니다.
3. **현재 개정에 근거 연결**을 누릅니다. 모의 SOP의 문서 개정과 원문 식별자, 당시 원문을 함께 보존합니다.
4. 모의 승인 단계에서 추가 확인 요청을 작성합니다. **초안 작성** 후 별도 버튼으로 승인 또는 반려합니다. 승인한 초안에서 **모의 티켓 생성**을 누릅니다.
5. **검토 의견 수정**을 눌러 내용을 바꾸고 새 개정을 저장합니다. 티켓 단계에서 새 승인이 필요하다는 안내를 볼 수 있습니다. 하단 **검토 개정**에서 이전 개정을 펼치면 그때의 근거·초안·결정·티켓을 다시 볼 수 있습니다.

모든 사례에서 세 가지 관찰 결과를 직접 선택할 수 있습니다. 리드 굽힘 모의 SOP는 CASE 01의 ‘이상 징후가 보임’에만 적용합니다. CASE 02·03에서 다른 의견을 남겨도 그 의견은 보존하며, 해당하지 않는 문서로 조치를 시작하지 않습니다. 같은 개정에서 반려한 초안을 다시 처리하려면 검토 내용을 보완해 새 개정을 작성합니다.

## 합성 시연 조작과 저장

- 단계 버튼, 3D 장비 또는 번호 표식을 선택하면 같은 단계의 작업 패널이 열립니다. 저장·승인·티켓은 현재 개정의 선행 기록을 확인합니다.
- 마우스로 드래그하거나 시점 도구를 눌러 회전·확대·축소·초기화합니다. 장면에 키보드 포커스를 두면 방향키로 회전하고 `+`, `-`, `0`으로 확대·축소·초기화합니다.
- 모바일에서는 한 손가락 가로 드래그로 회전하고 세로 드래그로 페이지를 스크롤합니다. 브라우저의 기본 핀치 확대도 사용할 수 있습니다. ‘크게 보기’로 원본과 지도를 확대할 수 있습니다.
- 장면은 시점이나 작업 상태가 바뀔 때 그립니다. 카메라 자동 재생이 없고, 동작 줄이기 설정에서는 화면 전환 효과를 끕니다. WebGL을 사용할 수 없으면 단계 선택이 가능한 2D 배치도를 표시합니다.
- 기록은 현재 브라우저의 같은 주소·포트에 사례별 `localStorage`로 보관합니다. 선택한 사례와 단계는 URL에 남습니다. 다른 기기로 동기화되지 않습니다. 저장 실패는 화면에 표시하고 기존 저장 기록과 작성 중 문구를 보존합니다.
- **사례 초기화**에서 대상 사례를 확인한 뒤 지울 수 있습니다. 브라우저 사이트 데이터를 지우면 해당 브라우저의 기록도 사라집니다.

## 실제 검토 기록

로컬 프로토타입의 대표 서비스 모델은 저장된 트랜지스터 PatchCore입니다. 실제 GPU 자동 등록 사례에서는 검토 의견과 SOP 연결까지, 이전 수동 등록 사례에서는 승인과 모의 티켓까지 확인했습니다. MPI-PCB 등 다른 데이터의 실험은 연구 범위입니다. [프로젝트 README](../../README.md) · [자동 등록 확인 기록](../../docs/api-review-integration.md)

실제 API는 새 검사마다 검사 ID를 발급합니다. 같은 검사 주소를 열거나 실패한 이미지만 다시 불러올 때는 기존 ID로 조회합니다. 실제로 등록된 검사에 의견과 근거를 남길 때는 프로젝트의 검토 UI를 사용합니다. 합성 시연의 모의 승인·티켓은 해당 브라우저에 저장됩니다. [검사 API](../../src/defectops/inspection_api.py) · [검토 저장소](../../src/defectops/review_store.py)

| Mac CPU 사진 검사 | 연구실 모델과 별도로 만든 미학습 테스트 가중치로 사진 두 장을 전송해 서로 다른 점수·지도를 얻음. API가 반환한 원본·이상 지도·겹친 지도의 체크섬, 검사 ID 재조회, 이미지 재시도, 연결 끊김·복구 및 320~1440px 네 너비를 확인 |
