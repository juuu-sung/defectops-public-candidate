# DefectOps · 3D 검사 흐름 시연

전자부품 품질 담당자가 저장된 사진을 검토하고 판단 근거를 남기는 상황을 Three.js로 표현한 독립 프런트엔드 프로토타입입니다.

## 실행

이 폴더에서 실행합니다.

```sh
python -m http.server 8786 --bind 127.0.0.1
```

브라우저에서 http://127.0.0.1:8786/ 을 여세요. JavaScript 모듈 때문에 HTML 파일을 직접 더블클릭하는 대신 HTTP 서버를 사용합니다. GPU 학습, Python 패키지 설치, 실제 모델 파일이 필요하지 않습니다. Three.js는 vendor에 포함되어 있습니다.

## 체험

1. CASE 01을 선택하고 검사 요청 시연을 누릅니다.
2. 합성 원본과 합성 지도를 비교합니다.
3. 확인 결과를 선택하고 검토 의견을 저장합니다.
4. 이상 징후 관찰인 경우 모의 SOP를 연결합니다.
5. 초안 작성 → 모의 승인 → 모의 티켓 발행을 진행합니다.
6. 의견을 수정하면 새 개정이 생기고 현재 승인·근거가 초기화됩니다. 과거 의견과 티켓 이력은 남습니다.
7. CASE 02와 03에서는 각각 '눈에 띄는 이상 없음', '판단 보류'로 저장해 분기를 확인할 수 있습니다.

단계 버튼은 자유롭게 이동할 수 있지만 작업 버튼은 선행 기록이 필요합니다. 3D 화면은 드래그로 회전하고 스크롤로 확대합니다. 작은 화면에서는 작업 패널이 3D 장면 아래에 배치됩니다.

## 범위

- 부품 그림·이상 지도·점수·모델 이름은 모두 합성 예시입니다.
- 실제 추론, 기존 검사 API, SQLite, 사용자 인증, MES/QMS에는 연결되지 않습니다.
- 기록은 현재 브라우저의 localStorage에만 보관됩니다. 브라우저 자료 삭제 시 사라집니다.
- 같은 개정의 모의 티켓을 중복 생성하지 않습니다.
- '눈에 띄는 이상 없음'은 제품 합격 판정이 아닙니다.
- 모의 SOP와 승인·티켓은 실제 생산품 처리나 외부 전송을 수행하지 않습니다.
- 현재 브라우저에 보이는 기록에는 개발 과정의 합성 검증 기록이 포함될 수 있습니다. 페이지 하단에서 사례별 시연 기록을 초기화할 수 있습니다.

## 확인한 동작

- 검사 등록 → 검토 revision 1 → SOP → 초안 → 승인 → 모의 티켓
- 동일 티켓 재요청 시 신규 생성 없음
- 새로고침 후 의견·티켓 유지
- 의견 revision 2 저장 후 기존 승인 재사용 차단, 이전 이력 보존
- 판단 보류 / 눈에 띄는 이상 없음에서 SOP 연결 차단
- 1440px와 390px 화면에서 문서 가로 넘침 없음
- 브라우저 오류·경고 로그 없음

이는 합성 프런트엔드 동작 검증이며 실제 서비스 통합이나 모델 검증이 아닙니다.
