# MPI 입력 검토 의견 저장 사용법

2026-10-14. 정상 입력 점검 결과를 보면서 사진·영역별 관찰, 검사 범위의 근거, 판단 이유, 작성자와 수정 이력을 저장한다. 모델·경고선·원본 점검 JSON은 읽기 전용으로 유지한다. 의견을 저장해도 제품 합격, 불량 확정, 조치 승인이나 기존 오경보 감소가 되지 않는다.

## 화면과 저장 위치

- 새 의견 저장 화면: `http://127.0.0.1:8770/`
- 기존 `8769` 화면: 변경하지 않은 읽기 전용 자료
- 입력: `mpi-normal-input-assessment-v1-archive.zip` 한 버전만 허용하며 ZIP 및 내용 해시를 확인한다.
- 별도 DB: 프로젝트의 `artifacts/review/mpi-input-notes-v1.sqlite3`
- 원본 `human_assessment=NOT_RECORDED`는 수정하지 않는다. 새 의견은 별도 DB에서 원본 ZIP·보고서·정책·관련 타일 지문과 연결된다.

512사진을 모두 볼 수 있고 입력 확인 대상 32장을 먼저 표시한다. 원본이 첨부되지 않은 영역은 통계만 표시하며, 원본이 있다고 오인하지 않도록 안내한다. 화면에 AI 관찰을 사람 의견으로 자동 등록하거나 미리 입력하지 않는다.

## 시작하기

기존 API 실행 환경의 `fastapi`, `uvicorn`을 사용한다. 별도 모델·GPU·새 라이브러리는 필요하지 않는다. 이 의존성이 없는 새 환경은 프로젝트의 `requirements/api.txt` 설치 절차를 따른다.

Mac에서 ZIP이 Downloads에 있는 경우, 저장소 루트에서 다음을 실행한다.

```sh
.venv/bin/python scripts/serve_mpi_input_review.py --bundle "$HOME/Downloads/mpi-normal-input-assessment-v1-archive.zip"
```

Windows에서 ZIP이 기존 `artifacts/handoff`에 있는 경우, 코드가 해당 컴퓨터에 전달된 뒤 실행한다.

```powershell
Set-Location 'C:\개인 프로젝트\defectops'
& '.\.venv\Scripts\python.exe' '.\scripts\serve_mpi_input_review.py'
```

터미널을 유지하고 같은 컴퓨터의 브라우저에서 `http://127.0.0.1:8770/`을 연다. 서버를 중단해도 저장한 의견은 DB에 남는다. `--db`로 별도 DB, `--port`로 로컬 포트를 지정할 수 있다. 다른 자료 버전의 DB나 기존 transistor 검토 DB는 이 기능에 재사용할 수 없다.

## 의견을 작성하는 순서

1. 사진 ID를 열고 원본을 확인한다. 아래의 ‘의견 작성으로 이동’ 링크로 입력란에 이동할 수 있다.
2. 관찰과 관련된 영역을 선택하고 작성자 이름을 직접 입력한다.
3. 보이는 사실과 위치를 적는다. 제품의 전기적 접속 상태 등 사진에서 확인할 수 없는 내용은 단정하지 않는다.
4. 필수 검사 범위의 근거가 없으면 ‘미정’을 유지한다. 문서가 있다면 범위와 문서·절·위치를 모두 적는다. 문서 입력 자체가 근거의 승인 또는 적정성 검증은 아니다.
5. ‘선택한 필수 부위가 보이는가?’라는 질문에 확인됨·확인되지 않음·판단 불가를 선택하고 이유를 적는다. 검사 범위가 미정이면 판단 불가만 저장할 수 있다.
6. 의견 저장을 누르고 저장 안내와 수정 이력을 확인한다. 기존 모델 경고는 별도 펼침 영역에서 확인한다. 이는 강제 맹검 기능이 아니다.

전체가 검은 타일은 그 타일 자체에 요구 정보가 보인다고 기록할 수 없다. 원본이 첨부되지 않은 영역도 이 화면에서 ‘확인됨’으로 저장할 수 없다. 선택 영역 이외의 사진 전체가 적합하다는 뜻으로 해석하지 않는다.

## 수정과 충돌 처리

다시 열면 이전 의견 내용이 입력란에 나타나며 작성자 이름과 수정 이유는 새로 입력한다. 수정은 r1, r2처럼 새 기록을 추가한다. 이전 내용·작성자·UTC 작성 시각·입력 지문은 이력에 남는다. UI에 삭제·승인·합격 버튼은 없다.

저장 버튼 중복 제출은 같은 요청의 한 기록만 만든다. 두 창에서 같은 개정을 수정하면 먼저 저장한 기록을 유지하고 뒤 요청에는 충돌을 알린다. 충돌 화면은 입력을 보존한다. 작성 내용을 따로 보관하고 최신 기록을 다시 연 뒤 수정 이유와 함께 저장한다. 자동 병합이나 덮어쓰기는 하지 않는다.

검증 실패 시 입력 내용을 유지하며 무엇을 고쳐야 하는지 표시한다. 저장 오류가 나면 완료로 표시하지 않는다. 기존 파일을 삭제하지 말고 이력에서 저장 여부를 확인한다.

## 내보내기와 보관

목록의 ‘전체 의견 이력 JSON 내려받기’로 모든 개정과 출처 지문을 보관할 수 있다. JSON은 검토용 내보내기이며 DB 복원·자동 재가져오기 기능은 아니다.

DB를 백업할 때는 이 서버를 정상 종료한 다음 DB 파일을 복사한다. 같은 입력 ZIP과 코드로 그 백업 DB의 별도 경로를 `--db`에 지정해 열 수 있다. 기존 DB를 덮어쓰거나 의견 파일을 GitHub에 올리지 않는다. 자동 백업이나 재해 복구 기능은 제공하지 않는다.

## 보안과 적용 한계

이 서버는 127.0.0.1에만 바인딩한다. 작성자 이름은 자기 기입이며 로그인·본인 인증·사용자별 권한 통제는 없다. 공용 서버나 생산 환경에 공개하지 않는다. HTML 출력 이스케이프, 교차 출처 저장 차단, 요청 토큰, 폼 크기 제한을 적용한다.

SQLite의 UPDATE·DELETE 방지 트리거와 개정 검사는 일반적인 앱 경로의 기록 변경을 막는다. DB 관리자나 파일 소유자의 의도적인 변조를 막는 감사 인증 체계는 아니다. 원본 ZIP을 바꾸거나 다른 버전의 DB를 섞으면 시작을 거부한다.

현재 의견 저장 기능은 MPI 연구 전용으로 기존 transistor API·SOP·티켓 승인·모델 성적과 연결하지 않는다. 입력 적합 정책의 성능 검증도 아니다. [입력 관찰 보고서](../reports/mpi-normal-input-visual-review-v1.md)의 검사 범위 미정 상태는 의견 저장 기능을 만들었다고 해소되지 않는다.
