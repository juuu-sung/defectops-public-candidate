# MPI-PCB 동일 영역 검색 대조

기준일: 2026-09-28. **Windows GPU 결과 수령·검토 완료.**
[결과](../reports/mpi-pcb-region-search-v1.md): 후보는 검출22/55·미탐33/55·정상 오경보7/54로
기존 A(검출33·미탐22·오경보3)보다 악화됐다. 시간은 단축됐으나 서비스 교체는 하지 않는다.
다음은 [두 방식 저장 지도 비교](mpi-pcb-region-map-review.md)다. 아래는 해당 실험의 고정 규칙이다.

## 이번에 답할 질문

기판 한 곳의 불량이 다른 곳의 정상 부품과 비슷하다고 비교되어 미탐하는가?
[패치 출처 진단](../reports/mpi-pcb-patch-trace-v1.md)에서 대표 미탐의 이런 사례를 확인했다.
그러나 정상이나 검출 성공 사례에서도 다른 영역 매칭이 있었다. 따라서 출처가 다르다는
사실만으로 오매칭이나 미탐 원인을 확정하지 않고, **비교 범위만 제한한 대조**를 한다.

예를 들어 grid3-2의 입력 패치는 기존에는 12영역의 정상 예시를 모두 검색했다.
후보에서는 그중 출처가 grid3-2인 정상 예시만 검색한다. **grid3-2 안의 정확히 같은
좌표로 제한하는 것은 아니다.** 학습 사진 추가, 특징층·해상도 변경, 자료 정제도 하지 않는다.

## 두 방식의 차이

| 항목 | 기존 A | 후보 A |
| --- | --- | --- |
| 저장 모델 | 기존 MPI PatchCore checkpoint | 동일 checkpoint, 저장 파일 수정 없음 |
| 원래 학습 자료 | 정상 64장 × 12영역 | 동일 |
| 특징/입력 | 고정 layer1+layer2, 768차원, 256×256 | 동일 |
| 정상 bank | 공유 78,643개 벡터 | 같은 벡터 중 해당 영역 출처의 행만 검색 |
| 패치 출처 | 구분 없이 비교 | 정확한 원래 특징 해시로 출처 확인 |
| 지도·이미지 점수 | 기존 평활화 지도 상위 1% 평균 | 같은 계산 |
| 영역 정상 수준 | 별도 정상 128장의 중앙값·MAD | 같은 128장을 후보로 계산하여 다시 산출 |
| 원본 사진 점수 | 12영역 보정 점수 중 최대 | 동일 |
| 경고 기준 | 정상 169장으로 정한 기존 5.4966275137 | 같은 169장의 후보 점수, 동일 95% higher 분위수 |
| 시험 | 이미 관찰한 109장 | 같은 109장 |

검색 범위가 줄면 불량뿐 아니라 **정상의 거리 점수도 오를 수 있다.** 기존 임곗값만
그대로 적용하면 그 상승 자체를 성능 개선으로 착각할 수 있다. 그래서 후보의 정상화와
임곗값은 같은 정상 자료·같은 규칙으로 별도 산출한다. 기준선 A의 수치·성적은 보존한다.
이는 검색 범위 변경에 맞춘 정상 보정이며, 시험 불량을 보고 임곗값을 낮추는 작업이 아니다.
보정 사진 `0411`도 유지한다. 이 사진의 정상 정의 문제와 검색 제한을 섞어 바꾸지 않는다.

후보는 **영역마다 coreset을 새로 만든 모델이 아니다.** 기존 공용 coreset에 특정 영역의
정상 예시가 적게 남았다면 그 부족까지 포함한 제한 실험이다. 실패해도 모든 영역별 모델이
효과 없다는 결론은 아니다. 모든 정상 패치를 보존하는 전체 패치 실험도 아니다.

## 실행 순서

1. **기존 모델 확인**: 기존 ZIP·코드·checkpoint·데이터 해시, 환경, 정상 점수 재현 확인.
2. **bank 전체의 출처 복원**: 원래 학습 64장/768영역을 한 타일씩 재계산한다.
   원래 stride2 후보 786,432개를 조회하여 bank 78,643행의 출처를 연결한다.
   역전파·coreset 재선정 없이 특징만 다시 계산한다. 모든 후보를 GPU에 쌓지 않는다.
3. **정상 비교와 후보 보정**: 별도 정상 개발 128장과 보정 169장을 두 방식으로 처리한다.
   후보 중앙값/MAD·경고 기준을 파일로 고정한 뒤 시험 점수 계산을 시작한다.
4. **동일 시험 109장 비교**: 두 방식 모두 같은 사진을 처리한다. 전체 bank의 기존 top1·A
   점수는 0.0001 이내 재현하고, 기존 A 판정은 정확히 같아야 한다.
5. **결과 저장**: 검출/미탐/오경보, 새 검출·새 미탐의 사진 목록, 비교 시간, GPU 메모리,
   영역별 bank 수, 출처 명단을 JSON과 한국어 HTML로 정리하여 별도 ZIP을 만든다.

### 출처 및 입력 무결성 규칙

- little-endian float32 특징 SHA256의 정확한 일치만 인정한다. 비슷한 값으로 대체하지 않는다.
- 같은 값의 출처가 여러 영역이면 **모든 해당 영역에서 허용**한다. 임의 첫 출처로 배정하지 않는다.
- bank의 중복 벡터 행도 원래 index·순서를 보존한다. 영역별 행 수 합계는 중복 출처 때문에
  전체 bank 크기보다 클 수 있다.
- 한 행이라도 미확인, 한 영역이라도 9개 미만, 정상 MAD 퇴화라면 중단한다.
  공용 bank로 우회하거나 정상 수를 임의로 줄이지 않는다. 9는 기존 native 가중 점수의 이웃 수다.
- GPU에서는 해당 영역의 원래 행을 임시 선택하고 추론 후 원래 bank 객체로 복구한다.
  실패 시에도 복구하며, 단계별·종료 시 원래 bank 전체 해시를 재확인한다.
- 같은 입력에 대한 제한 bank 거리는 수학적으로 전체 bank보다 작아질 수 없다. 평활화 맵에서도
  이 관계를 절대 오차 0.002 범위로 확인한다. 어기면 수치/구현 검토를 위해 중단하며 자동 완화하지 않는다.
- 중단 후 같은 명령으로 재개한다. 사진별 완결 기록·해시·보정 계약·정상 gate를 확인하고 재사용한다.
  실제 GPU 작업이 남았으면 새 프로세스에서 정상/특징/후보 gate를 다시 실행한다.
- 원본·기존 결과를 삭제하거나 덮어쓰지 않는다. bank 무결성 차단, 입력 변경, 미확인 출처 오류는
  반복 실행하지 말고 공유한다. 미완료 임시 폴더도 보존한다.

## 평가 범위와 시간 해석

불량 55장·정상 54장, 총 109장이며 `good/0013` 중복 제외를 유지한다.
복구 `defect/0054` 제외 108장 결과도 함께 낸다. `defect/0006`은 이미지 분류에 유지한다.
이번에는 **마스크를 읽지 않고 새 위치 성능도 계산하지 않는다.** 후보 시험 지도는 로컬에
저장한다. 후속 위치 분석을 한다면 `defect/0006` 전체 사진을 위치 분모에서 제외해야 한다.

이미 본 시험에 맞춰 가설을 세웠으므로 결과는 탐색·회귀 비교다. 독립 일반화나 공장 성능의
증명이 아니다. 자동 PASS·서비스 교체·티켓 발행은 하지 않는다.

- 같은 타일을 한 번 읽고 각 방식으로 특징 추출부터 끝까지 별도 추론한다.
- 타일 순서에 따라 첫 실행 방식을 교대한다. 한 원본의 12영역에서 각 방식이 6번 먼저 실행된다.
- 보고 시간은 **원본 한 장의 12영역 전처리·특징 추출·탐색·맵 전송 합계**다.
  후보 subset 선택 비용도 포함한다. 공통 디코딩, 모델 로딩, JSON/NPZ 저장, HTTP는 제외한다.
  API 전체 응답 시간 또는 현장 처리량으로 해석하지 않는다.
- GPU peak는 두 방식을 한 프로세스에서 실행한 PyTorch 메모리다. 방식별 독립 메모리 비교는 아니다.
- 이 실행에는 기존의 무거운 coreset 학습이 없다. 그래도 출처 해시·원본 읽기·두 방식 추론이
  필요하므로 실제 총시간과 추가 메모리는 측정 전 확정하지 않는다.
- 시험 후보 맵은 압축 전 약 327 MiB다. JSON 출처 명단·임시 시도 등도 있으므로 디스크 여유를 둔다.
  ZIP에는 이미지·모델·맵 배열을 넣지 않고 JSON과 HTML만 담는다.

## 연구실 Windows에서 하실 일

다른 GPU 작업은 정상 종료한다. 현재 가상환경과 자료를 그대로 사용하며 재설치·재다운로드·
재학습은 필요 없다. `git pull` 실패 시 다음 명령을 실행하지 않는다.

```powershell
Set-Location "C:\개인 프로젝트\defectops"
git pull --ff-only
if ($LASTEXITCODE -ne 0) { throw "git pull failed. Stop and share the error." }
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\scripts\run_mpi_region_search.ps1"
```

완료 후 첨부할 파일:

`C:\개인 프로젝트\defectops\artifacts\handoff\mpi-pcb-region-search-v1.zip`

결과를 직접 보는 명령:

```powershell
Start-Process ".\artifacts\analyses\mpi-pcb-region-search-v1\result\index.html"
```

이번 출력 폴더는 `artifacts/analyses/mpi-pcb-region-search-v1`이다. 현재 API 모델과 검토 이력은
변경하지 않는다. 이전 출처 진단 ZIP도 기존 `artifacts/handoff`에 그대로 있어야 한다.

## 결과를 받은 뒤 결정할 것

기존 A 기준은 **TP33 / FN22 / FP3 / TN51**이다.

1. 동일 A 결과가 재현됐는지, 출처가 전체 연결됐는지 먼저 검증한다.
2. 미탐 감소와 새 미탐을 함께 보고, 정상 오경보 3장보다 증가했는지 확인한다.
3. 미탐이 줄고 오경보가 늘지 않으면 후속 검토 가치가 있다. 두 지표가 상충하면 이득/비용을
   사용자와 검토한다. 시험 점수로 새 임곗값을 선택하거나 자동 승격하지 않는다.
4. 변화가 작거나 악화됐다면 해당 가설의 한계로 기록한다. 정상 대표성·영역 내 위치 문맥 등
   다른 변경을 한 번에 섞지 않고 다음 한 요인만 정한다.

## 구현 검증

Mac CPU 합성 runtime으로 실제 PNG 읽기, 전체 출처·복수 출처·영역 제한, 정상 보정→시험 순서,
기존 점수/판정 재현, 중단 재개, 파일 변경 차단, 모델 복구, JSON·HTML·ZIP 출력을 시험한다.
새 테스트 19개 통과. 전체 **353개 + 하위 테스트52개 통과**, 기존 경고3개.
실제 수령 ZIP으로 기존 소스59개 해시, 학습/평가 연결, A 보정 계약, 정상128/169장과
시험109장 명단을 확인했다. 원본 무결성 점검 목록110장과 최종 시험109장은 구분한다.
명령은 `.venv/bin/python -m pytest -q`다. Windows PowerShell 실행 및 실제 CUDA 추론·성능은
연구실 결과를 별도로 확인해야 한다. 새 Python 실행기 이름은 기존 frozen identity의
`*mpi_pcb*.py` 범위를 피하며, 기존 학습/평가 Python 소스·설정은 수정하지 않는다.
