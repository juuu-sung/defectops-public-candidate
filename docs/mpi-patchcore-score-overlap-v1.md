# MPI PatchCore 정상 고점수와 약한 불량 대조

개발자료 256장 후보에서 불량 0024보다 점수가 높거나 같은 정상 14장을 고정해 대조한다. 이번 작업은 재학습이나 점수 변경이 아니라, 다음 변경을 정하기 위한 읽기 전용 진단이다. 현재 55/55 검출을 유지하는 경고선만 조절해서는 오경보가 최소 14장 남는다는 점을 출발점으로 삼는다.

## 저장 점수로 확인한 사실

정상 14장 모두 각 사진의 주 반응 영역 원점수가 불량 0024의 주 반응 영역 원점수보다 높다. 따라서 영역별 보정만으로 생긴 순위 역전이라고 설명할 수 없다. 다만 서로 다른 영역의 원점수는 정상 분포가 다르므로 그대로 결함의 크기나 심각도로 비교하지 않는다.

grid4-2가 주 반응인 정상 0276·0961·1390은 작은 정상 폭이 점수 차이를 더 키우는 방향으로 작용했다. 나머지 다른 영역 10장의 폭은 반대로 차이를 줄이는 방향이었다. 0706은 불량 0024와 같은 grid3-2가 주 반응이며 동일한 중심·폭을 적용받는다. 이 한 쌍에서도 정상 원점수가 1.1680 높다.

수치 분해는 두 주 반응 영역의 `(원점수−정상 중심)/정상 폭` 차이에 대해 원점수·중심·폭을 바꾸는 여섯 순서를 평균한 산술 분해다. 물리적인 촬영 원인의 인과분석이나 새로운 판정 규칙이 아니다. 동일 영역 원점수 차이도 별도로 남겨 다른 영역끼리의 비교만으로 원인을 단정하지 않는다.

## 연구실에서 가져올 자료

정상 14장과 불량 0024, 총 15장의 모든 12영역을 포함한다. 총 180개 원본 타일·저장 지도와 불량 0024의 12개 원본 정답 mask·기존 규칙으로 읽은 이진 mask를 전달한다. 빈 mask도 유지한다. 점수가 높은 부위만 골라서 실제 결함 부위를 숨기지 않는다.

각 타일에는 원점수, 중심·폭, 정규화 점수, 경고 경계, 원본·지도 영수증과 위치 통계를 함께 보관한다. 시각 검토는 원본과 실제 배열로 수행하며 자동 대비를 조정한 열지도 색만으로 사진 간 강도를 비교하지 않는다. 실제 top1 점수와 위치 통계는 float64로 계산한다.

원본 ZIP 전체 해시, 두 입력 결과 ZIP 해시, 사진·지도 캐시 영수증, 원본 바이트/RGB 지문, mask 지문과 의미를 검증한다. 지도를 다시 읽어 상위 1% 점수가 이전 점수와 일치해야 한다. 누락·변조 시 새 추론으로 채우지 않고 중단한다. 모델 파일은 로드하지 않는다.

## 실행 방법

```powershell
Set-Location 'C:\개인 프로젝트\defectops'
git pull --ff-only
if ($LASTEXITCODE -ne 0) { throw 'Git update failed; stop here.' }
powershell.exe -NoProfile -ExecutionPolicy Bypass -File '.\scripts\run_mpi_patchcore_score_overlap.ps1'
```

기본 원본은 `Downloads\extracted.zip`이다. `artifacts\handoff`의 기존 개발자료 확대 및 PatchCore 확대 결과 ZIP과 `artifacts\analyses\mpi-patchcore-scaling-v1`의 시험·정상검증 지도 캐시를 그대로 둔다.

완료 후 `C:\개인 프로젝트\defectops\artifacts\handoff\mpi-patchcore-score-overlap-v1.zip`을 비공개로 전달한다. 데이터 사용권을 확인하지 않은 공개 이미지·mask 재배포는 하지 않는다.

GPU, 새 추론, 학습, 경고선 조정은 없다. 파일 읽기·검증·압축 시간은 필요하며 시간 상한은 없다. 실행 중 원본과 캐시를 변경하지 않는다. 중단되면 같은 명령으로 처음부터 다시 읽되 기존 결과를 덮어쓰지 않는다. 동일한 완료 ZIP은 검증 후 재사용하며 다른 내용이면 중단한다. 오류가 나면 파일을 보존하고 전체 오류를 전달한다.

## 다음 판단

지도와 실제 위치를 받은 후 정상 외관 자체의 높은 반응인지, 영역 척도 영향인지, 작은 결함 위치의 반응 부족인지 나눈다. 정상 라벨을 바꾸거나 사진을 삭제하지 않는다. 이번 자료는 이미 관찰한 사례를 고른 진단이며 새로운 일반화 성능 평가가 아니다. 근거가 모이면 변경 한 가지만 제안하고, 그 전에는 모델·개발자료·보정자료·기존 서비스·자동 PASS 금지 정책을 유지한다.
