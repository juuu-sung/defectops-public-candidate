## 1. 이번에 확인할 질문

> 같은 정상64장과 같은 크기의 PatchCore 기준표를 쓰더라도, 정상 외관의 다양성을 기준으로
> 사진을 고르면 기존 불량 검출을 보존하면서 정상 오경보와 보정 표본 민감도를 줄일 수 있는가?

[정상5장 지도 진단](../reports/mpi-normal-map-review-v1-received-review.md)에서는 검은 경계뿐 아니라
커넥터 핀·콘덴서 옆면에도 높은 반응이 있었다. 정상 외관의 범위가 기존 학습64장에 충분히
포함되지 않았을 가능성을 시험한다. **학습 다양성 부족이 원인으로 확정된 것은 아니다.**

PatchCore가 정상 패치의 특징을 기준표에 저장한다는 원리는 [원 논문](https://arxiv.org/abs/2106.08265)에
근거한다. 아래의 원본사진64장 선정 규칙은 이 프로젝트의 실험적 설계이며 논문의 성능 보장이 아니다.
정상으로 허용하는 범위가 넓어져 오히려 작은 불량까지 정상과 비슷하게 판단할 위험이 있다.
평균 특징은 작은 부위 변화를 놓칠 수 있고, 거리 기반 선정은 드문 촬영 이상을 과대표집할 수 있다.

사이클1의 후보2/2를 위한 카드다. 후보1의50% 부분 공유는 검출53→42장으로 실패했다.
이번 준비·메타데이터 감사 자체는 학습 실행이 아니다. 후보2 학습을 시작하면 실행 후보로 기록하며,
결과가 나쁘다고 선정법·장수·seed를 바꿔 추가 후보를 자동 생성하지 않는다.

## 4. 사진64장 선정 규칙 — 결과를 보기 전에 고정

1. 기존 동결 특징 추출기와 전처리로 후보1,086장×12영역=13,032타일의 특징만 추출한다.
   최근접 검색·이상 점수·마스크는 사용하지 않는다. batch1,eval,no gradient,증강 없음,seed42다.
2. 각 타일에서 기존 패치 융합 직후·stride2 적용 전의768×64×64 특징을 공간 평균한다.
   768차원 벡터를L2 정규화하고,고정12영역 순서로 연결한 후sqrt(12)로 나눈다.
   이9,216차원 벡터는 사진 선정용이다. 실제 PatchCore 학습 패치를 평균 벡터로 대체하지 않는다.
3. 특징과 저장 벡터는float32,선정 거리·중심 계산은CPU float64다. 비유한 값 또는 영역 벡터
   norm≤1e-12면 중단한다. 후보 풀 평균 벡터에서 유클리드 제곱거리가 가장 가까운 사진을 첫 장으로 고른다.
4. 이후에는 이미 고른 사진들과의 **최소 거리**가 가장 큰 사진을 한 장씩 추가해64장을 채운다.
   정확 동점이면 `SHA256("mpi-normal-diversity-v1\0" + photo_id)`,그다음ID 오름차순으로 정한다.
   결과를 보고 seed·거리·특징 정규화·제외 규칙을 바꾸지 않는다.
5. 선정 순위는 보존하되 실제 학습 입력은 기존 해시 순서로 정렬한다. 이렇게 학습 순서 규칙도 유지한다.
   선택ID·12영역 지문·벡터 파일·알고리즘/환경 해시를 저장하고 잠근다.

전체 풀의 중심/거리 계산은 정상 후보 안에서만 수행한다. 보정·검증 특징으로 선정법을 맞추지 않는다.
새64장이 기존64장과 같으면 변경 없음으로 종결한다. 다시 뽑아서 다른 결과를 만들지 않는다.
평균 최근접 거리·최대 최근접 거리·영역별 거리 요약과 두 명단 겹침을 보고하되,
이 수치가 좋아지는 것은 선정 목적함수의 결과이지 불량 검출 개선 근거가 아니다.

## 5. 학습·보정·평가와 통과 기준

선정 명단 고정 후에만 새bank를 만든다. 기존 전처리·특징·stride·coreset·검색을 유지한다.
새 모델로 정상128장의 영역별 `median`, `q90(higher)-median`을 계산한다.
폭≤1e-6 또는 비유한 값이면 실패한다. 정상169장의 정규화된12영역max를 계산하고
95% higher 분위수를 새 사진 기준으로 잠근다. 경고 비교는 `>=`다.
짝수 중앙값은 가운데 두 값 평균, higher 인덱스는0-based `ceil(q*(n-1))`이다.

저장·재로드 전후 정상297장(128+169)의 타일 원점수 최대 절대차≤1e-4,
고정 후보 기준에서 사진 판정 변화0을 요구한다. 척도·임곗값은 재로드 결과에 맞춰 몰래 교체하지 않는다.
기준선의 저장 점수로 Q90을 재계산할 때는 기존 계약 차≤1e-12·판정 변화0을 요구한다.
그 뒤 새 후보로 관찰된109+256장을 평가한다. 라벨은 모델·척도·임곗값을 잠근 뒤 비교에만 쓴다.

**고정 성적·보정 민감도·비용을 각각 판정하고 모두 통과해야 연구 우선 후보가 된다.**

- 불량55장 중 최소53장 검출,기존에 잡던53장 중 새 미탐0장. 두 기존 미탐의 회복도 별도 보고한다.
- 정상 오경보≤2/54 및≤12/256. 기준선3/54·14/256 대비 최소1장·2장 개선이다.
- 정상 개발만/보정만/둘 다 재표집:각1,000회,사진 단위 복원추출,12영역을 함께 취급한다.
  두 모델에 동일 인덱스를 적용하고 각 모델의 저장 정상 점수에서 척도와 기준을 다시 계산한다.
  모델 재학습 bootstrap이 아니며 학습 선정/seed 불확실성까지 검증하지 않는다.
- PCG64 seed20261001/20261002/20261003,둘 다인 경우 개발128개 다음 보정169개 순서.
  각 상황에서 TP2.5분위≥50,TP97.5−2.5분위 폭≤동일 반복 기준선 폭의절반,
  FP97.5분위≤5/54 및≤25/256,실패 반복0회. linear 분위수,반올림·실패 제거 금지.
  기준선 폭0이면 후보도0이어야 한다. 이는 새 제품 성능의 신뢰구간이 아닌 표본 민감도 진단이다.
- 동률이면 기존 모델 유지. 고정 성적만 개선되거나 안정성/비용 중 하나라도 실패하면 미통과다.
  기존 검출 손실0 조건으로 관찰 사례의 회귀를 제한하지만 결함군별 독립 성능을 보장하지 않는다.

이번에는 image/사진 판정이 목적이다. 새 pixel 지표나 마스크 기반 사진 선정은 하지 않는다.
새 독립 불량 자료가 없으므로 통과해도 독립검증·현장/서비스 사용 승인은 별도다.

## 6. 자원 예산과 측정 — 구현 전에 정한 계획 상한

장비: 연구실 Windows RTX 5060 8GiB, RAM 32GiB, Python 3.12.0, torch 2.8.0+cu128,
torchvision 0.23.0+cu128, anomalib 2.2.0. 다른 GPU 작업 종료 후 실행한다.

| 단계 | 누적 실행 시간 상한 | GPU reserved 상한 | 프로세스 RSS 상한 |
| --- | --- | --- | --- |
| 정상 특징·사진 선정 | 1시간 | 6GiB | 20GiB |
| 새fit+정상128/169보정+재로드 | 4시간 | **7GiB** | 20GiB |
| 관찰자료 추론·재표집·비용 비교 | 2시간 | 6GiB | 20GiB |

이 수치는 승인된 생산 SLA가 아니라 제안한 실행 중단 예산이다. 기존 fit의 PyTorch reserved peak가
약6.514GiB였으므로 추론6GiB 목표를 학습에 그대로 적용하지 않는다. 같은 bank 크기가 같은 peak를 보장하지 않는다.
GPU allocated/reserved는 단계별 reset 후 peak를, 프로세스 RSS와 GPU 전체 점유는100ms 주기 표본의 max를 기록한다.
표본 peak는 진짜 순간 최대의 상한이 아니다. 단계/타일/coreset 경계에서 예산을 검사하므로 한 연산이 상한을
넘기기 전에 항상 차단할 수 있는 hard limit는 아니다. 초과·OOM·필수 측정 누락은 비용 통과로 처리하지 않는다.
재개해도 완료 조각의 실행 시간을 더하며 대기·중단 시간은 별도 보고한다. 후보 수나 장수를 자동 축소하지 않는다.

선정 전 고정해시순 앞16장(192타일)으로 시간·메모리와 특징 일치 검사를 먼저 하고,
같은 계약으로 완료한 특징은 본 선정에서 재사용한다. 예상1시간 초과나 계약 실패면 전체 선정을 시작하지 않는다.
실제 학습 전에 장비가 이 예산을 지원하는지 다시 확인한다.

비용 비교는 두 모델을 각각 새 프로세스에 로드하고, 고정 validation256의 저장 명단 앞32장을 같은 순서로 쓴다.
앞5장 warmup 후32장×3회=96사진을 측정하고, 원본1장당12타일을 순차 처리한다. warm p95(higher)≤2초를 요구한다.
범위는 원본 읽기/디코딩·전처리·GPU 동기화 포함 추론·지도 CPU 전송·Q90/사진 집계까지이며 파일 저장·HTTP·대기열은 제외한다.
cold 모델 로드·첫 사진·파일 저장 시간은 따로 기록한다. 따라서 이 검사가 서비스 전체 응답 SLA를 증명하지 않는다.

## 7. Phase별 실행과 산출물

| 단계 | 진행 내용 | 다음 단계로 넘어가는 조건 |
| --- | --- | --- |
| A:이번 설계 | 후보 풀·고정 규칙·조건·예산 기록 | 완료;성능 측정은 하지 않음 |
| B:선정 준비 | CPU 테스트,연구실 정상 특징 추출,64장 명단 잠금 | 원본/특징 계약·누수 검사·예산 통과,사용자에게 선정 결과 보고 |
| C:학습·보정 | 고정64장 fit,128/169 보정,저장/재로드 | 모델·보정·원점수 재현 검증;관찰 시험은 아직 계산하지 않음 |
| D:비교 | 고정109/256,재표집3,000회,동일 장비 비용 | 성적·안정성·비용을 별도로 판정 |
| E:결론 | 유지/기각 및 한계 기록 | 후보 추가 자동 반복 없음,독립 final/서비스 교체 없음 |

사전 설계 당시 다음 구현은 **B단계 준비 도구**였다. 이후 구현한 명령은
[선정 준비 실행 안내](mpi-normal-diversity-preparation-v1.md)를 따른다.
준비 결과가 맞는지 확인하고 C단계 진행 동의를 받은 뒤 학습한다.

입력은 Downloads의 기존 원본 `extracted.zip`과 준비·fit·공간점수·외부v2 전달물이다.
예정 출력은 `artifacts/experiments/mpi-normal-diversity-v1/` 아래 prepare/fit/evaluation별 구분이다.
config·소스 LF hash·commit·라이브러리/장비·입력 ZIP·checkpoint·각 manifest를 단계 영수증에 남긴다.
완료 조각은 전체 계약과 파일 hash가 일치할 때만 재사용한다. 임시파일→원자적 저장,실패 보존,기존 출력 덮어쓰기 금지다.
소스·설정 변경 후 조용히 이어가지 않는다. 원본·모델·벡터·이미지는 Git/Notion에 올리지 않는다.

CPU 시험:수동 거리 대조·중심/최대최소 선정·동점·순서 재현·영역 순서·NaN/0norm·ID/RGB 누수·
전체/부분 중복·캐시 변조·재개·기존 명단 동일 시 중단·라벨 불사용을 확인한다.
실제 GPU에서는 기존 융합 특징과 선정용 추출 특징 일치,16장 반복 최대 차≤1e-4,fit/reload·시간·메모리를 확인한다.
새 GPU 환경에서 선정 벡터가 달라지면 기존 명단을 재사용하지 말고 계약 불일치로 보고한다.

handoff는 단계별 manifest·풀/선정 ID·겹침·기술통계·비용·검증 영수증·요약을 포함한다.
평가 단계에는 전체 점수·판정·FP/FN·추가/상실 검출·bootstrap 인덱스와 실패 포함 전체 결과를 남긴다.
최종 보고는 현재 관찰 범위의 연구 결과이며 자동 PASS는 계속 금지다. Notion13번 문서에 진행/결정을 기록한다.
