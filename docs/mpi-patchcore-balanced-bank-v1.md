# MPI PatchCore 영역별 정상 대표 균형 비교

## 목적과 현재 상태

전체 후보 지도 진단은 종결하고, **정상 기준표의 크기는 그대로 두고 대표를 뽑는 방식만 바꾸는 후보 하나**를 비교한다.
현재는 실행 준비 단계다. 연구실 CUDA 실행·성능 개선·운영 승인을 완료한 것이 아니다.
기존 모델, Q90 연구 기준선, transistor 서비스와 자동 합격 금지 정책은 유지한다.

기존 정상 256장 모델과 개발 256장 보정 조합은 불량 55/55를 검출했지만 정상 오경보는 1/54 및 15/256이었다.
전체 후보 진단에서 일부 정상의 높은 점수가 낮아졌지만 다른 정상 반응은 남았고 일부 결함의 위치 구분은 약해졌다.
따라서 전체 314만 특징을 서비스에 넣거나 경고선만 조정하지 않는다.

## 바꾸는 것과 유지하는 것

기존 78,643개 대표의 영역별 수는 순서대로 5,162 / 6,952 / 6,604 / 4,865 / 4,791 / 5,966 / 5,261 / 4,694 / 7,245 / 7,338 / 8,117 / 11,648개다.
가장 많은 영역과 적은 영역은 약 2.48배 차이다. 이것이 잘못된 배분이라는 증거는 아니다. 복잡한 영역에 더 많은 대표가 필요한 것일 수도 있다.
새 후보는 이 배분의 영향을 확인하는 단일 가설이다. 불량·오경보 사례를 보고 특정 영역의 몫을 늘리지 않는다.

| 항목 | 기존 비교 모델 | 새 후보 |
| --- | --- | --- |
| 정상 학습 원본 | 고정 256장 × 12영역 | 동일 |
| 학습 특징 후보 | stride2로 보관한 3,145,728개 × 768차원 | 같은 저장 특징 |
| 선택용 투영 | 저장된 369차원 투영 캐시 | 동일 캐시, 다시 만들지 않음 |
| 대표 선정 | 전체 후보에서 하나의 greedy 선택 | 각 영역에서 독립 greedy 선택 후 결합 |
| 대표 수 | 총 78,643개 | 총 78,643개 |
| 영역별 할당 | 데이터에 따라 달라짐 | 첫 7영역 6,554개, 뒤 5영역 6,553개 |
| 검사 중 최근접 검색 | 전체 기준표에서 검색 | 전체 기준표에서 검색 |
| 정상 점수 보정 | 개발 256장·보정 169장 | 동일 사진·동일 산식, 새 모델 점수로 새 값 산출 |
| 시험 | 불량 55장·정상 54장·별도 정상 256장 | 동일 |

영역 순서는 기존 REGIONS 순서(grid1-1부터 grid4-3)다. 각 영역 후보는 256 × 1,024 = 262,144개이며 후보 누락·무작위 사전 축소는 없다.
동일한 투영 차원·행렬·저장 값을 재사용한다. 최초 비교 중심은 기존 투영 초기 인덱스를 262,144로 나눈 나머지이며 모든 영역에서 같은 로컬 사진/패치 인덱스로 고정한다.
각 영역에서 기존과 같은 L2 greedy 갱신과 최초 최대값 동률 규칙을 사용한다. 이 선택 방식 전체가 변경 요인이다.
새 투영, 특징 정규화, 특징층 변경, 학습사진 확대, 학습 난수 재선택은 하지 않는다.

**영역별로 대표를 선정하는 것과 같은 영역끼리만 검사하는 것은 다르다.** 새 후보도 검사할 때 78,643개 전체를 검색한다.
과거 같은 영역으로 최근접 검색을 제한했던 실험을 반복하는 것이 아니다.
새 모델의 모든 비기준표 텐서가 기존 모델과 같은지, 새 기준표의 모든 행이 선정한 원래 특징과 정확히 같은지 검증한다.

## 자료 분리

대표 선정 함수는 기존 정상 학습 특징 캐시와 고정 인덱스만 받는다. 오경보 14장, 불량 0024, 정상 검증 256장, GT, 평가 점수를 입력으로 받지 않는다.
학습 256장·개발 256장·보정 169장·검증 256장의 원본 ID 및 RGB 중복을 검사한다. 시험은 별도 ID 공간이므로 숫자 ID가 아니라 RGB 중복으로 분리한다.
기존 코호트·중복군 제외·손상 데이터 처리 이력과 파일 해시를 그대로 사용한다. 물리적 기판·촬영 세션 독립성이 입증됐다는 뜻은 아니다.

## 한 명령으로 실행하는 순서

1. 기존 handoff 2개, 실행 소스, 학습 특징 256개 파일, 투영 48개 블록, 모델과 원본 지문을 검증한다. 기존 정상 8장의 지도·점수를 다시 확인한다.
2. 영역별로 대표를 선정한다. 매 1,000개와 영역 완료 시 거리를 포함한 체크포인트를 저장한다. 기존 특징 추출 신경망을 역전파로 다시 학습하는 작업은 아니다.
3. 총 78,643개 기준표를 새 모델로 저장한다. 정상 개발 256장으로 영역별 중앙값·Q90 폭을 계산하고 정상 보정 169장으로 사진 Q95 higher 경고선을 고정한다. 이전 경고선은 덮어쓰지 않는다.
4. 새 모델을 다시 불러와 정상 425장 전체의 점수·판정 재현을 확인한다. 최대 절대차이 1e-4, 판정 변경 0이어야 한다.
5. 별도 프로세스에서 불량 55장과 정상 54장·256장을 평가한다. 기존 12장 결과가 나빠도 정확도 때문에 중단하지 않는다. 입력 무결성·재현성·자원 오류는 중단한다.
6. 두 모델의 동일 정상 20장 × 3회 반복 속도, 모든 불량과 정상 고점수 12장의 지도·GT 반응, 정상 재표집 600회 안정성을 함께 비교한다.

지도 계산은 양쪽 모두 기존 native float32 추론을 유지한다. 앞선 CPU64 지도 진단을 이번 추론에 섞어 두 번째 변경 요인을 만들지 않는다.
GT가 부적합한 defect/0006은 기존처럼 위치 평가에서만 제외하고 사진 검출에는 포함한다. defect/0054는 기존 승인 복구 PNG의 지문을 검증해 사용하며 다시 복구하지 않는다.

## 판단 기준

- 직접 비교 기준은 이전 개발 256장 보정 모델(TP55, FP1/54, FP15/256)이다. 오래된 Q90 53/55 결과와 혼동하지 않는다.
- 불량 55/55 유지, 정상 오경보 ≤2/54 및 ≤12/256을 정확도 목표로 고정한다.
- 기존 안정성 목표를 유지한다. 이전 개발 확대에서 사용한 256장 재표집 인덱스를 두 모델에 동일 적용하고, 보정 169장도 동일 인덱스로 비교한다. 3종 × 200회이며 무효 반복을 버리거나 다시 뽑지 않는다.
- 정확도 목표·안정성 목표·결함 위치 변화·속도·메모리를 별도로 보고한다. 일부 목표 통과를 운영 승인으로 바꾸지 않는다.
- 균등 배분이 중요한 정상 외관을 덜 남겨 성능을 악화시킬 수 있다. 실패하면 결과를 보존하고 같은 시험에서 할당량을 반복 조정하지 않는다.
- 이미 관찰한 시험과 사례를 사용하므로 탐색·회귀검증이다. 새로운 일반화 성능이나 실제 생산 성능을 입증하지 않는다.

## 연구실 실행

기존 특징·투영 캐시와 모델 폴더를 보존한다. 다른 GPU 작업은 정상 종료하고 실행 중에는 소스를 업데이트하지 않는다.
남은 디스크 10GiB, 시작 시 GPU 여유 6GiB를 요구한다. RAM 표본최대 20GiB·GPU reserved 6GiB 제한은 유지하고 경과시간 상한은 두지 않는다.
새 원본 특징을 다시 저장하지 않아 이전 확대 학습처럼 수십 GiB의 새 특징 캐시를 만들지는 않는다. 실제 시간은 실행 로그로 확인한다.

```powershell
Set-Location 'C:\개인 프로젝트\defectops'
git pull --ff-only
if ($LASTEXITCODE -ne 0) { throw 'Git update failed; stop here.' }
powershell.exe -NoProfile -ExecutionPolicy Bypass -File '.\scripts\run_mpi_patchcore_balanced_bank.ps1'
```

완료 후 `artifacts\handoff\mpi-patchcore-balanced-bank-v1.zip`을 전달한다.
학습·보정까지만 완료된 경우 `mpi-patchcore-balanced-bank-v1-fit.zip`도 별도로 남는다.
Ctrl+C를 한 번 누른 뒤 정리가 끝나면 같은 명령으로 봉인된 체크포인트와 완료 사진부터 이어간다.
오류·자원 제한·강제 종료는 자동 우회하지 않는다. 폴더를 삭제하거나 난수를 바꿔 재시도하지 말고 오류를 전달한다.
모델·특징·전체 지도·원본은 연구실에 남고 ZIP에는 설정·검증 기록·점수·위치 통계·지문을 담는다.

## 준비 단계 검증

신규 CPU 검사 17개에서 영역 인덱스 전수 대응, 동일 greedy 결과, 중단·재개, 체크포인트 변조·누락 거부,
256장 보정 사용, 600회 동일 재표집, 학습과 평가 RGB 분리, 실패 시 전체 비교 지속, 저장 지도 연결과 위치평가 예외를 확인했다.
선정 루프의 실제 CUDA 검사는 별도 선택 테스트이며 Mac에 PyTorch가 없어 실행하지 않았다. PowerShell도 Mac에서 직접 실행하지 않았다.
기존 실제 handoff 2개의 해시·고정 소스·코호트를 확인하고 TP55/FP1/15와 개발256 기준의 600회 결과를 동일하게 재계산했다.
실제 모델 저장·GPU 메모리·새 후보 성능은 연구실 실행 결과로 확인해야 한다.
