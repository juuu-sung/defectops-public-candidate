# PatchCore 정상 256장 확대 설계와 계산 점검

2026-10-07. 다음 단일 후보 방향은 **기존64장을 포함한 정상256장으로 PatchCore 정상 기준표를 구성하되 최종 bank 크기78,643개는 유지하는 것**이다. 영역별 대표 수를 임의 배정하는 대안은 보류한다. 기존 특징·입력·점수 계산을 유지하면서 실제 정상 자료 확대를 확인하기 위한 선택이며 성능 개선을 전제하지 않는다.

이번 실행기는 **합성 특징을 이용한 계산·메모리 점검만** 한다. 정상 사진의 특징 추출·정식 bank 선정·보정·불량 평가는 하지 않는다. 이 점검이 통과해도 모델 정확도나 정식 학습 완료가 아니다.

## 무엇을 유지하고 바꾸는가

| 항목 | 기존 Q90 | 후속 설계 방향 |
| --- | --- | --- |
| 정상 학습 원본 | 64장 | 같은64장을 포함한256장, 기존 SSN 확대 명단 재사용 |
| 12영역의 후보 패치 | 786,432개 | 3,145,728개, stride2와768차원 유지 |
| 최종 정상 bank | 78,643개 | 78,643개 유지, 저장 용량 약0.225GiB |
| 대표 비율 | 약10% | 약2.5%, 후보 전체를 먼저 사용하고 최종 수만 고정 |
| 특징 추출·검색 | 기존 backbone/layer1+layer2, 공용 검색 | 유지, L2 정규화·영역 검색 제한 없음 |
| 영역 점수·사진 판정 | top1%·Q90·12영역 max | 규칙 유지, 새 모델의 정상128/169장으로 수치 재계산 필요 |

고정 bank 예산에서 자료 확대를 비교하므로10% 비율까지 유지해 bank를4배 키우는 실험과 다르다. 비율 감소를 후보 패치 사전 누락이나 임의 축소와 혼동하지 않는다. 데이터가 늘면 정상·불량 거리가 함께 줄 수 있어 미탐이 늘 가능성도 있다.

대표 선정에 사용하는 Anomalib의 무작위 투영은 표본 수에 따라 차원이 정해진다. 기본eps0.9에서64장335차원,256장369차원이다. 학습 입력이 늘면서 생기는 기본 알고리즘의 변화로 명시하며, 모든 내부 계산이 동일한 순수 자료 수 인과 실험이라고 표현하지 않는다. 최종 bank 벡터는 투영 전768차원이다.

공식 구현은 전체 투영 특징에서 중심을 뺀 임시 배열을 만든다. 이를 그대로 확대하면 큰 임시 GPU 메모리가 필요하다. [Anomalib 2.2.0 대표 선정](https://github.com/open-edge-platform/anomalib/blob/v2.2.0/src/anomalib/models/components/sampling/k_center_greedy.py), [무작위 투영](https://github.com/open-edge-platform/anomalib/blob/v2.2.0/src/anomalib/models/components/dimensionality_reduction/random_projection.py).

## GPU 메모리를 줄이는 방식

전체 원특징은64장 기준2.25GiB,256장 기준9GiB다. 따라서 정식 실행은 원특징을 CPU/디스크에 보관하고 투영할 때만65,536행씩 GPU로 옮기는 방식이 필요하다. 투영된 전체 후보는 약4.324GiB이고, 거리 계산의 차이 배열도 같은 크기의 작은 묶음으로 처리할 수 있다. **원특징 전체를 GPU에 동시에 올리지 않는 것**이 핵심이다.

이 수치는 배열 크기이지 peak 메모리 보장이 아니다. CUDA 작업 공간·allocator 예약·최솟값 배열 등을 실제 측정해야 한다. 최종 대표 선정은 매회 모든 후보의 거리를 반영하고 하나의 전역 최댓값을 선택한다. 묶음별로 별도 대표를 뽑거나 일부 후보를 버리는 근사법으로 바꾸지 않는다.

이번 합성 점검에서는9GiB의 원특징을 작은 묶음으로 생성·투영하여 전체3,145,728개 투영 후보를 유지한다. 실제 이미지 추출이나 디스크9GiB 특징 캐시 저장·재개는 구현하지 않았으므로 그 기능까지 검증됐다고 하지 않는다.

## 한 명령에서 확인하는 것

1. 기존 확대 학습 ZIP의 고정 SHA256·내부 해시와256장 명단을 확인한다. 기존64장 포함 및 정상 개발128/보정169장 비중복을 대조한다. 이미지 아카이브를 열지 않는다.
2. 합성2,048개 특징에서 설치된 공식 투영·거리 갱신·최댓값 선택과 분할 계산을 비교한다. seed42/43, 묶음127/512, 선택64회씩이다. 투영 최대절대차이≤1e-4, 거리 상태≤1e-5이며 **대표 인덱스는 정확히 같아야 한다.** 같은 투영에서 거리만 비교하는 검사와 분할 투영까지 포함하는 검사를 모두 수행한다.
3.256장과 같은 전체 후보 수·투영 차원에서2회 준비 후100회 대표 선택을 측정한다. 모든 후보가 남아 있는 상태의 GPU 예약·실사용, RAM과 시간을 기록한다.
4. JSON 전달 ZIP을 만든다. 기존 모델이나 checkpoint는 읽거나 쓰지 않으며 정상·불량 영상과 임곗값에 접근하지 않는다.

100회 평균에서78,643회 선택 시간을 단순 환산해 참고로 표시한다. 이는 합성 배열의 초기 구간 추정이며 전체 학습 ETA가 아니다. 실제 특징 추출·디스크 입출력·정상 보정·재로딩·평가 시간과 후반 선택 비용은 별도다. elapsed-time 상한이나 표본 자동 축소는 없다.

## 연구실 실행

기존 Windows Python3.12 / torch2.8.0+cu128 / torchvision0.23.0+cu128 / anomalib2.2.0 / RTX5060 환경을 사용한다. 추가 패키지·가중치 다운로드는 없다. 기존 `artifacts/handoff/mpi-supersimplenet-scaling-v1.zip`이 필요하다.

다른 GPU 작업을 정상 종료하고 GPU 여유6GiB·디스크 여유2GiB를 확보한다. RAM20GiB·PyTorch reserved6GiB 한도는 유지한다. 이 점검의 디스크 조건은 향후 실제 특징 저장에 필요한 공간 조건과 다르다.

```powershell
Set-Location 'C:\개인 프로젝트\defectops'
git pull --ff-only
if ($LASTEXITCODE -ne 0) { throw 'Git update failed; stop here.' }
powershell.exe -NoProfile -ExecutionPolicy Bypass -File '.\scripts\run_mpi_patchcore_scaling_probe.ps1'
```

전달 파일: `C:\개인 프로젝트\defectops\artifacts\handoff\mpi-patchcore-scaling-probe-v1.zip`.

Ctrl+C는 한 번 누르고 기록 후 종료될 때까지 기다린다. 같은 명령은 완료 단계를 검증해 재사용하고 미완료 합성 단계는 같은 고정 난수로 처음부터 계산한다. 이는 정식 학습의 대표 인덱스 중간 재개가 아니다. 강제 종료·오류·메모리 초과는 재실행을 막고 파일을 보존한다. 오류 메시지를 전달하며 출력 삭제·허용오차 완화·난수 재선정은 하지 않는다.

## 다음 단계와 완료 기준

결과를 확인한 뒤 분할 선택의 작은 문제 동등성, 실제 peak와 비용을 판단한다. 통과하면 실제 특징 캐시·대표 선택 중간 저장·재개를 포함한 정식 실행기를 구현한다. 작은 문제 동등성만으로 수백만 특징 전체의 선택 순서가 기존 단일 계산과 반드시 같다고 주장하지 않는다. 실제64장 대조와 재로딩 검증 범위를 정식 카드에서 고정한다.

정식 후보의 데이터·전처리·점수·정상 보정·전체 평가·600회 민감도·자원 및 중단 조건은 [후속 설계 기준](mpi-q90-next-design-2026-10-07.md)을 따른다. 새 실행기 완성과 검증 전에는 정식 학습 명령을 제공하지 않는다. 기존12장 실패로 전체 비교를 차단하지 않으며 서비스 교체·자동 PASS·독립 성능 주장은 금지한다.
