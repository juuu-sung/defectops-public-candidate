# MPI 특징 크기 보존 후보와 소규모 회귀 검사

2026-10-03 설계. 특징 길이를 1로 맞춘 직전 후보는 기존 검출 53장 중 45장을 잃어 종료했다.
이번에는 원래 특징값과 정상 패치 저장소를 보존하고, 패치 거리를 계산하는 방법 하나만 바꾼다.
목표는 전체 비교에 앞서 큰 검출 손실을 저렴하게 걸러내는 것이다. 아직 GPU 결과는 없다.

## 바꾸는 것과 유지하는 것

기존 방식은 각 검사 패치와 가장 가까운 정상 패치 1개의 거리를 사용한다. 이번 후보는
가장 가까운 정상 패치 3개까지의 거리 평균을 쓴다. 우연히 닮은 정상 패치 하나에 의해
불량 점수가 낮아지는 경우를 줄일 수 있다는 가설이다. 아직 이 현상이 현재 미탐의 원인이라고
확정하지 않았으며, 드문 정상 모습도 높은 점수를 받을 수 있다. 3은 이번 한 번의 고정값이며
2·5·9 등을 시험해 좋은 결과를 고르는 탐색은 하지 않는다.

| 항목 | 이번 실행 |
| --- | --- |
| CNN·특징층·전처리 | 기존 그대로, 특징 크기 보존, 입력 256×256 |
| 정상 bank | 기존 78,643×768 원소를 그대로 사용, 학습·대표 재선정 없음 |
| 패치 거리 | 최근접 1개 → 가까운 3개 거리의 평균 |
| 지도 생성 | 기존 확대·평활화 그대로 |
| 영역 점수 | 지도 상위 1%인 656픽셀 평균 그대로 |
| 영역별 척도 | 같은 정상 128장으로 중앙값·Q90 폭 계산 |
| 사진 경고 기준 | 같은 정상 169장, 12영역 최대값의 higher Q95 재계산 |
| 서비스 | 변경 없음, 자동 합격 없음 |

Anomalib 2.2.0의 `num_neighbors=9`는 이미지 점수의 가중에 쓰이며 지도는 최근접 1개로 만든다.
따라서 단순히 이 설정을 3으로 바꾸지 않는다. [공식 구현](https://raw.githubusercontent.com/open-edge-platform/anomalib/v2.2.0/src/anomalib/models/image/patchcore/torch_model.py)을 기준으로
한 번 계산한 거리 행렬에서 기존 최소값과 후보의 세 거리 평균을 따로 구한다. 기존 최소값의
동률 인덱스 규칙을 유지하여 기존 지도와 native 이미지 점수를 함께 재현한다. 후보의
`native_raw` 필드는 기존 이미지 점수를 보존하는 대조용이며 후보 의사결정에는 사용하지 않는다.

## 고정 검사 순서

1. 기존 ZIP·원본 압축파일·checkpoint·bank·실행 환경을 확인한다. 기존 정상 소규모 재현 검사도 먼저 통과해야 한다.
2. 정상 development 128장과 calibration 169장을 모두 계산해 후보의 새 경고 기준을 고정한다.
3. 기존에 검출한 불량 53장 중 아래 규칙으로 미리 선정한 12장을 검사한다. 한 장이라도 놓치면 후보를 중단하고 결과 ZIP을 만든다.
4. 12장 모두 유지하면 모델을 다시 불러온다. 고정 calibration 순서의 첫 8장과 같은 불량 12장만 다시 계산한다. 원점수 차이 0.0001 이하·판정 변화 0이어야 한다.
5. 결과를 전달받아 검산한다. 통과했더라도 전체 평가나 서비스 변경을 자동 실행하지 않는다.

회귀 표본은 기존 검출 53장에서 `SHA256("mpi-knn3-screen-v1" + NUL + key)` 오름차순 첫 12개다.
후보 GPU 점수를 보기 전에 ID를 아래처럼 동결하며 실패 사례를 바꾸거나 임곗값을 낮추지 않는다.

`0006, 0025, 0048, 0000, 0054, 0051, 0013, 0033, 0038, 0001, 0034, 0042`

모두 기존에 관찰한 불량이다. 0006의 손상 마스크는 읽지 않으며, 0054의 이미지에는 기존에 검증한 복구 파일을 그대로 사용한다.
임의 이미지 복구·재다운로드·새 마스크 해석은 하지 않는다. 12타일은 원본사진 1장의 구성 요소이지 독립 표본 12개가 아니다.

## 결과 해석과 남는 한계

12/12 유지와 작은 재로딩 검사 통과는 **전체 비교를 검토할 수 있는 조건**일 뿐이다. 남은 기존 검출
41장과 기존 미탐 2장, 정상 54장·256장, 보정 민감도·실행 비용은 아직 평가하지 않는다.
따라서 미탐 감소·오경보 개선·독립 일반화 성능을 주장할 수 없다. 작은 표본을 통과해도 큰 회귀를
전부 배제하지 못한다. 재로딩도 정상 297장 전체 검사가 아니며 후속 전체 비교에서 보완해야 한다.

본 계산은 실패 시 309장, 통과 시 반복을 포함해 329장이다. 시작·재로딩 때의 기존 정상 확인은
별도이므로 이 수가 전체 GPU 호출 수는 아니다. 이전 959장 실행보다 계산 대상을 줄였지만
최근접 3개 검색의 추가 비용이 있어 실제 소요시간은 Windows에서 측정해야 한다.
누적 1시간·프로세스 RSS 20GiB·PyTorch reserved 6GiB를 중단 상한으로 고정했다.
다른 GPU 작업은 먼저 정상 종료한다. 전체 GPU 점유와 PyTorch reserved는 서로 다른 수치다.

정상 자료를 소수로 줄이지 않는 이유는 새 점수를 기존 임곗값과 비교하거나 불안정한 작은 정상
표본으로 판단하면 잘못된 조기 탈락·통과가 생길 수 있기 때문이다. 회귀 검사는 검출 손실만
빠르게 거르는 장치이며 Q90의 기존 보정 불안정을 해결한 것은 아니다.

## Windows 실행과 복구

```powershell
Set-Location 'C:\개인 프로젝트\defectops'
git pull --ff-only
if ($LASTEXITCODE -ne 0) { throw 'Git update failed; stop here.' }
powershell.exe -NoProfile -ExecutionPolicy Bypass -File '.\scripts\run_mpi_knn3_screen.ps1'
```

원본 기본 경로는 `Downloads\extracted.zip`, 기존 모델·handoff·0054 복구 이미지를 재사용한다.
결과는 `artifacts\handoff\mpi-knn3-screen-v1.zip`에 저장된다. 원본·모델 파일을 ZIP에 포함하지 않는다.
사진별 완료 기록과 원본 체크섬·설정·실행 환경을 검증한다. 일반 예외 후 같은 명령 재실행은
검증된 완료 사진을 재사용한다. 강제 종료로 시간 기록이 누락되거나 자원 상한을 초과하면
자동 재시도하지 않고 검토를 요구한다. 오류 시 파일을 지우지 말고 메시지를 전달한다.

기존 Q90은 연구 기준선으로만 보존한다. 이번 실행은 독립 final·모델 채택·생산 판정이 아니다.
