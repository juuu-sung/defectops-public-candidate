# MPI PatchCore 고정밀 지도 검증과 전체 후보 비교

이번 실행은 **지도 생성의 수치 검증을 통과한 뒤 같은 20개 영역의 전체 후보 비교까지 이어간다.** 모델을 다시 학습하거나 경고선을 변경하지 않는다. 기존 실패 실행과 수치 진단은 보존하고 새 v2 폴더만 사용한다.

## 왜 수정하는가

[수령한 진단](../reports/mpi-patchcore-map-parity-audit-v1-received-review.md)에서 기존 거리로 지도를 다시 만들면 20영역 모두 차이가0이었다. 하지만 고정밀 거리로 만든 지도는 19영역에서 기존 교차정밀도 허용오차를 넘었다. 가까운 특징 거리의 float32 수치 상쇄가 확인됐고, 지도 평활화 단계에도 추가 정밀도 영향이 의심된다. 영역 점수 최대차이는0.000494로 작지만 지도 차이를 무시하지 않는다.

이 때문에 기존 지도와 고정밀 지도의 숫자가 같아야 한다는 검사를 단순히 완화하지 않는다. **기존 모델 재현 검증과 새 고정밀 계산의 정확성 검증을 분리한다.** 기존 모델은 기존 설정으로 재현하고, 새 진단 계산은 같은 Gaussian 커널의 독립 고정밀 계산과 일치해야 한다.

## 유지하는 조건과 바꾸는 조건

| 항목 | v2 조건 |
| --- | --- |
| 학습 모델·특징·대표 기준표 | 변경 없음. 정상256장 학습의 대표78,643개 |
| 비교 대상 | 이전 정상14개 영역과 불량0024의 정답6개 영역 그대로 |
| 전체 후보 | 기존 stride2 보관후보3,145,728개. 원학습 격자 전체 복구가 아님 |
| 거리 계산 | 기존 float64 분할 유클리드 거리. 정규화·근사검색 없음 |
| 대표 거리 재사용 | 검토한 진단ZIP의81,920개 거리·이웃을 고정하고 현재 bank의 해당 벡터로 직접 검산 |
| 공식 출력 재현 | 기존 정상8사진 및 저장 patch 거리의 공식 지도 재현1e-4 유지 |
| 진단 지도 | 설치된 지도 생성기를 복사해 CPU float64로 실행. 원본 모듈 불변 |
| 평활화 | 실제 설치된33×33 Gaussian 커널 값을 그대로 사용. 재생성·재정규화 없음 |
| 보간·경계 | nearest64→256, reflect16 유지 |
| 새 지도 정확성 검사 | NumPy float64 FFT 독립 교차상관과 모든 픽셀 비교, atol1e-9·rtol1e-10 |
| 교차정밀도 차이 | GPU TF32 on/off·CPU64 차이를 모두 보고. 서로 같다는 통과 조건으로 쓰지 않음 |
| 점수 | 지도 상위656개 평균. 사진 경고선 적용·새 사진 판정 없음 |

TF32 on/off는 지도 호출에만 임시 적용하고 예외 발생 시에도 원래 설정을 복구한다. 이미지 전처리와 특징 추출부 설정은 바꾸지 않는다. TF32 off가 반드시 차이를 없앤다고 미리 가정하지 않으며 실제 수치를 기록한다.

## 한 번의 실행에서 하는 일

1. 원본·기존 ZIP·모델·소스·환경·실패 실행의20개 특징 캐시를 확인한다. 정상8사진의 공식 출력 재현과 작은 고정 합성 질의의 분할 거리 계산을 검증한다.
2. 저장 거리로 지도만 TF32 on/off, CPU64로 계산한다. 상수·0·경계 impulse·ramp 및 실제20영역을 독립 기준과 대조한다. CPU64가 기준에 맞아야 전체 검색으로 진행한다. 진단용 커널과 모든 정밀도별 지도·차이를 보존한다.
3. 같은81,920개 위치를 전체3,145,728개 후보와 비교한다. 학습사진256개 블록으로 나누어 중간 결과를 저장한다. 기존 대표가 원후보의 정확한 부분집합인지 확인하고 최종 이웃 거리도 직접 검산한다. 이전53질의도 재현한다.
4. 대표·전체 후보 지도를 같은 CPU64 방식으로 만들고 상위656평균·최대위치 이동·정답 부위 반응·카드를 비교한다. 모든 최종 지도에도 독립 기준 검사를 적용한다.

양의 커널을 통과한 전체 후보 지도는 대표 지도보다 커지지 않아야 한다. 이 검사는 기존 거리 오차 상한1e-4를 실제 커널 합에 곱하고 CPU64 지도 허용오차를 더한 범위로 검사한다. 지도 기준을 임의로 늘리지 않으며 거리 계산의 오차 범위를 전파한다.

기존 공식 지도는 이력으로 내보낸다. 새 진단 지도와 공식 지도의 차이는 결과에 남기지만, 그 차이를 불량 검출 성능 변화로 해석하지 않는다.

## 시간과 중단 재개

시간 상한은 없다. 기존 RAM20GiB·PyTorch GPU reserved6GiB 및 실행 전 GPU 여유 메모리 검사를 유지한다. 다른 GPU 작업은 정상 종료한다. 새 설치나 학습은 필요하지 않다.

전체 거리 비교는 약2,577억 쌍이므로 오래 걸릴 수 있다. 첫 학습사진 블록이 끝나면 해당 블록의 시간과256블록의 단순 선형 추정치를 표시한다. 검증·파일 저장·중단 재계산을 제외한 참고값이지 완료 시각 보장이 아니다.

정상적인 Ctrl+C 후 같은 v2 명령으로 이어갈 수 있다. 완료한 지도 검증과 검색 블록은 해시를 확인해 재사용한다. 진행 중인 블록만 다시 계산한다. 원래 v1 실패 실행은 재개하지 않는다. 강제 종료·일반 오류·파일 변조·환경 변경은 자동 우회하지 않으며 오류 내용을 전달한다.

## 결과를 판단하는 질문

- 정상0706의 한 위치에서 본 거리 감소가 영역 전체 점수 감소로 이어지는가?
- 정상0335처럼 전체 후보에도 높은 반응이 남는 영역은 얼마나 있는가?
- 불량0024의 결함 반응도 함께 줄어드는가? 정상보다 상대적으로 유지되는가?

20개 영역은 이미 관찰한 자료이므로 탐색 진단이다. 이번 결과만으로 오경보 해제·55/55 검출 유지·운영 승인 등을 새로 주장하지 않는다. 기존 모델의55/55 검출·정상오경보1/54와15/256은 기존 결과로 남는다.

## 검증 범위

로컬 전체 검사1,169개와 하위검사52개 통과,10개 건너뜀이다. 신규 검사는14개 통과·실제 PyTorch/CUDA 대상2개 건너뜀이며, 명령 진입점·실제 수령184개payload 해시·20타일 배열·기존 소스 불변도 확인했다.

Mac에서 독립 교차상관·경계·입력 거부·TF32 상태 복구·가짜 runtime 전체 실행·중단 재개·기존 파일 보존·재출력·변조 거부를 검사한다. 실제 CPU PyTorch 및 CUDA 지도 연산 검사는 해당 의존성이 있는 환경에서만 실행하며, 연구실 실행의 첫 단계에 필수 수치 검증을 둔다. 로컬 검사 통과를 실제 CUDA 일치 확인으로 보고하지 않는다.
