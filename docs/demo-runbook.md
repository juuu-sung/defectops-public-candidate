# DefectOps 포트폴리오 시연 체크리스트

목표는 한 장의 검사 결과가 자동 합격으로 오해되지 않으면서 사람의 검토와 근거 기반
모의 티켓으로 이어지는 과정을 5분 안에 보여주는 것이다. 원본 MVTec 이미지·SQLite DB·사람
이름과 자유 입력 내용은 화면 공유 범위를 벗어나 공개하거나 Git에 올리지 않는다.

## 시연 전 준비

- GPU·실제 자료 없이 실행할 수 있는 [합성 검토 시연](synthetic-demo.md)을 제공한다. README GIF는 그중 의견 저장·개정 보존 구간이다. 아래 SOP·승인·티켓 전체 흐름과 촬영 범위를 구분한다.
- 비공개 저장소의 최신 commit을 사용한다.
- 로컬 DB와 등록된 inspection bundle이 Git 제외 상태인지 확인한다.
- `python scripts/serve_review_ui.py`로 `127.0.0.1` 전용 화면을 실행한다.
- 공개 녹화라면 검토자 이름과 기존 자유 입력 note가 보이지 않도록 별도 합성 DB를 사용한다.
- 시연 중에는 실제 외부 티켓·설비·메시지 시스템을 연결하지 않는다.

## 시연 순서

### 1. 모델 결과와 이미지

- 검사 선택에서 PatchCore 사례를 고른다.
- 원본과 오버레이를 나란히 보여준다.
- `REVIEW_REQUIRED`, 원시 점수, 고정 임곗값을 설명한다.
- 말할 핵심: 점수는 결함 확률이나 심각도가 아니며 자동 합격도 허용하지 않는다.

### 2. 사람의 관찰 기록

- 작업자가 원본 사진을 보고 `이상 징후가 보임`, `눈에 띄는 이상 없음`, `판단 보류` 중
  하나를 고른다.
- 관찰 근거와 확인란을 입력한 뒤 저장한다.
- 말할 핵심: 사람 기록은 모델 판정을 덮어쓰지 않고 새 revision으로 추가된다.

### 3. 모의 SOP 근거

- `이상 징후가 보임`일 때만 의심 유형을 사람이 직접 선택한다.
- 유효 날짜·개정판·인용 ID·문서 해시를 확인한다.
- 별도 확인 후 현재 검토 revision에 근거 스냅샷을 저장한다.
- 말할 핵심: 관찰 문장에서 유형이나 원인을 자동 추측하지 않으며 문서는 모의 자료다.

### 4. 조치 초안과 승인

- `현장 상태 재확인 요청` 초안이 공정 조치를 금지하는지 읽어 확인한다.
- 초안 저장과 승인/반려를 각각 별도 동작으로 수행한다.
- 말할 핵심: 반려되면 티켓을 만들 수 없고, 새 사람 검토가 추가되면 이전 revision 승인을
  재사용할 수 없다.

### 5. 로컬 모의 티켓

- 승인 후 마지막 확인란을 선택해 로컬 티켓을 만든다.
- 티켓 ID, payload SHA-256, `외부 전송 없음` 표시를 보여준다.
- 필요하면 `모의 티켓 스냅샷`을 펼쳐 검사·검토·근거·초안·승인이 한 payload에 묶였음을
  확인한다.

### 6. 공개 가능한 검증 결과

다음 명령으로 개인정보가 제거된 요약만 출력한다.

```sh
python scripts/review_inspections.py ticket-summary \
  --inspection-id <로컬 검사 ID>
```

[완료 보고서](../reports/local-review-to-mock-ticket-demo-v1.md)의 해시와 비교한다.

## 실패 시 보여줄 수 있는 안전장치

| 조건 | 기대 동작 |
|---|---|
| 검사 파일 또는 checksum 변경 | 이미지 표시와 모든 새 기록 중단 |
| 검사 실패 기록 | 사람의 시각 판정 입력 차단 |
| 사람 검토 없음/판단 보류 | SOP 근거와 조치 흐름 차단 |
| SOP 근거 미저장 | 조치 초안 생성 차단 |
| 검토 revision 불일치 | 초안·승인·티켓 저장 충돌로 거부 |
| 초안 반려 | 모의 티켓 발행 차단 |
| 승인 없음 | 모의 티켓 발행 차단 |
| 같은 요청 재시도 | 같은 내용은 중복 생성 없이 기존 기록 반환 |
| 저장 payload 변조 | SHA-256 불일치로 요약 생성 거부 |

## 시연 종료 후 설명

- 성공했다고 말할 수 있는 범위: 로컬에서 검사 추적, 사람 검토, 문서 revision 고정,
  승인 게이트, 티켓 중복 방지와 무결성 검증이 동작한다.
- 성공했다고 말하면 안 되는 범위: 실제 불량 원인 규명, 안전 보장, 공정 조치 승인,
  현장 일반화 성능, 외부 티켓 연동.
- 다음 개발 단계: 공개용 합성 데모 DB, 인증·역할 분리 설계, 3품목/3 seed 사전 고정 비교,
  실제 SOP와 외부 도구를 연결하기 전 권한·감사 정책 검토.
