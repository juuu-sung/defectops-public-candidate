# MPI-PCB 전용 정상 기준표: 같은 시험에서 비교하기

상태(2026-09-27): **실행기 구현, 로컬 합성 경계 검증 완료. 연구실 GPU 평가 결과는 아직 없음.**
학습·정상 보정 결과는 [수령 보고서](../reports/mpi-pcb-normal-bank-fit-v1.md)에 별도로 기록했다.

## 이번에 확인할 질문

**MPI-PCB 자체의 정상 모습으로 만든 기준표가 기존 Real-IAD PCB·VisA PCB3 모델보다
이 기판의 불량을 덜 놓치는가?** 기존 두 모델의 결과를 다시 만들거나 유리한 사진만
고르지 않는다. 새 MPI 모델 하나를 같은 시험에서 계산하고 검증된 두 결과와 비교한다.

- 학습을 다시 하지 않는다. 원본 64장으로 만든 checkpoint의 SHA256을 고정한다.
- 새 모델의 정상 보정 임곗값 `46.839376955497556`도 고정한다. 보정 169장을 다시
  전부 계산하거나 시험에 맞춰 임곗값을 조절하지 않는다.
- 비교 모델은 모두 PatchCore다. PaDiM 대 PatchCore 비교가 아니다.
- 정상 학습의 출처뿐 아니라 학습량·bank 크기도 다르므로 단일 요인의 인과 효과로
  설명하지 않는다. 같은 시험을 이미 봤으므로 사후 탐색/회귀 결과다.

## 왜 새 프로세스에서 불러오나

학습 직후 정상 보정은 약 5시간 11분이었지만 저장 모델 재로딩 후에는 약 3분 14초였다.
2,028영역의 모든 점수는 같고, 영역당 평균은 약 9.20초에서 0.095초로 줄었다.
예약 메모리 최고치는 7.715 GiB에서 2.928 GiB로 줄었다. 정확한 원인은 아직 미확정이다.

이번 PowerShell 실행기는 **새 Python 프로세스 하나**를 실행한다. 그 안에서 모델을
한 번 불러오고 짧은 정상 검사 후 시험으로 이어간다. 사진마다 모델을 새로 읽지 않는다.
속도 문제가 해결됐다고 미리 주장하지 않고 실제 실행 비용을 기록한다.

## 실행 순서

1. **고정 입력 확인:** 원본 ZIP, 학습·준비·기존 평가·맵 진단 ZIP의 SHA256/내부 manifest,
   checkpoint 바이트, 모델 설정·학습 실행 코드, 기존 시험 명단을 확인한다.
   새로운 데이터 다운로드나 복구 이미지를 다시 만드는 작업은 하지 않는다.
2. **짧은 정상 검사:** 기존 보정 명단의 앞 8장(96영역)을 고정 사용한다. 처음 5영역은
   준비 계산(warmup)으로 처리하고 측정에서 제외한다. 이후 정상 점수를 저장된 값과
   대조한다. 사진 하나를 끝낼 때마다 중단 조건을 확인하므로 매우 느린 상태에서 8장
   전체를 억지로 계산하지 않는다. 시험 결과를 보고 정상 명단을 바꾸지 않는다.
3. **새 모델 시험:** 동일 정상 54장+불량 55장=109장, 총 1,308영역을 검사한다.
   읽을 때마다 원본 바이트·RGB 해시를 대조하고 기존 정답 마스크 규칙을 유지한다.
   사진마다 점수·원시 맵·위치 분석·시간을 저장한다.
4. **세 모델 비교:** 기존 두 모델의 고정 점수 및 위치 진단과 새 모델을 나란히 정리한다.
   JSON 8개와 manifest를 ZIP으로 전달한다. 모델·이미지·마스크·NPZ는 ZIP에 넣지 않는다.

### 정상 검사에서 멈추는 조건

- 어느 영역 또는 사진 점수든 저장된 정상 점수와 절대 차이가 `0.0001` 초과.
- 측정 영역 평균 시간이 1,000ms 초과 또는 p95(higher)가 2,000ms 초과.
- 실행 환경·모델·자료·코드·기록의 신원이 바뀌거나 맵에 비정상 값이 있음.

시간 한도는 이전 약 9초/영역 상태로 장시간 실행되는 것을 막는 **실행 상태 점검 기준**이다.
서비스 응답시간 1초를 달성했다는 뜻이 아니며 정확도 합격 기준도 아니다.
GPU 메모리는 기록하지만 임의로 bank를 줄이거나 다른 모델로 바꾸지 않는다.
이 검사는 전체 정상 169장 재검증을 대체하는 새로운 성능 검증이 아니다. 앞선 전체
저장 재검증이 완료됐다는 전제 아래 새 프로세스의 실행 상태를 짧게 확인한다.

## 시험 자료와 예외는 그대로 유지

| 구분 | 이번에도 유지할 규칙 |
| --- | --- |
| 주 비교 | 정상 54장·불량 55장, 총 109장 |
| 중복 정상 `good/0013` | 기존처럼 시험에서 제외 |
| 복구 사진 `defect/0054` | 기존 검증된 파생 PNG로 주 비교에 포함, 제외한 108장 결과도 별도 보고 |
| 손상 마스크 `defect/0006` | 사진 분류에 포함, 위치 요약에서는 사진 전체 제외 |
| 위치 분석 분모 | 정답이 온전한 불량 54장 |

새 손상·불일치가 나오면 멈춘다. 임의로 사진을 추가 제외하거나 분모를 축소하지 않는다.
원본 ZIP과 기존 평가·학습 결과는 변경하지 않는다. 이번 단계는 시험을 새로 봉인한
독립 평가가 아니며, 수동 변형·한 기판의 반복 촬영이라는 한계를 계속 명시한다.

## 결과를 읽는 방법

- **미탐 / 오경보:** 불량 55장 중 놓친 수, 정상 54장 중 경고한 수를 먼저 비교한다.
- **개선과 퇴보 사례:** 기존에 놓쳤다가 새로 잡은 사진과 기존에 잡았다가 새로 놓친
  사진을 각각 기록한다. 순증가만 보고 “기존 미탐 전부 중 몇 개를 잡았다”고 추측하지 않는다.
- **위치 반응:** 최고 점수 영역에 정답이 있는지, 결함 포함 영역의 상위 1%에 정답이
  전혀 없는지, 결함 픽셀의 점수 순위를 비교한다. 같은 동점 처리 규칙을 쓰며 영역 평균
  후 사진 간 중앙값이다. 전체 Pixel AUROC나 이진 픽셀 판정 정확도로 부르지 않는다.
- **시간:** 영역별 계산 시간과 **실측 원본 사진별** 계산 시간을 구분한다. 마스크·위치
  진단, 맵 저장, 이들을 포함한 sample 전체 시간도 별도로 기록한다. 모델 로딩은 정상
  검사 기록에 따로 있고, HTTP·서비스 UI 시간은 포함하지 않는다.
- **재실행의 영향:** 여러 시도의 캐시가 섞이면 표시하고 각 정상 검사·프로세스 기록을
  보관한다. 공식 warm benchmark나 과거 두 모델과 동일 조건의 속도 경쟁으로 주장하지 않는다.
- **메모리:** 해당 실행 단계의 PyTorch 최고 allocated/reserved, 선택적 순간 RAM RSS를
  기록한다. 전체 GPU 사용량이나 RAM 최고치가 아니다. RAM 측정이 없으면 null이다.

다른 GPU 작업이나 검사 서버는 사용자가 정상 종료하고, 아래 명령을 실행한다.
기존 가상환경을 삭제하거나 패키지를 재설치할 필요는 없다.

```powershell
Set-Location "C:\개인 프로젝트\defectops"
git pull --ff-only
if ($LASTEXITCODE -ne 0) { throw "Git update failed." }
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\scripts\run_mpi_pcb_normal_bank_evaluation.ps1"
```

원본 ZIP이 다른 위치라면 마지막 명령에 `-Archive "실제 전체 경로"`를 추가한다.
이 Python 실행기는 Git 작업 트리가 clean이어야 하므로, 변경 사항이 있다고 나오면
무작정 삭제/되돌리기 하지 말고 상태를 공유한다.

완료 상태는 `mpi_pcb_target_bank_evaluated_exploratory`다. 전달할 파일:

`C:\개인 프로젝트\defectops\artifacts\handoff\mpi-pcb-normal-bank-evaluation-v1.zip`

처리 시간은 보장하지 않는다. 앞선 재로딩 속도가 유지된다면 짧은 정상 검사와 시험의
추론 부분은 수 분 규모가 예상되지만, 초기화·파일 검사·위치 분석·맵 저장이 추가된다.
속도가 느리면 점검 기준에 따라 멈추며, 결과를 보고 시간을 재평가한다.

## 중단·재실행·로컬 검증

평가 경로는 `artifacts/evaluations/mpi-pcb-normal-bank-evaluation-v1`이다.
완료 사진은 `samples/photo-001` 같은 폴더에 맵·점수·해시를 원자적으로 게시한다.
미완료 폴더와 시도 기록은 그대로 보존하고 재사용하지 않는다. 재실행은 완료 사진의
체크섬/점수 집계를 확인한 후 남은 사진만 계산한다. 미완료 시험을 재개할 때도 새
프로세스에서 정상 검사를 먼저 통과해야 한다. 전체 완료 후 재실행은 GPU 없이 결과를
검증·재포장한다. 잠금은 프로세스 종료 시 OS가 해제한다.

오류나 점검 중단이 나오면 출력된 `attempt-.../failure.json` 경로와 메시지를 공유한다.
미완료는 성공 ZIP으로 포장하지 않는다. 입력/코드가 바뀌거나 완료 캐시가 손상되면
그대로 보존하고 중단한다. 이름 변경·결과 삭제로 검증을 우회하지 않는다.

로컬 테스트는 가짜 GPU 경계를 이용해 실제 PNG·마스크·점수 집계·위치 규칙·중단 재개·
입력/산출물 변조 거절·정상 속도/점수 중단·JSON 전달 ZIP을 확인한다. 실제 수령한 준비,
학습, 기존 평가, 맵 진단 ZIP도 새 입력 검사를 통과했다. Windows PowerShell 및 RTX
5060의 **이번 새 평가 실행은 아직 하지 않았다.** 자동 PASS와 서비스 모델 교체는 없다.

검증 명령은 `.venv/bin/python -m pytest -q -p no:cacheprovider`다. Python 3.11.9에서
**298 tests + 52 subtests 통과**, 이 중 신규 평가 테스트는 21개다. 기존 경고 3개는 남아 있다.
CLI 인자 연결과 PowerShell의 실행 경로는 로컬에서 검사했지만, PowerShell 엔진은 없어
실제 Windows 스크립트 실행을 검증했다고 주장하지 않는다.
