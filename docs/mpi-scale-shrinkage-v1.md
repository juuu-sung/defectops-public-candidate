# MPI-C1-01 — 정상 변동 폭 부분 공유 후보의 사전 설계

작성일: 2026-10-01. Phase3 준비. 상태: **설계 완료 / 후보 점수 계산 전 / 실행기 미구현**.
상위: [통합 계획](model-development-plan-v1.md), [사이클 원장](mpi-model-cycle-1.md).
기계 판독 규칙: [config](../configs/mpi-scale-shrinkage-v1.json).
사용자의 “응 그렇게 진행해보자”에 따라 설계를 작성했다. 이 문서는 새 학습·배포 승인이 아니다.

## 1. 질문·근거·변경 하나

> 영역별 정상 변동 폭을 12영역의 대표 폭과 절반씩 섞으면, 정상 표본 구성에 따른 판정 변동을
> 줄이면서 기존 불량 검출을 보존하고 정상 오경보를 줄일 수 있는가?

기존 정상 개발128장 재표집에서 검출 수가 크게 변했다. [Phase2 결과](../reports/mpi-spatial-miss-review-v1-received-review.md)는
주요 결함 반응이 존재함과 공간 평균 후보의 실패를 보여줬지만, 보정 불안정을 해결하지 않았다.
이번에는 특징·bank·이미지 점수 집계는 그대로 두고 **정상화의 분모인 변동 폭 추정법만** 바꾼다.

후보 번호는 이 사이클의1/2다. 앞선 공간 후보는 과거 실험으로 계속 실패 기록에 남긴다.
이번 진단 자체는 후보 수에 포함하지 않는다. 아직 이 후보를 평가하지 않았으며, 효능은 미확인이다.
50%는 극단적인 개별 추정과 전면 공유의 중간을 시험하는 설계 선택이지 최적값이나 이론적 보증이 아니다.
이미 관찰한 시험 결과를 배경으로 설계했으므로 계산 전 규칙을 고정해도 독립 확증 실험은 아니다.

## 2. 계산법을 먼저 고정

정상 개발128장의 저장된 top1 점수로 각 영역 r에 대해 계산한다.

```text
c[r] = 해당 영역 점수의 중앙값
s[r] = 해당 영역 점수의 90% higher 분위수 - c[r]
g    = 12개 s[r]의 중앙값
s_new[r] = 0.5 * s[r] + 0.5 * g

기준선 영역 점수 = (top1 - c[r]) / s[r]
후보 영역 점수   = (top1 - c[r]) / s_new[r]
사진 점수        = 12개 영역 점수 중 최댓값
각 방법의 경고 기준 = 별도 정상169장의 사진 점수 95% higher 분위수
경고             = 사진 점수 >= 해당 방법 경고 기준
```

원래 폭이 작았던 영역은 폭이 커져 덜 민감해질 수 있고, 컸던 영역은 작아져 더 민감해질 수 있다.
한쪽으로 임곗값만 내리는 방법이 아니다. 영역 간 실제 차이가 중요한 경우 성능이 나빠질 수 있다.
대표 폭은 픽셀이나 모든 점수를 합친 분위수가 아니라 **12개 폭의 중앙값**이다.
중앙값은 짝수 개에서 가운데 두 값의 평균, higher는 정렬 후0-based `ceil(q*(n-1))`이다.
어느 원래 폭이라도1e-6 이하 또는 비유한 값이면 임의 보정하지 않고 실패한다.

고정 항목: checkpoint, 입력256, 특징층, 공유bank, seed42, top1%=656픽셀,
영역 중앙값 계산법, 사진 max, 개발/보정 명단,95% higher,>= 연산.
새 분모에 맞춰 후보 임곗값은 정상169장에서 다시 계산하되 기존 모델의2.316961 기준은 덮어쓰지 않는다.
창 크기·백본·학습량·보정 분위수·혼합비를 함께 바꾸거나, 실패 후25%/75%를 자동 탐색하지 않는다.

## 3. 입력과 데이터 역할

입력은 수령된 `mpi-spatial-score-v1.zip`의 저장 점수다. ZIP·원점수·기준선 계약 해시는 config에 고정했다.
이번 설계 중에는 해당 입력의 해시·개수·정상 라벨만 확인했으며 새 분모나 후보 성적은 계산하지 않았다.

| 자료 | 수 | 용도 |
| --- | ---: | --- |
| 정상 fit | 64 | 기존 bank 출처만 유지; 재학습 없음 |
| 정상 development | 128 | c·s·g 추정 |
| 정상 calibration | 169 | 방법별 사진 경고 기준 |
| 관찰된 test | 불량55 + 정상54 | 탐색 비교·기존TP 손실·오경보 검토 |
| 관찰된 validation | 정상256 | 별도 정상 회귀 비교; 보정에는 사용 안 함 |

명단·해시·손상 및 복구 예외·정확 중복 한계는 사이클 원장을 그대로 따른다.
새 미관찰 final은 없으며 어떤 자료도 새 final로 이름을 바꾸지 않는다. 사진의12영역은 함께 다룬다.
결함 위치 mask·6개 사례의 모양·특정 영역ID 우대는 새 공식에 사용하지 않는다.
사진 단위 실험이고 모든 결함 위치 검출이나 새 pixel 성능을 주장하지 않는다.

## 4. 성능·안정성 판정 — 실행 전에 검토할 규칙

### 원래 고정 명단에서의 조건: 모두 충족

- 기존 Q90 재계산이 저장 계약과 절대오차1e-12 이내, 판정 변화0이어야 후보 계산으로 진입한다.
- 기존 불량55장 중 최소53장 검출, 기존에 잡던53장 중 새로 놓치는 사진0장.
- 기존 정상54장 오경보 최대2장, 후속 정상256장 최대12장: 각각 관측5% 이하의 정수 상한이다.
- 전체 점수·FP/FN명단·추가/상실 검출·영역별 경계 변화를 공개한다. AUROC만으로 통과시키지 않는다.

### 정상 구성 민감도: 원래 성적과 별도 조건

개발만 / 보정만 / 둘 다를 바꾸는3개 상황을 각각1,000회 계산한다. 고정 test109장과
관찰 정상256장은 재표집하지 않는다. 정상은 원본사진 행 단위 복원추출하고12영역 관계를 유지한다.
각 반복에서 기준선과 후보가 정확히 같은 표본 인덱스를 쓴다. 개발 표본이 바뀌면 g도 매번 다시 계산한다.
보정은 각 방법의 해당 반복 점수로 다시 계산한다. 원래 g를 고정해 후보만 유리하게 하지 않는다.

난수는 NumPy PCG64, 상황별 seed20261001/20261002/20261003이다. 둘 다일 때 개발128개를 먼저,
보정169개를 다음에 추출한다. 새 난수로 반복을 골라내지 않고 인덱스·환경·모든 결과를 저장한다.
분포 요약은 linear 방식의2.5/50/97.5 분위수이며 임곗값의 higher 계산과 구분한다.

각 상황에서 다음을 모두 요구하는 **개발 선별 규칙**을 제안한다.

| 조건 | 기준 | 이유 |
| --- | --- | --- |
| 검출 수 변동 폭 | TP의97.5−2.5 분위 폭이 같은 반복 기준선의 절반 이하 | 평균만 같고 크게 흔들리는 후보 배제 |
| 검출 하단 | TP 2.5분위≥50/55 | 낮은 성능에 고정되어 폭만 줄어드는 후보 배제 |
| 정상 오경보 상단 | FP97.5분위≤5/54 및≤25/256 | 변동 상황에서 약10% 이상으로 커지는 양상 제한 |
| 실패 반복 | 0회 | 불리한 반복을 버려 안정적으로 보이게 만들지 않음 |

기준선 폭이0이면 후보도0이어야 한다. 정수 지표의 분위수는 소수가 될 수 있고 반올림하지 않는다.
50/55와 약10%는 민감도 스트레스 상한이지 본래95%/5% 성능 목표를 완화한 것이 아니다.
위 수치와50% 혼합비는 **후보 결과를 보기 전의 연구 판단 기준**이지 현장 보장이나 검증된 최적값이 아니다.
재표집 분위수는 새 제품 성능의 신뢰구간이 아니다. 데이터의 실물/촬영 세션 독립성이 확보되지 않았다.
과거1,000회 결과와 난수가 다르므로 기존 보고서 숫자를 비교분모로 쓰지 않고 기준선을 같이 재계산한다.

## 5. 실행 순서·자원·산출물

1. 카드·config 검토와 실행 동의 후 CPU 실행기를 구현하고 합성 테스트를 먼저 한다.
2. 모든 입력 해시·개수·정상 라벨·명단·영역 순서와 기존 Q90 점수/판정을 재현한다.
3. 정상128/169장만으로 두 방법을 산출해 별도 결과에 저장하고 잠근다.
4. 고정 관찰 자료 비교와3상황×1,000회 동일표본 민감도 비교를 수행한다.
5. 개발 조건·안정성 조건·비용·독립 평가 여부를 각각 판정하고 모든 실패도 기록한다.

Mac CPU만 사용한다. 입력은 저장 점수이므로 이미지 디코딩·GPU 추론·bank 재학습은 필요 없다.
이 분석 프로세스 총30분·peak RSS2GiB를 상한으로 제안한다. 하드웨어·Python/NumPy·wall time·
peak RSS 측정법/단위를 남긴다. 초과/미측정이면 비용 통과가 아니다. 반복 수를 몰래 줄이지 않는다.
CPU 분석 비용이 서비스 사진 p95 2초 또는 전체 추론 메모리6GiB의 검증을 대체하지 않는다.
GPU 학습시간·학습 seed 반복·새 결함군별 검증은 이번 읽기 전용 비교에 해당하지 않으며,
실제 후보 승격/배포 전에는 통합 계획의 별도 검증이 필요하다.

예정 출력: `artifacts/analyses/mpi-scale-shrinkage-v1/`.
입력/config/코드/환경 해시, 기준선 재현, 파라미터, 전체 사진 점수, 반복 인덱스·결과, 비교표,
실패 기록·비용·요약 JSON을 저장한다. 기존 출력이 있으면 덮어쓰지 않고 정합성 검증으로
재사용하거나 중단한다. 반복 단위 검증·원자적 저장으로 재개하고, 결과로부터 요약을 재계산한다.
checkpoint와 서비스 설정은 읽거나 변경할 필요가 없다.

실행 명령은 아직 없다. 다음 구현에서 실제 존재하는 실행기와 시험 결과를 확인한 뒤 안내한다.
단위 시험에는 수동 계산 대조, 원래/공유 폭 동일 조건, 비유한/0폭, 영역 순서, 동점,
정답 라벨 변경이 보정에 영향 없음, 동일 난수 재현, 실패 반복 보존·재개 검증을 포함한다.

## 6. 결과별 다음 행동

- 모두 통과: 연구 우선 후보 자격만 부여. 서비스 교체 없이 Phase4 실행 재현·비용 검증 계획으로 이동.
- 고정 성적만 통과: 보정 안정화 실패로 비채택. 좋은 한 번의 성적을 안정성 개선이라고 하지 않는다.
- 안정성만 통과: 정확도 조건 실패로 비채택. 실패 원인은 보존한다.
- 둘 다 실패: 기준선 유지, 혼합비 탐색 없이 종료 보고. 새 후보는 남은 한도와 새 근거로 별도 승인.
- 입력/실행 오류: 성능 실패와 구분해 고정 규칙으로 복구. 실패 샘플 삭제나 정답 변경 금지.

**현재 결과:** 미실행. 후보 threshold·TP/FP·안정성·비용은 아직 계산하지 않았다.
이번 턴의 산출물은 실험 카드와 고정 규칙이다. 연구실 추가 명령은 없다.
