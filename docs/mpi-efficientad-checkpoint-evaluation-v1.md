# EfficientAD 두 저장 모델 보정과 회귀검사

2026-10-04 사용자 진행 동의에 따라 저장된10,000회·30,000회 모델만 비교한다.
새 학습은 하지 않는다.7만 회 모델의 일부 정상 반응 증가가 확인됐지만 이전 모델의 검사 성능은 미검증이다.
두 모델 모두 실패하면 이 학습 구성의 저장 시점 탐색을 종료한다. 추가 시점을 자동 탐색하지 않는다.

## 이번에 확인하는 질문

같은 정상 자료와 같은 보정 공식을 적용했을 때 이전 저장 모델이 기존 불량 검출을 보존하는가?
원시 반응이 낮아졌다는 이유만으로 더 좋은 모델이라고 판단하지 않는다.
7만 회 경고선을 이전 모델에 재사용하지 않고 모델별 경고 기준을 새로 계산한다.
기존 Q90 모델·7만 회 모델·그 임곗값·transistor 서비스는 변경하지 않는다.

## 고정 자료와 순서

실행 순서는10,000회 다음30,000회다. checkpoint 원본과 교사 모델·정상 통계는 변경하지 않는다.
정상128장·169장, 고정 불량12장, 관찰된 불량55장·정상54장·후속 정상256장 명단은 기존과 같다.
1원본사진=12영역이며12개 독립 제품으로 세지 않는다. 이번 자료는 이미 관찰한 탐색·회귀 자료다.
0006은 사진 검사에는 포함한다. 위치 성적을 새로 산출하지 않고 mask를 읽지 않는다.
0054는 기존에 승인된 복구 PNG만 지문 확인 후 지연 로딩한다.

각 모델에서 다음을 수행한다.

1. 정상128장·169장 전체의 원시 ST/AE 지도를 저장한다. 정상128장 전체 픽셀의 q90/q995,
   부호를 보존한 ST/AE 절반 결합, 타일 상위656픽셀 평균, 영역별 중앙값과 Q90 폭을 계산한다.
   정상169장 사진 최대 점수의 Q95 higher로 경고 기준을 고정한다. 공식은 기존과 동일하다.
2. 모델을 메모리에서 해제하고 다시 불러 정상 보정 명단 첫8사진을 재검사한다.
   원시 지도·사진 점수 최대차1e-4 이내, 판정 변화0이어야 불량 검사로 넘어간다.
3. 기존 검출12장 전부를 검사한다.12/12 유지하지 못하면 해당 모델 확대 평가는 생략하고 다음 모델로 넘어간다.
4. 통과한 모델은 관찰된109장(불량55+정상54)과 정상256장을 검사한다. 기준선 Q90과 짝지어 검출 손실·회복을 기록한다.
   모델을 순차 로딩해 동일 정상20장,5회 예열,3회 반복으로 기준선과 후보의 실행 비용을 측정한다.
5. 성적과 후보 속도까지 통과한 경우만3상황×200회=600회 정상 재표집 보정 민감도를 계산한다.
   정상 개발만/보정만/둘 다를 바꾸며 사진12영역을 함께 뽑는다. 지도 분위수도 다시 계산한다.
   이 단계는 수시간 걸릴 수 있으며 새 GPU 학습이 아니라 CPU 보정 반복이다.

모델별 전체 비교 조건은 기존 기준과 동일하다. 최소53/55 검출, 기존53장 검출 손실0,
정상 오경보2/54 이하·12/256 이하, 후보 사진 warm p95 2초 이하다.
민감도는 검출 하단50장 이상, 검출 분위 폭이 기준선+0.5장 이하,
오경보 상단5/54·25/256 이하, 무효 반복0을 요구한다. 미래 성능 신뢰구간이 아니다.
모든 조건 통과도 서비스 채택 승인이 아니다. 두 결과를 모두 보존하고 사람이 검토한다.

## 보존과 실행 비용

원래 fit·평가·trajectory ZIP과 checkpoint 폴더를 그대로 둔다. 소스 지문도 검증한다.
새 출력은 `artifacts/analyses/mpi-efficientad-checkpoint-evaluation-v1` 아래 모델별 폴더다.
새 보정값과 결과는 과거 결과를 덮어쓰지 않는다. 원시 지도는 연구실에만 저장하고 전달 ZIP은 JSON만 포함한다.

- 여유 디스크30GiB, 모델 로드 시 GPU여유6GiB가 필요하다.
- 모델별 누적 계산4시간, 두 모델 최대8시간이다. 입력 해싱·ZIP 내보내기는 제외한다.
- RAM peak20GiB, PyTorch GPU reserved peak6GiB 상한이다. 전체 장치 사용량과 구분한다.
- 실제 Windows 소요시간은 아직 미측정이다.12장 단계에서 탈락하면 전체 비교·민감도는 실행하지 않는다.
- Ctrl+C가 정상 기록되면 같은 명령으로 재개한다. 저장된 사진부터 이어가되 정상 보정·재로딩을 다시 검증한다.
- 일반 오류·자원 초과·강제 종료는 자동 재시도하지 않는다. 파일을 지우지 말고 오류를 전달한다.
- 점수상 탈락은 정상적인 완료 결과이며 다른 저장 모델의 실행을 막지 않는다.

## 연구실 실행

다른 GPU 작업을 정상 종료한 뒤 실행한다. 데이터 기본 위치는 Windows Downloads의 `extracted.zip`이다.

```powershell
Set-Location 'C:\개인 프로젝트\defectops'
git pull --ff-only
if ($LASTEXITCODE -ne 0) { throw 'Git update failed; stop here.' }
powershell.exe -NoProfile -ExecutionPolicy Bypass -File '.\scripts\run_mpi_efficientad_checkpoint_evaluation.ps1'
```

완료 후 다음 파일을 전달한다.

```text
C:\개인 프로젝트\defectops\artifacts\handoff\mpi-efficientad-checkpoint-evaluation-v1.zip
```

두 모델 실패 시 새 저장 시점을 추가하지 않는다. 통과 모델은 전체 비교·안정성·비용을 함께 검토한다.
새 독립 데이터 성능, 생산 사용 승인, 자동 합격은 이번 범위가 아니다.
