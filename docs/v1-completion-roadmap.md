# DefectOps v1 완성 로드맵

기준일: 2026-09-29

## 결론

DefectOps v1은 **새 데이터셋과 모델 점수를 계속 늘리는 연구 프로젝트**가 아니라,
**품목별 정상 기준으로 이상을 찾고 사람이 근거와 조치를 검토할 수 있는 검사 운영 시스템**으로
마무리한다.

현재 MPI-PCB 후속 연구는 다음 사실까지 확인했다.

- 외부 기판 모델을 그대로 적용하면 MPI-PCB 결함 위치 반응과 판정 성능이 모두 약하다.
- MPI 전용 정상 bank는 결함 위치를 자주 찾지만 정상 점수와 경고 기준이 함께 높아져 미탐이 많다.
- 영역별 정상화 A는 검출을 33/55장까지 늘렸지만 여전히 22장을 놓쳤다.
- 같은 영역의 정상 패치만 검색하는 후보는 검출 22/55장, 미탐 33/55장, 정상 오경보 7/54장으로 악화됐다.
- 저장 지도 비교로 새 미탐의 다수는 결함 반응이 사라진 것이 아니라 경고 경계가 더 높아진 결과임을 확인했다.

따라서 영역별 bank를 다시 학습하는 실험은 연구 가치가 조금 남아 있지만 v1의 주요 병목은 아니다.
이미 관찰한 시험 자료로 설정을 계속 바꾸면 독립 성능 근거도 강해지지 않는다. MPI 연구 결과는
실패 조건을 보여 주는 기술 부록으로 보존하고, 아래 재개 조건 전까지 추가 튜닝을 멈춘다.

## v1 지원 범위

| 항목 | v1에서 지원하는 범위 |
| --- | --- |
| 품목 | MVTec AD transistor 시연 품목 |
| 주력 모델 | 동결된 PatchCore seed 42 bundle |
| 판정 | 자동 합격 없이 `REVIEW_REQUIRED` 또는 명시적인 실패 |
| 작업자 흐름 | 검사 결과 저장 → 검토 대기열 → 사람 의견 → 모의 SOP 근거 → 승인 → 모의 티켓 |
| 실행 환경 | 연구실 Windows GPU 검사, 우선 같은 장비에서 검토까지 연결 |
| 연구 결과 | PaDiM/PatchCore, 3품목, Real-IAD, VisA, MPI-PCB 결과를 한계와 함께 보존 |

Cable·metal_nut과 외부 PCB 실험은 검증 자료로 유지하지만, v1 서비스 API가 다품목 운영을 지원한다고
주장하지 않는다. 실제 현장 SOP, 외부 티켓 전송, 자동 PASS, 생산 성능 보장은 범위 밖이다.

## 진행 순서와 완료 기준

### 1. 재현 가능한 개발 기준

- 개발·테스트 의존성을 한 설치 명령으로 제공한다.
- 전체 CPU 테스트를 `python -m pytest -q` 한 명령으로 실행한다.
- GitHub Actions가 같은 명령을 새 환경에서 자동 실행한다.
- GPU가 필요한 실제 모델 시험과 CPU 가짜 runtime 테스트를 문서에서 구분한다.

완료 기준: 새 Python 3.11 환경에서 설치 후 전체 테스트가 수집 누락 없이 통과한다.

### 2. transistor 단일 장비 전체 흐름

- 검사 API가 만든 bundle을 같은 장비의 검토 저장소에 안전하게 등록한다.
- 체크섬과 모델·임곗값·입력 조건을 등록 전에 확인한다.
- 성공, 잘못된 이미지, 모델 미준비, 중간 실패, 동일 요청 재시도를 시험한다.
- 반복 요청과 반복 등록이 검사 또는 모의 티켓을 의도치 않게 복제하지 않게 한다.
- 검토 revision이 바뀌면 이전 승인과 근거를 잘못 재사용하지 않게 한다.

완료 기준: 한 장비에서 이미지 입력부터 모의 티켓까지 반복 실행되고, 실패와 재시도 이력이 남는다.

### 3. 실제 응답시간과 자원 측정

- 모델 최초 준비 시간과 상주 모델 재사용 요청을 분리한다.
- 이미지 읽기, 전처리, GPU 추론, 결과 변환, 파일 저장, 검토 등록 시간을 구분한다.
- 평균뿐 아니라 p50·p95, RAM, GPU 할당·예약량을 기록한다.

완료 기준: 현재 장비에서 사람이 단건 검토할 때의 전체 지연과 병목을 설명할 수 있다.

### 4. 시연·복구·문서 마감

- 설치부터 시연까지 하나의 runbook으로 정리한다.
- 모델이 없는 환경은 실제 추론처럼 보이지 않는 결과 재생 모드를 제공한다.
- DB 백업·복구와 모델 버전 변경·복구를 시험한다.
- README는 현재 지원 범위를, 연구 보고서는 과거 실험을 설명한다.

완료 기준: 다른 사람이 문서만 보고 설치·시연·복구하고 현재 한계를 설명할 수 있다.

## 모델 연구 재개 조건

다음 중 하나가 생길 때만 MPI-PCB 또는 새 모델 연구를 다시 연다.

1. 서비스 목표가 정해져 현재 모델이 그 recall·지연·메모리 기준을 충족하지 못한다.
2. 같은 제품의 독립 촬영 세션 또는 새 미관찰 holdout을 확보한다.
3. 오류 분석이 한 가지 변경으로 검증할 수 있는 구체적인 원인을 제시한다.

재개하더라도 한 번에 한 요인만 바꾸고, 이미 본 시험 결과는 탐색 결과로 명시한다.

2026-09-29 후속 분석에서 영역별 정상 분포의 꼬리 폭을 반영하는 Q90 보정이 기존 출력으로
검출53/55장·오경보3/54장을 보였다. 사용자가 후속 진행을 요청해 조건3의 구체적인 보정 가설에
한정하여 [고정 후보 재현과 미사용 정상 검증](mpi-score-validation.md)을 진행한다. 비교 대상은
기준 A·Q90·원시 점수+MAD 세 가지다. 기존406장 재현 후 미사용 정상256장을 고정 임계값으로
평가하며 새 정상으로 기준을 다시 맞추지 않는다. 모델 재학습이나 서비스 교체는 포함하지 않는다.
연구실 결과를 수령해 기존406장 점수 차이0, 새 정상256장 오경보 A13장·Q9014장·원시 점수18장을
확인했다. 세 방법 모두 관측5% 목표를 넘었다. [다섯 사례 검토](../reports/mpi-score-case-review-v1-received-review.md)도 완료했다.
2026-09-30 사용자가 승인한 후속 작업은 [26×26 공간 집계 한 종류 비교](mpi-spatial-score-v1.md)다.
기존 모델·Q90은 보존하고 후보만 별도 정상 개발·보정 자료로 보정한다. 이미 관찰한 자료의 탐색 비교이며 서비스 승격은 포함하지 않는다.

## 바로 다음 작업

재현성 기준을 먼저 통과한 뒤, **검사 bundle을 같은 장비의 검토 저장소에 등록하는 단일 진입점**을
설계한다. 이때 기존 검사 API·SQLite 검토 저장소·Streamlit 화면을 재사용하고 모델이나 임곗값은
변경하지 않는다.
