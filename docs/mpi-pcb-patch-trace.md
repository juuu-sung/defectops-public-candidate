# MPI-PCB A 잔여 오류와 정상 패치 출처 진단

기준일: 2026-09-28. **실제 연구실 GPU 진단 수령·검토 완료**.
[결과](../reports/mpi-pcb-patch-trace-v1.md): 선택 bank369개 출처 연결, 점수 차이0.
아래는 실행 당시 고정 설계다. 다음 실험은 [동일 영역 검색 대조](mpi-pcb-region-search.md)다.

## 왜 하는가

[점수 비교 결과](../reports/mpi-pcb-score-probe-v1.md)에서 A는 불량 검출을 1/55 → 33/55장으로
개선했지만 22장을 놓쳤다. 정상 오경보는 1/54 → 3/54장이다. A를 연구용 기준선으로
보존하고, 남은 오류를 줄일 다음 **한 가지** 변경을 정하기 위한 진단이다.

이번 실행에서는 정확도를 높이려고 모델을 바꾸지 않는다. 두 질문에 답할 자료를 만든다.

1. 새 오경보와 정상 보정 경고 기준을 만든 사진에서 어떤 정상 구조가 크게 반응하는가?
2. 대표 미탐 부위를 모델은 어느 정상 학습 사진·영역의 패치와 비슷하다고 보는가?

## 무엇을 유지하고 무엇을 계산하는가

| 자료/계산 | 이번 역할 | 바꾸지 않는 것 |
| --- | --- | --- |
| 기존 MPI checkpoint, bank 78,643×768 | 같은 결과 재현, 모델이 실제 선택한 최근접 bank 행 기록 | 모델 파일·특징층·대표 패치·bank 크기 |
| A의 정상 개발 128장·보정 169장 결과 | 이미 저장된 중앙값·MAD·기준 5.4966275137 사용 | 임곗값 재선정 없음 |
| 아래 선택 사례 12장 | 12영역 모두 재추론, 기존 top1·raw·A 점수/판정 대조 | 기존 평가 성적·분모 |
| **기존 정상 학습 원본 64장 × 12영역** | 특징만 다시 계산해 bank 패치 출처 검색 | 새로운 학습 자료 추가 없음 |

### 64장을 다시 처리하는데 왜 재학습이 아닌가

기존 checkpoint에는 대표 패치의 특징 값은 있지만 **원본 사진·영역·격자 위치의 명단은 없다.**
따라서 저장된 동일한 특징 추출기로 원래 학습 정상 64장의 특징을 다시 계산하고,
원래의 공간 간격 2로 남긴 후보 786,432개와 선택된 bank 행을 대조한다.

역전파, coreset 선택, bank 교체, 새 임곗값 계산은 하지 않는다. 모든 후보를 하나의 큰 GPU
텐서로 쌓지 않고 **타일 한 장씩 1,024개 특징**만 처리한다. 읽은 사진·후보 수와 해시를 남긴다.

출처는 little-endian float32 특징 값의 SHA256이 **정확히 일치할 때만** 연결한다.
일치 후보가 여러 개면 모든 원본 위치를 보존한다. 하나를 진짜 원본이라고 임의로 확정하지 않는다.
정확한 재현이 안 되면 `unresolved`로 남기며 비슷한 값으로 몰래 대체하지 않는다.
수치 재현 특성 때문에 실제 GPU에서 출처를 얼마나 복원할 수 있을지는 아직 모른다.

## 고정한 12개 사례

새 A 결과를 본 뒤 선정한 **사후 진단 사례**다. 독립 시험이나 무작위 표본이 아니다.
점수 순 정렬 후 중간은 `n//2`, 동점은 사진 key 순으로 고정한다.

| 역할 | 사진 |
| --- | --- |
| A 정상 오경보 전체 | `good/0019`, `good/0012`, `good/0046` (새 오경보는 0019·0046) |
| A 기준을 정한 정상 보정 사진 | `calibration/0411` |
| 정상 보정 중간 점수 대조 | `calibration/0196` |
| 시험 정상 비경고 중간 점수 대조 | `good/0020` |
| A 미탐 점수 최저·중간·최고 | `defect/0024`, `defect/0041`, `defect/0020` |
| A 미탐 중 최고 영역에 GT가 없는 사례 | `defect/0034` |
| 기존에도 검출한 불량 대조 | `defect/0010` |
| 새로 검출한 불량 중 A 점수가 가장 낮은 대조 | `defect/0046` |

`good/0046`과 `defect/0046`은 서로 다른 파일이다. 정상·불량 prefix를 생략해 섞지 않는다.
선정 규칙은 수령 ZIP의 수치로 재계산하여 위 12장과 일치하는지 확인했다.

## 어떤 패치를 추적하는가

Anomalib의 기존 최근접 탐색 결과를 관찰하여 거리와 bank index를 기록한다.
별도 거리 구현으로 대체하거나 추론용 모델을 변경하지 않는다. 원래 weighted raw score를
계산할 때 쓰는 추가 이웃 탐색과, 입력 4,096패치의 1-NN 탐색을 구분한다.

각 타일에서 다음 지점을 고른다. 역할이 같은 좌표로 겹치면 중복 제거한다.

- 원시 패치 거리 최댓값과 중간값 지점: 정상/비결함 위치 대조를 포함한다.
- GT가 있는 경우 해당 표시 격자 중 거리 최솟값·중간값·최댓값 지점.
- 256×256 GT를 64×64 표시 격자로 연결할 때 **4×4 안에 GT 픽셀이 하나라도 있으면 포함**한다.
  작은 GT가 단순 축소로 사라지지 않게 하지만, 이 격자 범위는 CNN의 실제 수용영역이 아니다.
- 작은 특징 거리=정상 bank와 가까움. 이는 평활화 이전 값이며 A 사진 점수·지도 픽셀값과 다르다.
- 입력의 최근접 bank 행 하나를 추적한다. 서로 다른 bank 벡터가 같은 거리를 갖는 경우의 모든
  동률 최근접 행을 열거하는 것은 아니며, 라이브러리가 선택한 index를 기록한다.

각 사례의 모든 선택 지점은 JSON에 보관한다. 화면에는 최대 6개 대표 지점을 보여준다.
A 최고 영역의 거리 최대 → GT 낮음/중간/높음 → 거리 최대/중간 대조 순서로 한 지점씩
넣으며, 각 역할에서는 A 영역 점수가 높은 곳부터 고른다. 그림이 전체 지점 전수 표시는 아니다.

출처를 같은 영역만 / 다른 영역만 / 여러 영역에 걸친 동일 특징 / 미확인으로 나눈다.
**다른 영역 매칭 자체가 잘못된 매칭이라는 뜻은 아니다.** 정상 대조에서도 흔할 수 있다.
GT 역할의 여러 지점·영역은 상관된 사례이며 독립 불량 수로 세지 않는다.
이 진단만으로 학습 정상 다양성 부족이나 실제 부품 결함 원인을 확정하지 않는다.

## 실행·재개와 안전장치

1. 수령 ZIP, 원본 압축 파일, checkpoint, 기존 입력 코드/보정 규칙의 해시를 확인한다.
2. 실제 환경이 기존 checkpoint 재로딩 환경과 같은지 확인한다. 정상 8장/96영역 + warmup 5영역으로
   점수 재현·심한 속도 저하를 먼저 검사한다.
3. 원래 학습 정상 타일 하나에서 직접 특징 재계산과 기존 추론 내부 특징의 정확한 일치를 확인한다.
4. 선택된 12장/144영역의 top1·raw·A 점수 차이가 0.0001 이내이고 A 판정이 유지되는지 검사한다.
5. 학습 정상 64장/768영역의 후보를 한 타일씩 읽어 **선택된 bank 벡터의 출처만** 검색한다.
6. 모델 bank의 실행 전후 float32 해시도 대조한다. 변경되면 이 실행을 무결성 중단 상태로 고정한다.
7. 진단 JSON·전체 사진 카드 24개·패치 출처 카드 12개·한국어 HTML 화면을 별도 ZIP으로 묶는다.

사례별·정상 원본별 완료 기록을 검증해 재사용한다. 중단되면 같은 명령으로 이어갈 수 있다.
새 GPU 작업이 필요할 때 정상/특징 경로 점검을 다시 한다. 완료 파일이 손상되거나 입력이
달라지면 보존하고 중단한다. 손상 파일 자동 삭제·덮어쓰기·새 모델 학습은 없다.
bank 무결성 오류가 기록되면 무조건 재시도하지 말고 오류를 공유한다.

완료 상태는 정확한 출처가 전부 연결되면 `patch_trace_completed_exploratory`, 일부 또는 전부
연결되지 않으면 `patch_trace_completed_with_unresolved_sources`다. 후자는 출처 검색의 한계를
기록한 진단 완료이지, 출처 검증 성공이라는 뜻이 아니다. 이 경우 임의 근사 연결을 하지 않는다.

## 연구실 Windows에서 하실 일

다른 GPU 작업을 정상 종료한 뒤 기존 프로젝트에서 아래를 실행한다.
새 데이터 다운로드, 패키지 재설치, 학습 명령은 필요 없다.

```powershell
Set-Location "C:\개인 프로젝트\defectops"
git pull --ff-only
if ($LASTEXITCODE -ne 0) { throw "git pull 실패: 여기서 멈추고 오류를 공유해 주세요." }
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\scripts\run_mpi_patch_trace.ps1"
```

이전 비교의 `mpi-pcb-score-probe-v1.zip`을 포함한 기존 `artifacts\handoff` 자료와
`Downloads\extracted.zip`, 기존 checkpoint·복구 타일을 읽는다. 파일이 없으면 새로 학습하지 말고
오류에 표시된 경로를 공유한다.

본 진단은 전체 시험 109장 재평가나 수 시간 coreset 학습이 아니다. 12장 추론과 정상 64장
특징 재계산, 약 2.4GB의 특징 값 누적 해시 처리를 한다. 실제 소요 시간은 아직 측정하지 않았으며
원본 해시 검사·사진 카드 생성 시간이 추가된다. GPU/CPU 메모리 최고값도 실제 결과에서 확인한다.

완료 후 전달할 파일:

`C:\개인 프로젝트\defectops\artifacts\handoff\mpi-pcb-patch-trace-v1.zip`

직접 결과 보기:

```powershell
Start-Process ".\artifacts\analyses\mpi-pcb-patch-trace-v1\result\index.html"
```

ZIP에는 원시 특징 배열·checkpoint·전체 데이터셋을 넣지 않는다. 출처를 표시한 파생 이미지와
진단 JSON만 담는다. 이를 Git에 올리지 않는다.

## 결과를 받으면 결정할 것

- 다른 영역 정상 패치와의 매칭이 잔여 오류와 연관된 근거가 있는가? 그러면 **영역별 bank** 대조를 검토한다.
- 고득점 정상의 외형과 학습 정상 표현의 차이가 더 중요한가? 그러면 **정상 대표성/학습량** 대조를 검토한다.
- 출처가 미확인이거나 근거가 불충분하면 원인을 확정하지 않고 무엇이 빠졌는지 기록한다.

새 오경보·기준 정상·대표 미탐·정상/검출 대조군의 관찰과 출처를 정리하고,
다음 변경 하나의 근거와 실패 조건을 정하는 것이 이번 단계의 종료 조건이다.
현재 A 성적, 109장 평가, 108장 민감도 결과, 자동 PASS 금지와 기존 transistor 서비스는 유지한다.

구현 참조: [Anomalib v2.2.0 PatchCore](https://raw.githubusercontent.com/open-edge-platform/anomalib/v2.2.0/src/anomalib/models/image/patchcore/torch_model.py).
Mac의 합성 runtime 테스트는 실제 GPU에서 출처 복원이 성공했다는 근거가 아니다.
