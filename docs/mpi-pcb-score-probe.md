# MPI-PCB 미탐 원인 검토와 점수 비교 v1

기준일: 2026-09-28. **실행기 준비 완료 / 실제 연구실 비교 결과 대기**.
기존 시험은 이미 관찰했으므로 사후 탐색이며, 독립 검증·서비스 채택이 아니다.

## 왜 하는가

MPI 정상 기준표를 만든 뒤 불량 위치에 대한 반응은 개선됐지만, 기존 경고 기준에서는
55장 중 54장을 놓쳤다. AUROC 0.9118은 점수 순위의 개선이지 91% 검출률이 아니다.
정상 중 높은 점수를 내는 사례가 경고 기준을 올렸을 가능성과, 점수 집계 방식 문제를
구분한다. [수령 결과와 해석](../reports/mpi-pcb-normal-bank-evaluation-v1.md)을 참고한다.

## 무엇을 바꾸고, 무엇을 유지하는가

| 비교 | 영역 점수 | 원본 사진 점수 | 경고 기준 |
| --- | --- | --- | --- |
| 기존 기준선 | 이상 지도 상위 1% 평균 | 12영역의 최댓값 | 기존 46.839376955497556 보존 |
| A: 영역별 정상 차이 보정 | `(기존 영역 점수 − 해당 영역 정상 중앙값) / 해당 영역 MAD` | **모든** 12영역의 최댓값 | 정상 보정 169장에서 새로 산출 |
| B: PatchCore 자체 점수 | Anomalib 모델이 반환한 원시 이미지 점수 | 12영역의 최댓값 | 정상 보정 169장에서 별도로 산출 |

MAD는 정상 점수가 중앙값에서 떨어진 거리들의 중앙값이다. 12영역 모두 같은 방법을
적용한다. 특정 결함 위치를 시험 정답에서 알아낸 뒤 해당 영역만 검사하지 않는다.
MAD가 0.000001 이하이면 중단하며 다른 계산법으로 몰래 대체하지 않는다.
B는 지도 최댓값과 같다고 가정하지 않고 모델 반환값을 직접 사용한다.
A+B 조합, 상위 비율 변경, 특징층·해상도·bank 크기 변경은 이번 실험에 넣지 않는다.

**재학습하지 않는다.** 체크포인트 `3d1635bd…d56a73`, 78,643×768 bank, 고정 특징층,
256×256 입력을 그대로 쓴다. 서비스는 기존 MVTec transistor 모델을 유지한다.
기존 임곗값 파일·검토 이력·SOP·티켓도 바꾸지 않는다.

## 데이터 역할을 분리한다

| 자료 | 원본 수 × 12영역 | 이번 역할 |
| --- | --- | --- |
| 기존 정상 학습 | 64 × 12 = 768 | 저장 모델의 출처. 이번에는 재학습하지 않음 |
| **별도 정상 개발** | **128 × 12 = 1,536** | A의 영역별 중앙값·MAD 계산. 특징을 bank에 추가하지 않음 |
| 기존 정상 보정 | 169 × 12 = 2,028 | A/B 각각 원본 사진 점수의 95% 분위수(`higher`) 계산 |
| 기존 시험 | 109 × 12 = 1,308 | 정상 54·불량 55장에서 기존/A/B 비교 |

개발 128장은 준비 ZIP의 정상 풀에서 `SHA256(mpi-pcb-score-probe-v1\0photo_id)`
오름차순으로 고른다. 정상 학습·보정 원본과 겹치거나, 그 자료 및 기존 시험 전체의 어느
영역과든 RGB가 정확히 같은 타일을 포함한 원본은 제외한다. 선택된 개발 원본끼리도
타일 중복이 있으면 뒤 원본을 제외한다. 시험 점수·불량 종류·마스크로 정상 개발을 고르지 않는다.
이 규칙으로 Mac에서 명단 계산을 검증했고, 128장/1,536영역이 확보됐다.
명단 SHA256: `63d49a5794c10d2521f6b4626465ace6bdcf36c9d2d87ea9f4f9bfdf0c37e694`.
이는 픽셀 중복 분리이지 다른 생산 개체·촬영 세션의 독립성을 보장하지 않는다.

개발 자료로 정상화 기준을 정한 다음, **별도 보정 자료로 최종 12영역 최대 점수의 임곗값을
정한다.** 영역마다 95% 임곗값을 따로 적용한 뒤 OR로 합치는 방식이 아니다.
95% 분위수는 시험 오경보율 5%를 보장하지 않는다.

## 실행 순서와 실패 시 동작

1. 검토된 ZIP 5개, 원본 압축 파일, 체크포인트의 해시·자료 연결을 검사한다.
2. 명단·코드·규칙·검토할 사례를 별도 입력 기록으로 고정한다.
3. 새 프로세스에서 모델을 로드하고 기존 정상 8장으로 점수 재현·심한 속도 저하를 확인한다.
4. 정상 개발 128장 → 정상 보정 169장을 처리한다. 기존 보정 점수 차이는 0.0001 이내여야 한다.
5. A의 정상화 기준과 A/B 임곗값을 저장한 **다음** 기존 시험 109장을 처리한다.
6. 시험의 기존 상위 1% 점수도 모두 재현 확인한다. 기준선의 판정이 바뀌면 중단한다.
7. 성능표·바뀐 판정 명단·검토 카드·입력 기록을 별도 ZIP에 묶는다.

원본별 완료 기록에 해시를 남겨 같은 명령을 다시 실행하면 검증된 완료 원본을 재사용한다.
미완료 시도는 보존하고, 변경되거나 손상된 완료 자료는 재사용하지 않는다.
새 GPU 작업이 필요하면 정상 점검을 다시 통과해야 한다. 자동 삭제·덮어쓰기·재학습은 없다.
새 실험 파일은 기존 실행기의 입력 코드 목록을 바꾸지 않으므로, 기존 학습·평가 재개 기록과도
충돌하지 않음을 확인했다.

## 사진으로 확인할 것

기존 점수만으로 **27개 원본, 54개 카드**를 선택했다. 새 A/B 결과에 유리한 사례를
사후에 골라 넣지 않는다.

- 보정 정상: 고득점 10장 + 중간 점수 3장.
- 기존 미탐: 점수 하위·중간·상위 각 3장 = 9장.
- 기존 검출 불량 1장, 정상 오경보 1장, 정상 비경보 중간 3장.

각 카드는 원본+정답, 고정 색상 이상 지도, 상위 1% 반응 위치를 나란히 보여준다.
정상에서는 조명·반사/정렬·경계/부품 외관 변화와 반응의 겹침을 확인한다.
불량에서는 실제 결함 부위와 다른 정상 부위의 반응을 비교한다. 이는 원인 가설을 검토하는
자료이지 색만으로 결함 원인을 자동 확정하는 기능이 아니다.
동점 때문에 빨간 상위 반응 표시가 656픽셀보다 많을 수 있다.
손상 마스크가 있는 `defect/0006`은 분류에는 포함하되 원본 전체를 위치 통계에서 제외한다.
이번 카드 통계를 새로운 전수 위치 성능으로 제시하지 않는다.

## 연구실 Windows에서 실행

다른 GPU 작업을 정상 종료한 뒤 프로젝트 PowerShell에서 아래 전체를 실행한다.
Python·패키지 재설치나 모델 학습 명령은 필요 없다.

```powershell
Set-Location "C:\개인 프로젝트\defectops"
git pull --ff-only
if ($LASTEXITCODE -ne 0) { throw "git pull 실패: 여기서 멈추고 오류를 공유해 주세요." }
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\scripts\run_mpi_score_probe.ps1"
```

첫 실행은 정상 점검 101영역 + 본 비교 4,872영역을 추론한다. 이전 측정 약 0.096초/영역을
단순 곱하면 순차 영역 처리만 약 8분이다. 원본 해시 검사·카드·출력·시작 비용은 별도이며
완료 시간 보장이 아니다. 오래 걸리는 coreset 학습은 하지 않는다.

완료 후 전달할 파일:
`C:\개인 프로젝트\defectops\artifacts\handoff\mpi-pcb-score-probe-v1.zip`

쉬운 성능 비교표와 카드 직접 보기:

```powershell
Start-Process ".\artifacts\analyses\mpi-pcb-score-probe-v1\result\index.html"
```

ZIP에는 보고 JSON·HTML·출처 표시된 검토 카드가 들어가며 체크포인트·원시 맵은 넣지 않는다.
원본 데이터와 산출 이미지는 Git에 추가하지 않는다.

## 결과 판단과 다음 단계

정상 54·불량 55장의 미탐/오경보를 **같이** 비교하고, 새로 잡은 불량과 새로 놓친 불량의
명단을 모두 확인한다. 복구 사진 `defect/0054`를 뺀 108장 결과도 선택 없이 함께 보고한다.
공유 추론으로 두 점수를 얻으므로 실행 시간을 후보별 독립 속도 측정으로 해석하지 않는다.
현재 자료는 이미 본 한 기판의 반복 촬영·수동 변형이다. 후보 성적이 좋아져도 곧바로
일반화나 실제 생산 성능을 주장하거나 자동 PASS로 전환하지 않는다.

- A가 주로 좋아지면: 영역별 정상 분포 차이의 영향을 검토한다.
- B가 주로 좋아지면: 기존 지도 점수 집계가 병목인지 검토한다.
- 둘 다 약하면: 카드 근거로 특징 구분력·정상 bank 표현 범위 실험을 **한 가지씩** 설계한다.
- 불량 검출만 좋아지고 정상 오경보가 크게 늘면: 이를 개선으로 단정하지 않는다.

**다음 행동은 ZIP 수령 후 수치·판정 변화·사진 근거를 함께 검증하는 것이다.**
Mac 테스트는 합성 runtime의 실행·중단·재개·무결성 검증이다. 실제 Windows GPU/PowerShell
실행과 실제 A/B 성능은 아직 검증하지 않았다.
