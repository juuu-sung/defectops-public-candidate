# PatchCore 정상 사진 확대 실행

정상 사진을 기존64장에서 이를 포함하는256장으로 확대한다. 대표 패치78,643개와 특징 추출기·사진 점수·Q90 보정 규칙은 유지한다. 같은 크기의 정상 기준표에 더 다양한 외관을 담으면 미탐·오경보·보정 불안정이 개선되는지를 확인하는 탐색·회귀 실험이다. 기존 모델과 서비스는 변경하지 않는다.

## 고정 조건

| 항목 | 기존 Q90 | 이번 후보 |
| --- | --- | --- |
| 정상 학습 원본 | 64장 | 기존64장을 포함한 고정256장 |
| 원본마다 영역 | 12개 | 12개 |
| 타일마다 유지 패치 | 1,024개 | 1,024개 |
| 대표 선정 전 후보 | 786,432개 | 3,145,728개 전부 |
| 최종 대표 수 | 78,643개 | 78,643개 |
| 특징 | WideResNet50_2 layer1·2, 768차원 | 동일 체크포인트의 추출기 가중치 복사 |
| 대표 선택용 투영 | eps0.9, 335차원 | eps0.9, 후보 수 공식에 따라369차원 |
| 보정 | 별도 정상128장·169장 | 같은 자료·같은 산식, 후보 점수로 새 경고선 |

256장 명단은 검토 완료된 SuperSimpleNet 확대 학습 ZIP에서 가져온다. 정상 개발·보정·검증 자료와 섞지 않으며 다시 뽑지 않는다. 최종 bank는 약0.225GiB로 유지한다. 후보 전체의 원특징은9GiB이며 GPU가 아닌 디스크에 둔다. 패치에 L2 정규화를 추가하지 않고 영역별 할당이나 임의 후보 축소를 하지 않는다.

공식 투영 산식은 후보 수에 따라 차원이 달라진다. 따라서 데이터만 바뀌고 내부 계산은 완전히 같다고 주장하지 않는다. 작은 합성 문제에서는 공식 방식과 선택 인덱스가 일치했지만 실제 전체 자료의 분할 투영이 단일 행렬 곱과 비트 단위로 같다는 보장은 없다. [Anomalib 2.2 투영 구현](https://raw.githubusercontent.com/open-edge-platform/anomalib/v2.2.0/src/anomalib/models/components/dimensionality_reduction/random_projection.py)을 따른다.

## 한 명령에서 진행하는 단계

1. **정상 특징 저장:** 먼저 기존 모델로 정상8장 점수를 재현해 전처리·계산 설정이 달라지지 않았는지 확인한다. 256원본×12영역을 고정 순서로 읽고, 사진마다12,288개 특징을 저장한다. 기존 모델의 추출기만 복사하며 불량 이미지를 학습하지 않는다. 기존 PatchCore의 결정적 cuDNN·cuDNN TF32 허용·행렬 곱 TF32 비허용 조건을 명시적으로 고정한다.
2. **대표 선택:** 모든 후보를65,536행씩 투영해 저장한다. 추출 모델을 GPU에서 내린 후 약4.324GiB의 투영 특징을 올리고 거리 계산만 나눠 수행한다. seed42, eps0.9, 대표78,643개를 고정한다.
3. **모델과 경고선 저장:** 선택된 원래768차원 특징을 모아 bank를 만든다. 별도 정상128장의 영역별 중앙값·Q90폭과 정상169장의 사진Q95 higher로 경고선을 계산한다. 이미지 입력256, 전처리·이웃9개·상위1%평균·12영역 최대 집계는 기존과 같다.
4. **재로딩 확인:** 저장 모델을 다시 불러와297개 정상 원본 점수 차이≤1e-4, 판정 변화0을 확인한다. 평가 프로세스에서도 고정 정상8장의 지도·점수를 다시 확인한 뒤 시험 자료를 연다.
5. **전체 비교:** 불량55장·정상54장·별도 정상256장을 검사한다. 기존12장 검출은 설명용이며 성적이 나빠도 나머지 평가를 중단하지 않는다. 모델은 고정한다.
6. **위치·비용·안정성:** 불량55장과 각 정상 집합의 고점수3장씩 총12장을 수치 진단한다. 결함0006은 위치만 제외한다. 기존 검증 지도와 비교하며 없으면 없다고 기록한다. 같은 정상20장을3회씩 양 모델에서 측정하고, 정상 개발만·보정만·양쪽 각각200회 재표집한다. 실패한 표집을 버리거나 다시 뽑지 않는다.

결함 정답 마스크는 학습이나 점수 계산에 쓰지 않는다. 지도 진단은 GT 평균·최대 반응, 타일 내 AUROC, 상위656픽셀과 결함의 겹침으로 보고하며 새 픽셀 임곗값은 만들지 않는다. 결과 그림과 원본은 이번 JSON 전달 ZIP에 넣지 않는다.

## 비교 기준

기존53장 검출을 모두 보존하고, 정상 오경보≤2/54·≤12/256을 목표로 한다. 미탐 개선이라는 표현은 기존 미탐0019·0024 중 적어도1장을 추가 검출하고 기존 검출을 잃지 않았을 때만 쓴다. 검출 수가 같아도 다른 불량을 놓치면 별도로 보고한다.

정상 재표집600회의 난수·범위·수치 기준은 기존 안정성 계약을 유지한다. 세 범위 각각 검출2.5백분위≥50, 검출구간 폭≤기준선 폭+0.5, 오경보97.5백분위≤5/54·≤25/256, 무효 표집0회를 요구한다. 점수 설명만 이번 상위1%평균 방식으로 명시한다. 이것은 보정 민감도이며 독립 일반화 성능의 신뢰구간이 아니다. Q90도 운영 승인 모델이 아니며 자동 PASS나 자동 서비스 교체는 없다.

## 자원과 재개

- 시작 시 디스크 여유32GiB, GPU 여유6GiB를 요구한다. 재개 시 최소5GiB를 확인한다. 원특징9GiB·투영4.324GiB·중간 거리 상태 약1GiB·지도와 모델 등을 보존한다. 반복 강제 종료로 남은 파일은 자동 삭제하지 않는다.
- RAM 표본 피크20GiB·PyTorch reserved 피크6GiB 상한은 유지한다. 장비 전체 GPU 사용량도 기록한다. 시간 상한은 없다.
- 원본1장·투영 블록1개·선택1,000개 단위로 원자적 저장과 SHA256 검증을 한다. 선택 시 최소거리 벡터·선택 인덱스·다음 중심을 함께 저장하므로 처음부터 다시 선택하지 않는다.
- Ctrl+C를 한 번 누르고 정리될 때까지 기다린다. 같은 코드·입력의 동일 명령으로 저장 완료 지점부터 재개한다. 선택 구간에서는 마지막 저장 이후 최대약1,000회만 다시 계산한다. 실패·메모리 초과·강제 종료로 종료 기록이 없는 경우는 자동 재시도하지 않고 검토를 요청한다.
- 실행 중 `git pull`·파일 수정·출력 삭제·다른 GPU 작업을 하지 않는다. 일반 종료로 다른 GPU 작업을 끝낸 후 시작한다.

합성 규모 점검에서 대표 선택만 약45분으로 환산됐다. 실제 사진 특징·디스크 저장·전체 보정·평가 시간은 포함하지 않은 참고치이므로 총 완료 시간으로 해석하지 않는다.

## 연구실 실행

```powershell
Set-Location 'C:\개인 프로젝트\defectops'
git switch main
git pull --ff-only
powershell.exe -NoProfile -ExecutionPolicy Bypass -File '.\scripts\run_mpi_patchcore_scaling.ps1'
```

원본 기본 경로는 `Downloads\extracted.zip`이다. 이전 handoff ZIP들과 기준 모델, 승인된0054 복구 파일은 기존 프로젝트 안에 그대로 둔다. 새 다운로드나 재학습으로 대체하지 않는다. 다른 원본 위치는 PowerShell 실행기에 `-Archive '실제 파일 경로'`를 전달한다.

학습 종료 시 `artifacts\handoff\mpi-patchcore-scaling-fit-v1.zip`을 먼저 남기고 평가까지 자동 이어간다. 최종 전달 파일은 `C:\개인 프로젝트\defectops\artifacts\handoff\mpi-patchcore-scaling-v1.zip`이다. 큰 모델·특징 캐시·이미지는 포함하지 않는다. 오류가 나면 파일을 보존하고 전체 오류를 전달한다.

## 검증 범위

Mac CPU 테스트는 저장·재개·해시·전체 후보 순서·점수/보정 산식·실패 보존을 검증한다. NumPy 대역 실행은 실제 CUDA 검증이 아니다. 실제 이미지 특징 추출과 전체 선택·모델 추론은 연구실 실행에서 확인한다. 기존 합성 GPU 점검 통과가 새 모델 성능이나 전체 실행 성공을 보장하지 않는다.
