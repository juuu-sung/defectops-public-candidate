# MPI 보정 후보 재현과 미사용 정상 검증

2026-09-29 고정. 목적은 **기존 모델 출력으로 발견한 개선이 재현되는지**, 그리고 **아직 보정에 사용하지 않은 정상 사진에서 오탐이 유지되는지** 확인하는 것이다. 모델을 새로 학습하거나 서비스에 적용하는 실행은 아니다.

## 고정한 비교

| 방법 | 영역 점수 | 기존 불량 검출 | 기존 정상 오탐 | 고정 임계값 |
|---|---|---:|---:|---:|
| 기준 | (top1 − 영역 중앙값) / MAD | 33 / 55 | 3 / 54 | 5.496627513743306 |
| Q90 후보 | (top1 − 영역 중앙값) / (Q90 − 중앙값) | 53 / 55 | 3 / 54 | 2.3169610768645974 |
| 원시 점수 후보 | (native_raw − 영역 중앙값) / MAD | 46 / 55 | 3 / 54 | 5.6920057976697285 |

- top1은 이상 지도 상위 1% 픽셀의 평균이며 native_raw는 기존 PatchCore 원시 사진 점수다.
- 영역별 중앙값·척도는 기존 개발 정상128장으로 계산한다. MAD는 배율을 곱하지 않는다. Q90은 `higher` 방식이다.
- 사진 점수는12개 영역의 최대값이다. 기존 calibration 정상169장에서95% `higher` 분위수를 임계값으로 정한다. 점수 ≥ 임계값이면 검토 대상으로 센다.
- 후보 선정에는 이미 본 시험109장의 결과를 사용했다. 위 표는 **탐색 결과**이며 독립 시험 성능이 아니다.
- 모델·bank·입력 해상도는 이전과 같다. 기준 아래인 MPI 사진도 자동 합격으로 승격하지 않는다.

계산 근거와 관련 연구는 [성능 개선 검토](../reports/performance-improvement-review-2026-09-29.md)에 있다. 실제 실행 계약은 [고정 설정](../configs/mpi-score-validation-v1.json)이다. 검증 결과를 본 뒤 이 파일을 재생성해서 같은 실험에 재사용하면 안 된다.

## 이번 실행 순서

1. 원본ZIP·이전 전달ZIP·checkpoint·기존 추론 코드의 checksum을 확인한다. 개발/보정/시험 점수 기록과 사진 목록의 대응도 확인한다.
2. 고정된 설정과 검증 정상256장의 명단을 먼저 확인한다. 학습64장·개발128장·보정169장·기존 시험 사진과 사진 번호 및 정확한 RGB 중복을 배제한다. 선택 순서는 고정 hash로 정하며 점수를 사용하지 않는다. 검증 사진끼리 같은 타일 RGB가 있는 경우도 배제한다.
3. 연구실의 기존 모델을 새로 불러온다. 이전 환경과 정상 사진 점수·실행 속도 점검을 통과해야 한다.
4. 개발128 + 보정169 + 기존 시험109 = **406장**을 다시 추론한다. 타일별 top1과 native_raw가 기존 값에서 절댓값 `1e-4` 이내여야 하며, 세 방법의 고정 기준 판정이 모두 같아야 한다. 경계값의 작은 변동으로 판정이 뒤집혀도 중단한다. 이를 숨기기 위해 임계값을 바꾸지 않는다.
5. 재현 통과 기록을 저장한 뒤에만 **미사용 정상256장**을 추론한다. 임계값·중앙값·척도를 다시 맞추지 않는다.
6. 방법별 오탐 수/비율, 기준 대비 추가·제거된 경고, 오탐 사진 번호, 경고가 집중된 영역, 원시 점수, 환경 점검 기록을 결과ZIP으로 저장한다.

총662장, 사진별12영역의 순차 추론이다. 시작·재시작 때 정상 점검 추론이 별도로 들어간다. 필요한 점검만 수행하며 새 의존성을 설치하거나 자료를 다운로드하지 않는다.

## 연구실 Windows 실행

먼저 맥북의 이 변경사항을 Git으로 전달해 연구실에서 같은 commit을 사용한다. 다른 GPU 작업은 정상적으로 마친 뒤 실행한다. 기존 DefectOps `.venv`, 모델, 원본 `Downloads\extracted.zip`, 이전 전달ZIP들이 필요하다. 입력이 없거나 checksum이 다르면 실행이 중단된다.

```powershell
Set-Location 'C:\개인 프로젝트\defectops'
git pull --ff-only
powershell -ExecutionPolicy Bypass -File .\scripts\run_mpi_score_validation.ps1
```

원본ZIP이 다른 위치에 있으면:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\run_mpi_score_validation.ps1 -Archive 'D:\data\extracted.zip'
```

중단되면 오류와 표시된 `failure.json` 경로를 확인한다. **같은 명령을 재실행하면 검증한 완료 사진을 재사용**한다. 입력·코드·설정 또는 캐시가 바뀌면 조용히 덮어쓰지 않고 중단한다. 기존 결과를 삭제하거나 후보 설정을 재생성해서 통과시키지 않는다. 완료한 실험의 재실행은 사진 캐시와 결과를 확인하며 GPU를 다시 호출하지 않는다.

반환할 파일:

```text
artifacts/handoff/mpi-score-validation-v1.zip
```

실험 폴더는 `artifacts/analyses/mpi-score-validation-v1/`다. 완료ZIP의 `report.json`이 요약이며, `raw-scores.json`, `freeze.json`, `plan.json`, `runtime-probes.json`, `handoff-manifest.json`이 근거다. 체크포인트나 원본 이미지는 ZIP에 포함하지 않는다.

## 결과에 따른 다음 결정

| 관찰 | 다음 행동 |
|---|---|
| 기존406장 점수/판정이 재현되지 않음 | 계산·환경·기록 차이를 조사한다. 미사용 정상 추론은 시작하지 않는다. |
| 재현되고 Q90의 정상 오탐도 낮게 유지됨 | Q90을 우선 후보로 유지하고 새 촬영 세션의 정상·불량을 수집해 독립 검증한다. 서비스 승격은 아직 하지 않는다. |
| Q90의 오탐이 기준 또는 원시 점수 후보보다 크게 증가 | 경고 사진과 집중 영역을 검토한다. 정상 촬영 조건과 분포 추정 안정성부터 개선한다. 같은256장에 다시 맞춘 뒤 검증 완료라고 하지 않는다. |
| 두 후보 모두 새 정상에서 오탐이 많음 | 데이터 정의·촬영 조건·정상 대표성 문제를 먼저 확인한다. 임계값만 높여 기존 개선이 유지된다고 주장하지 않는다. |
| 이후 독립 불량에서도 놓치는 사례가 남음 | 오류 위치에 맞춰 공간 집계·정상 bank·원본 해상도 중 한 요인만 대조한다. 필요하면 AnomalyDINO 한 종류를 후속 비교한다. |

보고서의5% 예산은 **관측 오탐에 대한 진단용 개발 목표**다. 256장에서는12장까지5% 이내,13장은 초과다. 표본 오차·촬영 상관을 무시한 현장 보장이나 자동 승격 조건이 아니다. 새 정상만으로 새 불량 검출률은 측정할 수 없다.

정상 사진들은 같은 데이터셋에서 나온다. 정확한 이미지 중복 배제는 서로 다른 실물·촬영 세션·유사 사진의 독립성을 보장하지 않는다. 검증 가능한 촬영 조건 메타데이터가 없어 이번 코드는 조건별 성능을 만들어 내지 않는다. 새 수집에서는 실물 ID, 촬영 세션, 조명·각도와 불량 유형을 함께 기록해 분리해야 한다.

## 맥북에서 확인한 범위

원본 추론 기록ZIP을 검증하고 세 방법의 기존 판정이 이전 분석과 동일함을 재계산했다. 미사용 정상256장의 명단과 전체 행 hash를 고정했다. CPU 테스트는 계산·분리·중단·재개·변조 검출을 확인한다. 실제 CUDA 재현과 새 정상 오탐 결과는 연구실 실행 후에만 알 수 있다.

2026-09-29 전체 검사: **374개 테스트 및52개 하위 테스트 통과**, 기존 경고3개. 이번 절차의 새 CPU 테스트8개를 포함한다. PowerShell·CUDA 실행은 이 맥북에서 수행하지 않았다.
