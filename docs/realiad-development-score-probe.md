# PCB 작은 결함 점수 방식 탐색 — 개발 데이터만 사용

상태: **코드·검증 절차 준비 완료, 연구실 GPU 결과 미수신** (2026-09-24)

## 왜 하나요?

기존 PCB final에서 세 번 모두 놓친 불량 67장 중 상당수는 결함 위치의 픽셀 점수 순위가
높았지만, 결함이 작아 이미지 점수에 기여한 몫이 낮았다. 반면 9장은 결함 픽셀이 세 seed
모두 상위 1%에 하나도 없었다. 즉 점수 **모으는 방식**만 바꿔 일부를 잡을 가능성은 있지만,
결함 위치의 신호 자체가 약한 사례까지 해결할 수는 없다.

이 관찰로부터 생긴 가설을 이미 관찰한 **development** 데이터에서만 탐색한다. 기존 final의
이미지, 맵, 라벨, 결과는 실행기의 입력이 아니다. Development 결과도 이미 본 데이터이므로
어떤 개선 수치가 나와도 새 final 성능이나 현장 성능으로 주장하지 않는다.

## 무엇을 고정해 비교하나요?

- 기존 PCB seed 42의 `fine_features_top_1pct` 체크포인트를 재사용한다. **재학습하지 않는다.**
- 256×256 anomaly map의 가장 높은 점수 **상위 0.1%, 0.25%, 0.5%, 기존 1%** 평균을 비교한다.
  정답 마스크는 점수 계산에 사용하지 않는다.
- 점수 방식마다 **동일한 정상 calibration 56장**의 95% higher 분위수로 임곗값을 따로 만든다.
- 기존 1% 점수·임곗값·판정이 이전 development 기록과 `1e-5` 이내로 재현되지 않으면 중단한다.
- Development 363장(정상 139, 불량 224)에서 미탐·오탐·결함별 recall을 함께 보고한다.
  기존 미탐이 새로 잡힌 수와 기존 검출을 새로 놓친 수도 표시한다.
- 기존 모델의 development 정답 위치 면적·상위 1% 점수 기여를 함께 집계한다.
  정답 마스크는 이 **사후 설명 통계**에만 쓰인다.
- 비교 후보를 결과를 본 뒤 추가하지 않는다. 이 실행으로 승격 후보를 자동 선택하지 않는다.

기존 checkpoint·manifest·원래 development 점수 파일의 checksum을 확인한다. 이미지별 맵은
출력 폴더에 저장해 중단 후 같은 명령으로 재개한다. 다른 내용의 기존 맵은 덮어쓰지 않고
오류로 중단한다. 전달 ZIP에는 원본 사진·맵·checkpoint를 넣지 않는다.

## 연구실 Windows에서 실행할 작업

기존 프로젝트 폴더와 `.venv`를 그대로 사용한다. 체크포인트와
`artifacts\handoff\realiad-followup-development-v1.zip`이 보존돼 있어야 한다.
이 작업은 GPU에서 약 419장(정상 calibration 56 + development 363)을 다시 추론하므로
시간이 오래 걸릴 수 있다. 이전 warm p95 약 10초/장을 단순 적용하면 **1시간 이상**이지만,
이는 완료 시간 보증이 아니다.

```powershell
Set-Location "C:\개인 프로젝트\defectops"
git pull --ff-only
git status --short

powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File ".\scripts\run_realiad_development_score_probe.ps1"
```

완료되면 `C:\개인 프로젝트\defectops\artifacts\handoff\realiad-development-score-probe-v1.zip`을
이 작업에 첨부하고 출력된 SHA-256을 알려준다. ZIP의 `summary.md`에는 놓친 불량·정상 검토
요청·새로 잡은/놓친 불량을 짧은 표로 담는다. 중단되면 **같은 명령으로 재개**한다.
기존 결과·부분 맵을 삭제하거나 임곗값을 수동 수정하지 않는다.

## 어떻게 읽나요?

1. 기존 1% 기준선의 재현 오차가 0에 가깝고, 원래 판정과 같아야 비교 가능하다.
2. 새 방식이 미탐을 줄여도 정상 오탐 증가와 새 미탐이 생겼는지 동시에 확인한다.
3. 개선이 보여도 **탐색 결과**로만 기록한다. 국소 신호가 약한 사례는 별도의 특징 모델
   가설이 필요하다. 새 미관측 holdout 없이 모델·임곗값을 교체하거나 자동 PASS하지 않는다.
