## 1. 이번에 확인할 것

이전 C단계는 **새 모델을 만들고, 정상 자료로 경고 기준을 정하고, 다시 불러와도 같은 점수가 나오는지** 확인했습니다.
이번 D단계는 **그 모델이 기존 모델보다 검사에 도움이 되는지** 확인합니다. 재학습은 하지 않습니다.
바뀐 요인은 정상 학습 사진64장의 선정 방식뿐이며, 사진 수·특징 추출기·기준표 크기·점수 계산법은 같습니다.

| 확인 항목 | 기존 기준선 | 새 모델에 요구하는 조건 |
| --- | ---: | --- |
| 관찰 불량55장 검출 | 53장 | 53장 이상, 기존에 잡은53장을 하나도 잃지 않기 |
| 관찰 정상54장 오경보 | 3장 | 2장 이하 |

| 충분히 준비된 모델의 사진당 처리 시간 | 이번에 같은 장비에서 다시 측정 | 두 모델 각각 warm p95 2초 이하 |

검출 수가 같아도 기존에 잡던 불량을 놓치고 다른 불량을 잡았다면 통과시키지 않습니다.
109장과256장은 이미 관찰한 자료입니다. 이번 결과는 **탐색·회귀 비교**이지 새 독립 시험 성적이 아닙니다.

## 2. 실행 순서

1. **입력과 기준 확인**: C단계 ZIP, 기존 전달물, 원본ZIP, 두 모델 파일, 고정 명단·코드·설정을 해시로 확인합니다.
   기존 정상 점수에서 Q90 보정을 다시 계산해 저장 계약과 모든 사진 점수 차이가1e-12 이내이고 판정 차이가0인지 확인합니다.
   C단계 새 임곗값2.297261596468405도 저장 정상 점수에서 검산합니다.
2. **새 모델 점수 계산**: 새 프로세스에서 모델을 불러오고 개발 정상 앞16장으로 원점수 차이≤1e-4·판정 차이0을 확인합니다.
   통과한 뒤 고정 관찰109장과정상256장을 계산합니다. 불량 마스크는 읽지 않습니다.
   기존 PNG 복구 예외는 이미 검증된 같은 복구 파일만 사용하며 새 복구나 이미지 제외를 하지 않습니다.
3. **실제 처리 비용 비교**: 기존 모델과 새 모델을 각각 별도 새 프로세스에 불러옵니다.
   각 모델의 정상16장 재현 검사를 통과한 뒤 고정 정상256장 중 앞32장을 사용합니다.
   앞5장 준비 운동 후32장×3회=96회/모델을 측정합니다. 원본사진1장당12영역을 순서대로 처리합니다.
4. **보정 안정성 비교**: GPU 없이 저장된 정상 점수를 재표집하여 총3,000번 가상 보정합니다.
   두 모델에 같은 사진 인덱스를 적용합니다. 모델을 다시 학습하거나 실제 경고 기준을 바꾸지는 않습니다.
   성적·추가/상실 검출·개별 점수·비용·반복 전체 기록을 JSON 전용ZIP에 묶습니다.

콘솔의4개 작업은 `score`, `baseline-warm`, `candidate-warm`, `bootstrap`입니다.
첫 작업 전 입력 검산도 수행합니다. 준비 운동과 정상 재현 검사 시간은 warm 지연에서 제외하지만 총 계산 예산에는 포함합니다.

## 3. 보정 안정성은 무엇인가요?

“정상 자료를 조금 다르게 골랐다면 판단이 크게 달라졌을까?”를 확인하는 검사입니다.
정상128장은 영역별 기준점·변동 폭을, 정상169장은 최종 사진 경고 기준을 결정합니다.

- 개발128장만 복원추출: 영역 척도가 정상 표본에 얼마나 민감한지 확인합니다.
- 보정169장만 복원추출: 최종 경고 기준이 얼마나 달라지는지 확인합니다.
- 두 집합 모두 복원추출: 두 변화가 함께 일어났을 때 확인합니다.

각각1,000회,PCG64 seed20261001/20261002/20261003입니다. 두 집합을 뽑는 경우 개발128개 인덱스 다음 보정169개를 뽑습니다.
사진의12영역은 함께 움직이며 타일을 독립 표본으로 뽑지 않습니다. 매번 동일한 인덱스를 두 모델에 사용합니다.
고정 관찰 시험 점수는 판단 변화를 세는 데만 사용하고 보정 기준 계산에는 넣지 않습니다.

각 상황에서 다음 조건을 모두 요구합니다. 분위수는linear 방식의2.5%·50%·97.5%입니다.

- 검출 수의2.5% 지점이50장 이상.
- 검출 수의97.5%−2.5% 폭이 기존 모델 폭의절반 이하. 기존 폭0이면 새 모델도0이어야 합니다.
- 정상54장 오경보의97.5% 지점≤5장,정상256장의97.5% 지점≤25장.
- 계산 불능 반복0개. 변동 폭이0에 가까운 반복을 버리거나 새로 뽑지 않고 전체 안정성 조건 실패로 기록합니다.

이 분포는 **보정 표본 민감도**이며 미래 제품의 정확도 신뢰구간이 아닙니다.

## 4. 시간·메모리와 앞선 실패

이번 D단계의 누적 예산은 **2시간,PyTorch GPU 예약6GiB,프로세스 RAM RSS20GiB**입니다.
RSS와장치 전체 점유는100ms 표본 최대,PyTorch는할당·예약 peak를 기록합니다.
검사는 사진 경계·재표집 반복 경계에서 수행하므로 한 연산의 순간 초과를 사전에 차단하는hard limit는 아닙니다.

warm 시간에는 원본ZIP 읽기·디코딩·전처리·GPU 동기화 포함 추론·지도CPU전송·Q90 사진 점수 집계를 포함합니다.
모델 로드·출력 파일 저장·HTTP·대기열은 제외합니다. 모델 로드·첫 정상사진 시간과성공한 gate/cache/computed JSON 저장 시간은 별도 기록합니다.
마지막 비용 영수증·결과 게시·ZIP 압축·입력 해시·오프라인 대기는 총 계산 예산에서도 제외합니다.
부분 실패한 파일 쓰기 시간은 개별 분리하지 못할 수 있지만 시도 총 시간에는 포함됩니다.

**C단계의 첫 시도7.715GiB 예약 메모리 초과는 그대로 남습니다.** D단계가 좋아도 과거 위반을 지우지 않습니다.
`D_passed`와 `C_resource_review_required`를 따로 표시하며 `overall_candidate_accepted=false`를 유지합니다.
학습→보정 전환의 메모리 안정화는 별도 과제입니다. 이 비교가 재학습이나 자원 제한 완화를 수행하지는 않습니다.
