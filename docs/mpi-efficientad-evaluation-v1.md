# EfficientAD 고정 모델 검증 실행

2026-10-04. 사용자는 기존 모델 비교의 노션 기록과 고정12장→전체 비교→비용·안정성 검증을 요청했다.
**70,000회 모델을 재학습하지 않고, 저장된 보정 계약 그대로 검사한다.** 이 문서는 실행 전 계획이다.
실제 GPU 성능은 연구실 결과를 받아야 확인할 수 있으며 모든 평가 사진은 관찰된 탐색·회귀 자료다.

## 복구 이미지 읽기 오류 수정

첫 실행은 고정12장 중 다섯 번째인0054의 승인된 복구 이미지가 아직 로드되지 않아 중단됐다.
복구 타일을12장 밖으로 잘못 판단한 실행기 오류이며 학습 실패나 CUDA 메모리 문제가 아니다.
수정본은 정상8장 재현 후,0054가 실제 검사될 때 기존 복구 파일의 바이트·RGB 해시를 검증해 읽는다.
새 이미지 복구나 다운로드, 표본 교체, 학습·보정 변경은 하지 않는다.

수정 평가는 `mpi-efficientad-evaluation-v2`에 별도 저장한다. 기존v1 폴더·ZIP·학습 산출물은 유지한다.
v1의 코드 지문·모델·계약·첫4장 캐시·종료 기록을 검사해 보고된 buffer 오류1회와 일치할 때만 재시작한다.
기존 예측을 재사용하지 않고 동일12장부터 다시 계산하며, 실패 시도 시간도4시간 누적 한도에 포함한다.
다른 오류·미완료 종료·여러 시도·변조가 발견되면 자동으로 우회하지 않는다. 이때 오류를 다시 전달한다.

## 질문과 비교 대상

기존 MPI PatchCore + top1% + Q90은 불량53/55, 정상 오경보3/54·14/256이다.
EfficientAD는 정상 특징 저장소 검색 대신 teacher/student/autoencoder의 특징 차이를 사용한다.
제품 정상64사진×12영역은 유지했지만 모델 계열·보조 Imagenette·지도 보정이 바뀌었으므로
개별 요소의 인과 효과를 분리한 실험은 아니다. 서비스 transistor 모델과도 별개다.

## 한 명령의 진행 순서

1. **실물 연결 검증:** 수령 fit ZIP의 고정 SHA256, 최종 checkpoint·297개 정상 지도 실물,
   보정 계약·receipt·과거 실행 코드·MPI archive를 확인한다. 새 실행기 추가로 과거 학습 identity를
   다시 만들지 않는다. 새 파일을 포함한 평가 identity는 별도로 잠근다.
2. **재현 확인:** 최종 모델을 추론 전용으로 로드해 고정 보정 정상8사진의 지도·점수를 재현한다.
   절대 차이≤0.0001, 판정 변화0을 요구한다. 실패하면 불량 사진을 열지 않는다.
3. **고정12장:** 기존 최근접3 검사와 동일한12장, 순서까지 고정한다. 12/12가 아니면
   정상적으로 종료해 결과 ZIP을 내보낸다. 나머지 불량·정상 시험·속도·안정성은 실행하지 않는다.
4. **전체 관찰 비교:** 통과 시 불량55+정상54, 추가 정상256사진을 계산한다. 앞서 계산한12장은
   재사용한다. 기존53개 검출 모두 유지, TP≥53, FP54≤2, FP256≤12를 요구한다.
   미탐 감소 주장은 기존 미탐0019·0024 중 하나 이상을 추가 검출했을 때만 한다.
5. **반복 속도:** 12장 통과 시 전체 성적의 통과 여부와 무관하게 양쪽 속도를 측정한다.
   기존 모델과 후보를 차례로 로드하고 같은 보정 정상 앞20사진을 사용한다. 앞5사진 예열 후
   20사진×3회=60회 측정, higher p95≤2초를 후보 기준으로 적용한다. baseline warm은 비교 자료다.
6. **정상 보정 민감도:** 전체 정확도와 후보 속도 기준까지 통과했을 때만600회 재표집한다.
   미통과이면 명시적으로 생략한다. 학습·주평가 임곗값은 바꾸지 않는다.

고정12장: `0006,0025,0048,0000,0054,0051,0013,0033,0038,0001,0034,0042` (모두 defect).
원시 ST/AE 지도는 2×256×256 float32로 저장하고, 정규화 과정의 음수를 자르지 않는다.
상위656픽셀 평균→정상128사진 영역 Q90 보정→12영역 최대→정상169사진 Q95 경고 구조를 유지한다.
원본·마스크·모델은 수정하지 않으며 mask는 읽지 않는다. 이미 승인·기록된0054 타일 복구본만 사용한다.

## 시간과 자원 및 재개

- 시작 여유 디스크12GiB·GPU6GiB. 기존 학습 폴더·teacher/보조 자료를 삭제할 필요가 없다.
- 누적 계산4시간, RSS20GiB·PyTorch reserved6GiB 상한. 연산 경계에서 확인하므로 한 연산이
  끝나기 전 강제 중단을 보장하는 하드 실시간 제한은 아니다.
- 원본 입력 해싱·결과 내보내기는 계산 시간에서 제외한다. 실제 학습이나 다운로드는 없다.
- 속도 범위는 ZIP읽기·무결성검사·디코딩·전처리·추론·지도전송·점수 계산이다. 모델로딩·결과저장·
  DB/UI를 포함하는 서비스 응답시간은 아니다. 서로 다른 시간 범위를 혼합해 배수 개선을 주장하지 않는다.
- 사진별 지도와 결과, 완료한 속도 단계·재표집 회차를 원자적으로 저장한다. Ctrl+C는 같은 명령으로
  완료 지점부터 재개한다. 강제 종료·오류·OOM·상한 초과는 재실행 전에 검토하며 파일을 지우지 않는다.
- 중단된 부분 작업의 시간도 누적한다. 완료한 실행을 다시 호출하면 검증 후 같은 JSON ZIP을 재사용한다.

## 보정 민감도 상세

정상128만 / 정상169만 / 둘 다를 사진 단위로 재표집한다. 각200회, PCG64 seed는
20261004/20261005/20261006이다. 같은 인덱스를 PatchCore 기준선과 EfficientAD에 적용한다.
EfficientAD는 **ST/AE 지도 분위수→두 지도 합성→상위656픽셀→영역 Q90→사진 Q95를 전부 재계산**한다.
calibration-only에서는 개발 자료가 그대로이므로 지도 분위수와 개발 점수를 정확히 재사용할 수 있다.
지도 분위수는 모든 픽셀의 linear 분위수이며 무작위 축소나 근사치로 바꾸지 않는다.

기준: TP2.5%분위수≥50, TP95%구간 폭≤동일 표본 기준선 폭+0.5,
FP54의97.5%분위수≤5, FP256의97.5%분위수≤25, 무효 반복0. 무효 재표집을 새 표본으로 대체하지 않는다.
성적 구간은 관찰자료에서 정상 보정의 민감도를 나타내며 모집단 일반화 신뢰구간이 아니다.
600회 전체 지도 재집계는 오래 걸릴 수 있다. 소요시간을 보장하지 않으며4시간을 넘으면 검토용으로 중단한다.

## 연구실 명령

다른 GPU 작업을 정상 종료하고 아래 명령을 실행한다. 모델 학습 명령을 다시 실행하지 않는다.

```powershell
Set-Location 'C:\개인 프로젝트\defectops'
git pull --ff-only
if ($LASTEXITCODE -ne 0) { throw 'Git update failed; stop here.' }
powershell.exe -NoProfile -ExecutionPolicy Bypass -File '.\scripts\run_mpi_efficientad_evaluation.ps1'
```

기본 원본은 `Downloads\extracted.zip`. 다른 위치면 실행기에 `-Archive '전체 경로'`를 추가한다.
기존 `artifacts\mpi-efficientad-fit-v1`의 모델·지도와 `artifacts\handoff`의 기존 전달 ZIP들이 필요하다.
추가 다운로드·패키지 업데이트는 하지 않는다. fit ZIP은 검토한 다음 해시 그대로여야 한다.
`2a60c4f4818a4c7927ff8ac7fed3d28b5bc9e163f3e878bb1e77a1e6f8d0e5a0`.

성능 기준을 실패하더라도 정상 종료했다면 아래 파일을 보낸다.

```text
C:\개인 프로젝트\defectops\artifacts\handoff\mpi-efficientad-evaluation-v2.zip
```

실행 오류라면 ZIP이 없을 수 있다. 폴더를 보존하고 오류를 보낸다. 정확도 실패와 실행 오류를 구분한다.
이 ZIP에는 JSON만 포함하며 가중치·이미지·원시 지도는 연구실에 보관한다.

## 검증 범위

Mac 테스트는 CPU 대역 런타임으로 gate 순서, 부호 있는 점수, 원자적 저장·재개·변조 거부,
paired 재표집과 수학을 확인한다. 실제 CUDA 속도·불량 성적을 검증한 것은 아니다.
후보가 통과하더라도 서비스 자동 교체나 자동 PASS는 하지 않는다.
