# MPI 정상 다양성 후보 학습과 정상 보정 실행

2026-10-02. 선정 결과 검토 후 사용자가 C단계 진행에 동의하여 실행기를 준비했습니다.
**새 모델의 학습·보정·재로드 확인까지만 실행하며 불량 시험이나 서비스 교체는 하지 않습니다.**
후속 [Windows 실행 결과 수령 검토](../reports/mpi-normal-diversity-fit-v1-received-review.md)를 완료했습니다.
학습·보정·재현 검증은 완료했으나 첫 시도의GPU예약7GiB 초과는 유지하며 자원 전체 통과로 보지 않습니다.
아래는 실행 절차 보존본입니다. 이미 완료한 실행을 다시 돌릴 필요는 없습니다.

## 이번에 확인하는 질문

기존과 같은 수의 정상 사진을 더 다양한 구성으로 바꾸었을 때 사용할 새 정상 기준표를 만듭니다.
선정 명단은 이미 잠겼으므로 다시 뽑지 않습니다. 이번 완료만으로 불량 검출 개선을 주장하지 않습니다.

| 자료 | 수량 | 이번 역할 |
| --- | ---: | --- |
| 잠근 새 학습 정상 | 원본64장 ×12영역 =768타일 | 정상 패치 기준표 생성 |
| 별도 개발 정상 | 원본128장 ×12영역 | 영역별 정상 점수의 중앙값과 Q90 폭 계산 |
| 별도 보정 정상 | 원본169장 ×12영역 | 사진 단위 경고 기준 결정 |
| 저장 후 재확인 | 위128+169=297장 | 저장 전후 점수와 판정이 같은지 검사 |
| 관찰 시험109장·검증 정상256장 | 이번 계산0장 | 다음 D단계 비교에만 사용 |

개발128장과 보정169장은 학습64장과 ID·정확한 RGB가 겹치지 않습니다.
검증256장도 이미 선정 후보 풀에서 제외됐습니다. 이 분리는 실물 기판이나 촬영 세션의 독립성을 보장하지는 않습니다.

## 어떻게 학습하는가

PatchCore의 이번 학습은 신경망 가중치를 역전파로 바꾸는 방식이 아닙니다.
기존 모델 파일의 동결된 특징 추출기 가중치를 그대로 읽고 정상768타일에서 패치를 추출합니다.
가중치는 로딩 직후 텐서 단위로 일치하는지 확인하며 새 인터넷 가중치를 다운로드하지 않습니다.

- 기존 WideResNet50_2의 layer1+layer2,256입력,768차원 특징,seed42를 유지합니다.
- 각 타일의64×64 특징 격자에서 기존 stride2 규칙으로1,024개 패치를 남깁니다.
- 총786,432개 패치에서 기존 Anomalib10% coreset 방식으로 **78,643×768 기준표**를 만듭니다.
- 특징 추출·stride·coreset 본체는 기존 학습 코드를 재사용합니다. 바뀌는 요인은 정상64장의 구성입니다.
- coreset은25회 반복마다 자원 예산을 확인합니다. 패치 수·장수·bank 크기를 자동 축소하지 않습니다.

## 경고 기준과 저장 검증

타일 점수는256×256 이상 지도에서 상위656픽셀 평균입니다.
개발 정상128장으로 각 영역의 중앙값과 `Q90(higher)−중앙값`을 계산합니다.
이 폭이1e-6 이하거나 유효하지 않으면 대체 공식을 쓰지 않고 중단합니다.

각 사진의12개 영역 점수를 위 척도로 정규화하고 최댓값을 사진 점수로 씁니다.
보정 정상169장의 사진 점수에서95% higher 분위수를 경고 기준으로 정합니다. 기준 이상(`>=`)이면 경고입니다.
이 보정 집합의 경고 빈도는 새로운 정상 데이터의 오경보 성능이 아닙니다.

그다음 모델을 메모리에서 해제하고 **저장한 파일을 다시 읽어** 정상297장을 재계산합니다.
타일 top1% 점수와 원시 이미지 점수 최대 절대차≤1e-4,최초에 잠근 척도·임곗값에서 판정 변화0을 요구합니다.
재로드 결과에 맞춰 임곗값을 다시 계산하지 않습니다. 같은 프로세스 안에서 새 모델 객체를 로드하며,
독립 프로세스 warm 성능 측정은 다음 D단계 작업입니다.

## 자원 제한과 오류 대응

이번 C단계 누적 계산 예산은 **4시간,PyTorch GPU 예약7GiB,RAM RSS20GiB**입니다.
기존 같은 크기 bank 학습의 GPU 예약 peak가 약6.514GiB였으므로 선정 단계의0.330GiB와 혼동하면 안 됩니다.
이전 선정98.854초는 이번 학습의 예상 시간이 아닙니다. 대표 패치 선정 중 진행 표시가 느릴 수 있습니다.

RSS와GPU 전체 점유를100ms 주기로 표본 측정하고,PyTorch allocator peak를 처리 경계에서 검사합니다.
이는 연산 도중 상한 초과를 항상 미리 막는 hard limit가 아닙니다. OOM과예산 초과도 실패 기록으로 남깁니다.
누적 시간은 실패·중단 시도를 포함한 runtime생성부터해제까지이며,입력 해시·내보내기·오프라인 대기는 제외합니다.
ZIP에는 성공 시도까지 포함한 시간 영수증이 들어갑니다. 과거 실패 비용은 성공 재실행으로 지우지 않습니다.
실패/필수 메모리 측정 누락 이력이 있으면 `resource_review_required`를 남기므로 최종 비용 통과와 혼동하지 않습니다.

완료된 모델 및 사진별 점수는 계약·파일 해시·환경 일치 시 재사용합니다.
일반 오류나Ctrl+C 후 같은 명령을 사용할 수 있지만,원인을 먼저 공유해 주십시오.
전원 종료나강제종료로 종료시간 기록이 없으면 예산을0으로 초기화하지 않고 검토를 요청합니다.
오류 때 기존 결과 폴더를 삭제하거나 학습/선정 설정을 바꾸지 마십시오.
