# EfficientAD 정식 학습과 정상 보정

2026-10-04. 사용자가 정식 학습 진행과 연구실 실행 명령을 요청했다.
**이번 명령은70,000회 학습, 정상128/169사진 보정, 최종 모델 재로딩 검증까지 수행한다.**
불량 평가·서비스 교체·자동 PASS는 하지 않는다. 사전 점검 성공과 실제 검출 성능을 구분한다.

## 왜 길게 학습하는가

100회 사전 점검은 자원과 저장 복원을 확인하기 위한 것이었다. 정식 학습에서는 teacher가
알려주는 정상 특징을 student와 autoencoder가 여러 번 학습한다. PatchCore처럼 대표 패치를
모으는 방식이 아니므로 충분한 신경망 업데이트를 수행한 뒤 비교해야 한다.

70,000회는 [공식 저자 구현의 기본 학습 횟수](https://github.com/nelson1425/EfficientAD/blob/main/efficientad.py)를
참고한 고정 출발점이지 MPI에서 최적인 횟수라는 뜻은 아니다. batch1·768타일 기준 약91.15회
순회에 해당한다. 학습 후반95%에서 학습률을0.1배로 낮추는 방식은
[Anomalib2.2.0 구현](https://github.com/open-edge-platform/anomalib/blob/v2.2.0/src/anomalib/models/image/efficient_ad/lightning_model.py)과 맞춘다.
공식 예제의 중간 test 평가는 가져오지 않는다. 이번 모델은 마지막70,000회 checkpoint 하나로 고정하며
불량 성적이 가장 좋은 중간 모델을 고르거나 학습을 자동 연장하지 않는다.

## 데이터와 학습 일정

| 항목 | 고정 조건 |
| --- | --- |
| 제품 학습 자료 | 기존 정상64사진×12영역=768타일, 원래 명단 유지 |
| teacher 통계 | 전체768타일에서 새로 계산, 점검8사진 통계 재사용 금지 |
| 모델 | EfficientAD-S,384채널,256×256,한 모델이12영역 공동 학습 |
| 초기값 | seed42로 새 student·autoencoder, 고정 공식 teacher. 점검 checkpoint 재사용 금지 |
| 업데이트 | 70,000회, batch1, Adam, weight_decay0.00001 |
| 학습률 | 1~66,500회0.0001,66,501~70,000회0.00001 |
| 입력 순서 | seed42·역할·epoch·행번호 해시 정렬. 매 순회 각 타일을 한 번씩 사용 |
| 보조 이미지 | 이미 받은 Imagenette의 train9,469장 전체. val은 사용하지 않음 |
| 저장 | 0회와 매1,000회, 모델·optimizer·난수·손실·고정 정상12영역 지도 |
| 모니터 표본 | 첫 학습 사진의12영역. checkpoint마다 같은 raw ST/AE 지도를 기록 |
| 자동 중단 | 비유한 손실·gradient·가중치, 자원 초과, 입력·저장 검증 오류 |

보조 이미지96장만 반복한 짧은 probe와 달리 정식 학습은 다운로드된 train 전체를 사용한다.
새 데이터셋을 추가 다운로드하는 것이 아니라 같은 공식 archive에서 train만 검증·준비한다.
MPI 제품 학습 자료는64장으로 유지한다. 제품·보조 이미지 순서는 독립적으로 고정한다.
제품은 원본 RGB256×256에서 ToTensor만 적용하고 모델 내부 정규화와 중복하지 않는다.
보조 이미지 변환과 모델 내부 증강은 앞서 검증한 Anomalib 경로를 사용한다.

## 정상 자료로 경고 기준 만들기

학습 완료 후 별도 정상128사진과169사진의 ST·AE 원시 지도 두 장을 각각 로컬에 보관한다.
이는 후속 보정 민감도 검사를 위한 자료이며 전달 ZIP에는 이미지·지도·가중치를 넣지 않는다.

1. 정상128사진의 모든 지도 픽셀에서 경로별90%·99.5% 분위수를 정확하게 계산한다.
   GPU 전체 지도 누적·무작위 픽셀 축소 대신 CPU에서 한 경로씩 처리한다.
2. 각 경로를 `0.1 × (원점수−Q90)/(Q99.5−Q90)`으로 보정하고 두 지도를 절반씩 합친다.
   이 과정에서 발생하는 음수는 정상적인 보정 결과다. 임의로0에 자르지 않는다.
3. 영역별 가장 높은656픽셀의 평균을 구하고, 같은128사진으로 영역별 중앙값·Q90 폭을 계산한다.
   128사진을 지도와 영역 보정에 함께 사용하므로 독립 검증 자료라고 부르지 않는다.
4. 정상169사진에서12영역 중 가장 큰 표준화 점수를 사진 점수로 삼고,95% 분위수(higher)를 경고 기준으로 정한다.
5. 최종 모델을 다시 불러와297사진 전체 원시 지도·보정 점수·판정을 비교한다.
   허용 절대 오차0.0001 이하, 판정 변화0이며 경고 기준을 다시 맞추지 않는다.

폭이0.000001 이하인 지도·영역 보정은 중단한다. 다른 공식으로 바꾸거나 불량 점수로 기준을 낮추지 않는다.
관련 모델 지도 공식은 [Anomalib2.2.0 모델 코드](https://github.com/open-edge-platform/anomalib/blob/v2.2.0/src/anomalib/models/image/efficient_ad/torch_model.py)를 따른다.
정상 학습 한 번의 성능 우연성이나 일반화까지 이 명령이 검증하는 것은 아니다.

모델 checkpoint는 두 원시 지도를 출력하고, 지도·영역·사진 보정은 별도
`calibrated/value.json`에 고정한다. 후속 검사는 반드시 이 둘을 함께 사용한다.
checkpoint만 일반 EfficientAD 서비스에 연결하면 이번 보정·판정 계약을 재현한 것이 아니다.

## 시간과 메모리

사전 점검11.83초/100회를 단순 환산하면 약2.3시간이다. 실제로는 저장 주기, 전체 보조 자료,
teacher 통계·정상 보정·재로딩 비용이 달라질 수 있으므로 **2~3시간 수준은 예상일 뿐 보장이 아니다.**
누적 계산 상한은4시간이며 초과하면 멈추고 기록을 보존한다. 자료 준비·해시 검사 시간은 별도다.
한 CUDA·CPU 연산 도중 강제 종료하는 하드 실시간 제한이 아니라 연산 경계에서 확인한다.

- GPU 시작 여유6GiB, PyTorch reserved peak6GiB 이하, 프로세스 RSS peak20GiB 이하.
- 디스크 시작 여유30GiB 필요. 저장점·원시 지도·보조 자료를 자동 삭제하지 않는다.
- RSS·장치 전체 GPU는100ms 표본과 경계 측정, PyTorch는 allocator peak로 기록한다.
- 중단 시 소모한 연산도 누적한다. 완료70,000회 외 재실행 여유는2,000회로 제한하며 총시도72,000회 또는4시간을 넘기지 않는다.

## 연구실 실행 명령

다른 GPU 학습과 검사 서버는 정상 종료하고, PC가 절전 상태에 들어가지 않게 준비한다.
GPU 프로세스 종료나 시스템 설정 변경은 스크립트가 대신 수행하지 않는다.

```powershell
Set-Location 'C:\개인 프로젝트\defectops'
git pull --ff-only
if ($LASTEXITCODE -ne 0) { throw 'Git update failed; stop here.' }
powershell.exe -NoProfile -ExecutionPolicy Bypass -File '.\scripts\run_mpi_efficientad_fit.ps1'
```

필요 파일은 기존 `Downloads\extracted.zip`과 프로젝트의 다음 파일이다.

- `artifacts\handoff\mpi-pcb-normal-bank-preparation-v1.zip`
- `artifacts\handoff\mpi-pcb-score-probe-v1.zip`
- `artifacts\handoff\mpi-efficientad-probe-v1.zip`
- 사전 점검 때 받은 `artifacts\research-assets\efficientad-v1`의 공식 teacher·Imagenette archive.

기존 torch·anomalib 등 환경을 업데이트하지 않는다. 사전 점검의 환경·설치 모델 소스 지문과 일치해야 시작한다.
원본 archive 경로가 다르면 `-Archive '실제 전체 경로'`를 PowerShell 실행기 뒤에 붙인다.

결과는 별도 `artifacts\mpi-efficientad-fit-v1`에 저장된다. 완료 후 아래 ZIP만 전달한다.

```text
C:\개인 프로젝트\defectops\artifacts\handoff\mpi-efficientad-fit-v1.zip
```

## 중단과 다음 단계

Ctrl+C로 정상 중단하면 같은 실행 명령으로 마지막1,000회 저장점부터 재개한다.
저장 후 소모한 업데이트도 시도 예산에 포함되므로 재개 횟수는 무제한이 아니다.
강제 종료·OOM·자원 초과·파일 손상·환경 변경은 자동 재개하지 않는다. 파일을 지우지 말고 오류를 전달한다.
실행 중 코드 업데이트·패키지 변경을 하지 않는다. 소스나 입력이 달라진 결과를 한 실행으로 섞지 않는다.
완료 후 동일 명령은 검증된 결과를 재사용하며 재학습하지 않는다.

이번 ZIP 검토 뒤 기존 검출12장 회귀검사를 먼저 진행한다. 명단은 기존 최근접3 검사와 동일하게
실행 정책에 고정했다. 한 장이라도 놓치면 자동 전체 비교를 하지 않는다.
전체 비교에서는 기존53장 검출 보존, 정상 오경보≤2/54·≤12/256을 요구한다. 미탐 개선 주장은
기존 미탐0019·0024 중 적어도 하나의 추가 검출을 요구한다. 서비스 자동 채택은 없다.

후속 보정 민감도 조건도 지금 고정했다. 정상 사진 단위로 development만/calibration만/둘 다
재표집하고, EfficientAD 지도 분위수부터 영역 Q90·사진 임곗값까지 모두 다시 산출한다.
각범위200회(총600회), PCG64 seed20261004/20261005/20261006, 기준선과 동일 표본 인덱스를 사용한다.
전체 지도 재계산 비용 때문에 기존3,000회보다 적은 탐색 검사이며 기존결과의 분위수와 그대로 비교하지 않는다.
동일600회로 기준선을 다시 계산한다. 불량 TP2.5%분위수≥50, TP구간 폭≤기준선 폭+0.5,
정상FP97.5%분위수≤5/54·≤25/256, 무효 반복0을 기준으로 한다. 별도 후속 계산 상한4시간이다.
실행 전 정책 고정일 뿐 이번 명령에는 bootstrap·불량 평가 코드가 없다. 이미 관찰한 시험이므로 독립 성능 주장을 하지 않는다.

## 검증 범위

로컬 테스트는 CPU 대역 런타임으로 학습 순서·저장·재개·위변조 거부·정상 보정 수학·전달 ZIP을 검사한다.
실제70,000회 CUDA 학습은 연구실 실행 전이며 CPU 테스트 통과를 실제 학습 성공으로 표현하지 않는다.
공식 보조 이미지·가중치와 MPI 자료는 연구실 로컬에서만 사용하고 Git·노션·전달 ZIP에 재배포하지 않는다.
