# VisA PCB3 정상 기준표 v2 오류 사진 검토

## 왜 하는가

동일한 PCB3 시험 201장에서 v2는 불량 100장 중 91장을 검토 대상으로 보냈지만
9장을 놓쳤고, 정상 101장 중 6장을 잘못 검토 대상으로 보냈다. 숫자만으로는
모델이 실제 결함 부위를 보고 반응했는지 알 수 없다. **미탐 9장과 정상 오검출
6장 전부**의 원본·정답 마스크·기존 이상 지도·v2 이상 지도를 나란히 보고,
특히 기존 모델은 잡았으나 v2가 놓친 3장(`040.JPG`, `042.JPG`, `068.JPG`)을
확인한다. 이미지 식별자는 공식 PCB3 불량 디렉터리 기준이다.

이는 이미 여러 번 관찰한 시험 집합의 **사후 탐색**이다. 사진을 보고 임곗값을
바꾸거나, 15장의 패턴을 성능 보증·자동 PASS·현장 판정에 사용하지 않는다.

## 무슨 자료를 만드는가

연구실 컴퓨터에 남은 이전 평가와 v2 평가의 저장된 이상 지도를 읽는다.
모델을 다시 불러와 추론하거나 학습하지 않는다. 원본 VisA tar와 이전 시험 감사
기록의 이미지·마스크 SHA-256, 두 평가 ZIP과 사진별 저장 지도 SHA-256을
확인한다. 오류 15장 중 하나라도 누락되거나 파일이 바뀌면 중단한다.

- `contact-missed.jpg`: 미탐 9장을 세로로 모은 검토 시트.
- `contact-false-positives.jpg`: 정상 오검출 6장을 모은 검토 시트.
- `case-*.jpg`: 각 사진의 확대 카드. 왼쪽부터 256px 원본과 초록색 정답
  윤곽, 기존 지도, v2 지도, 원본 해상도의 결함 부근 확대 영역(정상은 v2
  지도 최고점 부근)이다.
- `selection.jsonl`와 `summary.json`: 사진 ID, 기존·v2 점수/판정,
  오류 유형, 변경 금지 상태와 출처를 기록한다.

초록색은 **공식 정답 위치**이지 모델의 판정이 아니다. 지도 색은 각 모델의
서로 다른 정상 보정 픽셀 임곗값으로 표시하므로 두 지도의 빨강 정도를
숫자처럼 직접 비교하면 안 된다. 빨간 위치도 실제 물리 결함의 증거는 아니다.

## 연구실 Windows에서 할 일

기존 평가의 `samples` 폴더 두 곳, 두 평가 handoff ZIP, v2 fit handoff ZIP,
`Downloads\VisA_20220922.tar`를 보존한다. 다음 명령만 실행한다.

```powershell
Set-Location "C:\개인 프로젝트\defectops"
git pull --ff-only
powershell.exe -NoProfile -ExecutionPolicy Bypass `
    -File ".\scripts\run_visa_pcb_normal_bank_visual_diagnostics.ps1"
```

완료 후 `artifacts\handoff\visa-pcb-normal-bank-pcb3-errors-v1.zip`을 이
Codex 작업에 첨부한다. 원본 사진이 포함된 파생 자료이므로 외부 공개 저장소에는
올리지 않는다. ZIP이 이미 있거나 필요한 저장 지도가 없다는 오류가 나면
기존 파일을 삭제하지 말고 메시지를 그대로 보내 준다.

## 검토 뒤 판단

사진별로 (1) 정답 위치가 원본에서 보이는지, (2) v2 이상 지도가 그 부위에
집중되는지, (3) 기존 모델과 위치 반응이 어떻게 다른지, (4) 영상 자체나
마스크 품질의 문제인지 기록한다. 시각적 관찰은 가설을 만드는 용도다.
새로운 방법을 적용하려면 별도 사전 계획과 **새 미관측 시험 데이터**가 필요하다.
VisA 원본 출처는 Amazon Science의 VisA visual anomaly dataset, CC BY 4.0이다.
