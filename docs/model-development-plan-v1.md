## 1. 현재 계획에 대한 판단

**개별 실험 계획은 상당히 잘 설계됐지만, 전체 모델 개발 계획으로는 불완전하다.**
데이터 분리·체크섬·재현성·실험 전 규칙·실패 보존은 유지한다. 다만 원인 진단 후 다음 실험을
계속 추가하는 흐름을, 사용 목적과 성공 기준을 통과하는 단계별 개발 흐름으로 바꿔야 한다.
처음부터 다시 학습하는 것이 아니라 지금까지 확보한 증거를 새 단계에 배치한다.

| 점검 항목 | 현재 근거 | 보완 |
| --- | --- | --- |
| 데이터·실행 재현 | manifest, hash, 고정 split, 정상 보정, reload, 중단·재개 구현 | 유지. 코드 테스트와 실제 GPU·현장 검증을 분리 |
| 모델 비교 | PaDiM/PatchCore·여러 품목·seed·후보 실패 기록 | 품목별 기준선과 채택 상태를 한곳에서 관리 |
| 사용 목적 | 초기3품목 MVP, 이후transistor 서비스, 최근MPI 연구가 병존 | 모델 연구와 서비스 개발을 별도 트랙으로 명시 |
| 성공 기준 | 연구별95%/5%, 다른 연구10% 오경보, 지연은 때로 동률 기준 | 새 사이클 시작 전에 정확도·비용을 동시에 필수 조건으로 고정 |
| 종료·재개 | 원인 가설이 생기면 연구 재개 가능 | 진단1회·제한 후보·예산·통과 실패 처리까지 명시 |
| 독립 평가 | 과거Real-IAD development/final 분리는 있었음 | 이미 본MPI·후속final을 새 holdout으로 재사용 금지; 새 자료 경로는 미확보 |
| 정상 보정 안정성 | 정상256장 고정 평가 완료, 이전 재표집 민감성은 큼 | 재현성0오차와 표본구성 안정성을 별도 gate로 확인 |
| 문서 최신성 | 연결표가A33/55에 머물고 일부 과거 계획은 실행 대기 표기 | 최신 상태와 과거 실행 당시 상태 분리 |

근거: [초기 검토](plan-review.md), [서비스 로드맵](v1-completion-roadmap.md),
[Real-IAD 선택/비용](../reports/realiad-followup-development-selection-v1.md),
[보정 민감도 분석](../reports/performance-improvement-review-2026-09-29.md),

## 2. 목표와 범위

### 모델 연구 트랙 — 현재 진행 방향: MPI-PCB 우선

> 지정 품목의 정상 기준을 만들고, 정해진 정상 오경보 예산과 장비 비용 안에서 불량 미탐을 줄이며,
> 어떤 조건에서 실패하는지 설명 가능한 이상탐지 파이프라인을 만든다.

- 첫 대상: 현재 사용 중인MPI-PCB 데이터 조건. 다른 기판 전반의 공통 모델이라는 주장을 하지 않는다.
- 판단 단위: 원본사진1장 = 12영역. 12타일을 독립 기판12장으로 계산하지 않는다.
- 출력: 이상 점수·경고 여부·참고 이상 위치·모델/보정 버전·실패 이유.
- 초기 용도: 사람 검토 보조. 기준 미만도 자동 합격/폐기/설비 조치로 연결하지 않는다.
- 정상만으로 학습하는 PatchCore를 기준선으로 유지한다. 불량 지도학습 도입에는 별도 목표·분할·승인이 필요하다.
- 직접 촬영은 사용자 제약상 계획의 필수 과제로 배정하지 않는다. 공개 자료의 미관찰 범위를 검토하되
  자료가 없으면 독립검증 미완료로 남기고 임의로 확보됐다고 하지 않는다.

### 서비스 트랙 — 기존 별도 계획 유지

MVTec transistor seed42 PatchCore의 검사→검토→모의SOP→승인→모의티켓을 연결한다.
MPI 연구의 추가 성능 개선은 이 통합의 선행 조건이 아니다. 반대로UI 완성도는 모델 정확도 근거가 아니다.
다품목 등록·모델 교체가 준비되지 않은 서비스에MPI checkpoint를 자동으로 넣지 않는다.

### 여기서 말하는 모델의 구성

이미지/품목 계약 → 전처리·타일 규칙 → 특징 추출기 → 정상bank → 검색·이상 지도 →
영역 점수 → 정상 분포 보정 → 사진 집계 → 경고 기준까지 **전체를 하나의 버전**으로 본다.
checkpoint가 같아도 점수 함수·보정·threshold가 바뀌면 다른 판정 파이프라인이다.
픽셀 정답은 평가·진단용이며 실제 추론 점수 계산에 넣지 않는다.

## 3. 기준선과 데이터 역할 고정

현재 MPI 기준선은 Wide ResNet-50-2의 고정 layer1+layer2, 256×256 입력, 학습 패치 stride2,
정상64장, 12영역 공용 bank78,643×768이다. 기존 설정은
[normal-bank config](../configs/mpi-pcb-normal-bank-pilot-v1.toml)에 고정돼 있다.

현재 비교 기준 점수는 **top1%(656픽셀) 평균 + 영역별 median/Q90 간격 + 사진12영역 최대 +
별도 정상169장의95% higher 기준2.3169610768645974**다.
Q90의90%는 영역 척도용이며, 사진 경고 기준의95%와 다른 개념이다.

| 데이터 | 현재 역할 | 현재 할 수 없는 주장 |

| MPI 정상64장 ×12영역 | 정상 bank 구축 | 768개의 독립 제품 학습 |

| 기존 시험109장: 불량55+정상54 | 이미 관찰된 개발·회귀·원인 분석 | 새 독립 성능 |

## 4. 수용 기준 — 초기 연구 목표와 미확정 세부 조건

아래 값은 기존 관측치를 합격으로 만들기 위한 사후 기준이 아니라 향후 모델 선택의 작업 기준이다.
검출95%·오경보5%·사진 warm p95 2초를 초기 연구 목표로 진행하며, 나머지 세부 값은 새 후보
실행 전 확인할 제안이다. 현장 비용·검토량이 확인되지 않았으므로 생산 기준으로 쓰지 않는다.

| 구분 | 제안 기준 | 해석/실패 처리 |
| --- | --- | --- |
| 사진 불량 검출 | recall≥95% / 미탐≤5% | 새로운 고정 평가에서 관측 목표. 분모·불확실성 함께 보고 |
| 정상 오경보 | FPR≤5% | 정상 검토 부담의 대리지표. 정상 보정95%와 별개 |
| 주요 결함군 | 사전 등록한 각 군의 분모·미탐 별도 보고, 숨은 악화 검토 | 유형·중요도·최소 표본 미정이면 승인 불가. 현재6사례로 유형 목표를 만들지 않음 |
| 추론 비용 | RTX5060, 원본사진12영역, batch1 warm p95≤2초 | 임시연구한도. 읽기→전처리→추론→점수 포함; 서비스전체시간 아님 |
| 메모리 | 추론 PyTorch reserved peak≤6GiB, 프로세스 RSS peak≤20GiB | 8GB/32GB 장비용 제안. 다른 GPU 점유·여유 별도 확인, 순간값으로 통과 금지 |
| 학습 자원 | 작은 정상 자료로 특징 수·bank·시간/메모리 계획, 후보1개 fit+보정≤4시간 제안 | 학습 직후 보정5시간 이력 주의. 초과 예상이면 계획 재승인, 자동 축소 금지 |
| 재현 | 같은 고정 환경 reload 원점수 차이≤1e-4, 판정 변화0 | 다른 장비/변환에는 별도 허용오차 규칙 필요 |
| 입력 실패 | 실패를 성공/정상점수로 대체0건, 실패 건수·분모 전수 공개 | 깨진 파일을 삭제해 성적 개선 금지 |

기존 Q90은 관측 recall96.36%지만 정상3/54=5.56%,14/256=5.47%로 오경보 목표를 못 넘는다.
독립성·보정 안정성·전체 메모리도 미해결이므로 지금 사용 승인하지 않는다.
불량55장에서는1장이 약1.82%p, 정상54장에서는1장이 약1.85%p다. 작은 표본의 경계 통과를
확실한 품질 보장으로 표현하지 않는다.

표본 독립성이 성립하면 비율의95% 신뢰구간을 보고하고, 그룹 상관이 있으면 기판/세션 단위
추정을 계획한다. 그룹 정보가 없으면 독립성 한계를 표시한다. Phase5 전에는 표본 수·군별 최소 수·
허용 구간 폭을 정해야 한다. 점추정 목표와 신뢰구간까지 보장하는 주장은 분리한다.
자동 PASS를 위한 통계적 보증은 이번 범위 밖이다. 실제 불량 비율과 사람 검토 시간이 없으므로
시험 precision/경고 비율을 현장 작업량으로 옮기지 않는다.

### Phase3: 조건부 후보와 실험 한도

2026-10-01 업데이트: [MPI-C1-01](mpi-scale-shrinkage-v1.md)은 영역별 정상 변동 폭을 대표 폭과

### Phase4: 무엇이 안정적인지 따로 검증

- **수치 재현:** 같은 고정 모델의 재로딩·중단 후 재개 점수가 같은가. 기존에 확보한 강점이다.
- **학습 변동:** bank/특징 선택이 바뀌는 후보만 seed42/43/44로 반복하고 모든 값·최악값을 보고한다.
  같은 checkpoint의 후처리만 바꾸는 경우 불필요한3회 재학습을 하지 않는다.
- **보정 변동:** 기존 재표집1000회 결과부터 재사용한다. 새 방법은 실행 전 정한 재표집/그룹 분할로
  분위수·경고율·미탐 범위를 확인한다. 유리한 보정 분할이나 seed를 골라 사용하지 않는다.
- **후속 정상 자료:** 실제 미사용 정상이 있으면 먼저 중복·그룹 관계를 감사하고 고정 규칙으로 선정한다.
  기존256장을 다시 새 정상이라고 하지 않는다. 새 정상만으로 새 불량 검출을 검증하지 않는다.
- **운영 비용:** warmup·측정 수·반복 수·동기화·저장 범위를 실행 카드에 고정한다. cold/warm,
  특징 추출/검색/전송/저장 시간, PyTorch/전체 GPU 메모리, RSS peak/순간값을 구분한다.

재표집은 새 촬영 시험이 아니다. 보정 민감도의 허용 변동 폭을 Phase3 전에 고정하지 않으면
Phase4 통과를 선언하지 않는다. 시간·메모리가 기록되지 않았다면 미측정이지 통과가 아니다.

### Phase5: 직접 촬영 없이 가능한 검증과 한계

새 자료를 찾기 전에 다음 중 시험 질문을 고른다.

1. **동일 제품의 다른 조건 유지:** 같은 제품·독립 실물/세션인 공개 자료가 확인돼야 한다.
   없으면 이 주장은 미검증으로 남긴다.
2. **새 품목에도 학습 절차가 통하는가:** 미관찰 공개 품목의 정상으로 새 bank를 만들어 고정 레시피를
   평가한다. 기존 MPI checkpoint의 성능이나 같은 제품의 촬영 변동 검증이라고 하지 않는다.
3. **다른 제품으로 그대로 전이:** 기존 checkpoint와 대상 정상 보정만 쓰면 정상 보정 적응을 포함한
   스트레스 시험이다. 1·2번을 대체하지 않으며 새 bank 적합과 구분한다.

출처·라이선스·열람 이력·그룹 분리·라벨·실패 처리·필요 표본과 군별 최소 수·보정 범위를 검토한 뒤
정확히 하나의 평가 경로를 승인한다. 외부 품목의 정상으로 보정한다면 그것도 미리 명시한다.
최종 시험의 불량 정답은 후보/임곗값 결정에 쓰지 않는다. Final 개봉은 명시적 승인 후1회이며,
기술 오류 복구는 동일 잠금의 재개로 기록한다. 결과를 본 뒤 변경한 후보는 탐색으로 돌아간다.
기존 Real-IAD final은2026-09-23 평가 완료다. 새 후보의 미개봉 final로 사용하지 않는다.

자료가 없으면 **연구 정리 완료 / 독립 성능 미검증**으로 마감할 수 있다. 이때 완료된 것은 연구
산출물이지 미탐 목표 달성이나 생산용 모델 완성이 아니다. 기존 자료의 시연·회귀 시험은 계속 가능하다.

### Phase6: 모델 사용 승인과 시스템 연결

최종 산출물은 checkpoint뿐 아니라 품목ID·입력 조건·전처리·특징·bank 출처·점수/보정·threshold·
manifest/hash·환경·지표/분모/한계·비용·승인 상태·복구 대상을 포함한 model card/bundle이다.
품목이 맞는지 확인하지 못하면 잘못된 모델로 자동 진행하지 않는다. 모델 미준비·손상 입력은 실패로 남긴다.
기존 bundle의 `decision=PASS`는 모델 기준 미만 출력이며 `automatic_pass_allowed=false`다.
과거 JSON/평가를 소급 수정하지 않고 UI/연계 계층에서 모델 경고와 사람 검토 상태를 분리한다.
연구 후보→검증 후보→제한 시연 승인→사용 중→사용 중지의 상태와 전환 근거를 기록한다.
현재 이 모델 등록/다품목 승인 체계가 완성됐다는 뜻은 아니다.

## 6. 역할·일정·승인 관리

| 담당 | 역할 |
| --- | --- |
| Codex/맥북 | 근거 검토·계획/카드 작성·코드/CPU 시험·명령 준비·수령 검산·문서/노션 정리 |
| 사용자/연구실 Windows | GPU 작업 가능 시간 확인·실행·원본/모델 보관·결과 ZIP 전달 |
| 사용자 | 품목 우선순위·미탐/오경보 부담·비용 상한·새 자료/최종 시험/사용 승인 결정 |

일정은 주차 강제가 아니라 증거와 완료 조건을 기준으로 한다. Phase0–1 문서부터 정리하고,
이미 작성한 Phase2 진단의 실행을 확인한다. Phase3는 원인표·실험 카드 승인 뒤, Phase5는 독립 자료
확보 뒤 진행한다. 한 실험 사이클의 종료 보고 전에 새 데이터셋/모델 연구를 무제한 늘리지 않는다.

매 단계 보고 형식: **이번 질문 → 변경/고정 항목 → 자료 역할 → 결과/비용 → 통과·실패·미확정 → 다음 행동**.
실행 완료·검산 통과·성능 통과·사용 승인은 다른 상태다. 테스트 개수를 정확도의 증거로 사용하지 않는다.

### 승인 범위와 남은 미정 항목

사이클1의 두 개별 카드는 후속 사용자 동의로 실행했고 종료했다. 성적·민감도·자원 조건은
해당 실행에 고정 적용했다. 아래 미정 항목은 생산 사용 및 다음 사이클에 대한 것으로,
이미 완료한 실험의 기준이 없었다는 뜻이 아니다.

- [x] 첫 우선순위: MPI-PCB 미탐 연구, 서비스 완성은 별도 트랙으로 유지
- [ ] 제안한 관측 recall95%·오경보5%와 품목/결함군별 조건
- [ ] warm p95 2초·추론 reserved6GiB·RSS20GiB·fit+보정4시간 예산
- [x] 사이클1 최대2개 한도와 개별 카드 보정 민감도 조건 적용·결과 검산, 두 후보 비채택
- [ ] 독립 평가 질문·출처·표본 계획 (현재 미확보)

미정값은 검증 통과로 간주하지 않는다. 이 문서 작성은 새 학습·최종 시험 개봉·모델 교체 승인이 아니다.
