# MPI 패치 특징 정규화 비교 실험

2026-10-03. 기존 Q90 연구 기준선의 정상 오경보와 보정 불안정을 줄이기 위한
**새 특징 거리 비교 후보 한 개**다. 구현과 CPU 검증을 완료했으며, 실제 GPU 성능 결과는 아직 없다.
기존 서비스 모델을 바꾸거나 자동 합격을 허용하지 않는다.

## 이번에 바꾸는 것

기존 방식은 신경망이 만든 768개 숫자의 차이를 그대로 거리로 계산했다.
이번에는 각 패치 벡터를 그 벡터의 길이로 나눈다. 예를 들어 `[3,4]`와 `[6,8]`은
둘 다 `[0.6,0.8]`이 된다. 전체 반응 크기가 달라도 특징 비율이 같으면 비슷하게 본다.
실제 CNN 특징이 조명 변화에 이렇게 반응한다는 사실은 확인되지 않았다.

가설은 **특징의 크기 차이가 정상 외관 변화에 과민한 비교를 만들고 있을 수 있다**는 것이다.
반대로 불량이 주로 크기 변화로 표현된다면 미탐이 늘 수 있다. 개선을 전제하지 않는다.
이것은 사진의 최종 경고 점수 보정을 바꾸는 작업이 아니라,
최근접 정상 패치를 찾기 **전**의 특징 거리 정의를 바꾸는 실험이다.

| 항목 | 유지하거나 변경하는 내용 |
| --- | --- |
| CNN | 기존 wide_resnet50_2, layer1+layer2, 가중치 고정 |
| 입력 | 기존 256×256 전처리, 64×64 특징 격자 |
| 정상 기준표 | 기존 정상64장으로 만든 78,643×768 벡터의 행과 순서 유지 |
| 변경 | 기준표와 입력의 각 패치 벡터에 L2 정규화 적용 |
| 거리 | 정규화된 벡터끼리 기존 Euclidean 거리; 최근접 패치가 달라질 수 있음 |
| 이상 지도 | 기존 보간·평활화, 상위1% 656픽셀 평균 유지 |
| 보정 | 개발 정상128장의 영역별 median/Q90, 별도 정상169장의 사진 higher Q95 |
| 사진 판단 | 12영역 정규화 점수의 최댓값, 기존 >= 비교 유지 |

단위 벡터의 유클리드 거리 제곱은 `2-2*cosine`이다. 그러나 뒤에서 거리의 제곱근·
지도 평활화·상위픽셀 평균을 사용하므로 최종 점수가 cosine 평균과 같다는 뜻은 아니다.
Anomalib의 k=9 이미지 점수 계산도 같은 정규화 벡터를 받지만, 판단에는 기존처럼 지도 top1을 쓴다.
제로/비유한 벡터는 임의 보정하지 않고 오류로 중단한다.

기존 대표 벡터는 원래 거리로 선정된 것이다. **정규화 거리에 최적화된 새 coreset 학습**으로
설명하지 않는다. 이 제한을 감수하고 대표 선정을 다시 하지 않아 거리 변경의 영향을 먼저 확인한다.
성능 저하 시 모든 특징 정규화 방법이 실패했다고 일반화하지 않는다.

## 고정 실행 순서

1. 원본 압축파일·기존 checkpoint·수령 자료 해시와 환경을 확인한다.
   기존 정상8장의 96영역 점수가 재현되어야 한다.
2. GPU 메모리의 정상 기준표만 정규화한다. 원래 checkpoint는 쓰지 않는다.
   원본·변환 bank 지문을 저장하고 변환 코드·설정을 함께 고정한다.
3. 개발128장과 보정169장을 계산해 새 Q90 계약을 먼저 저장한다.
4. 원본 checkpoint를 다시 로딩하고 동일 변환을 재구성한다. bank 지문이 같아야 하며
   정상297장 모두 원점수 차이1e-4 이하, 고정 계약 판정 변화0이어야 한다.
5. 이미 관찰한 시험109장과 정상256장만 비교한다. 새 독립 시험·마스크 읽기·ROI 선택은 없다.
6. 검출53/55 이상, 기존 검출53장 전부 유지, 정상 오경보2/54 이하와12/256 이하를 모두
   만족해야 정상 표본 재추출 민감도 검사를 수행한다. 실패하면 추가 계산을 생략하고 비채택한다.
7. 통과 후보도 비용 재검토 대기다. 실제 성능·동일 장비 paired warm p95·현장 검증 없이 서비스에 올리지 않는다.

정상 재표집은 기존과 같은 development-only/calibration-only/both 각1,000회 PCG64,
seed 20261001/20261002/20261003을 사용한다. 두 모델에 같은 원본사진 인덱스를 적용한다.
검출2.5백분위50 이상, 검출95%구간 폭 기준선의 절반 이하, 오경보97.5백분위5/54와25/256
이하, 무효 반복0을 요구한다. 이것은 관찰 자료에서의 보정 민감도이지 새 데이터의 성능 신뢰구간이 아니다.

## 시간과 중단 처리

기존 사진당 약1초대 warm 기록을 단순 적용하면 959장 분량(보정297 + 재로딩297 + 비교365)의
추론은 약20분 안팎이다. 이번 방법의 실측 예상은 아니며 초기 로딩·검증·디스크·재표집이 추가된다.
사용자는 여유 있게 20~40분을 잡되, 누적2시간이 상한이다. PyTorch reserved6GiB, 샘플링
RSS20GiB 초과 시 중단한다. 이 수치는 성공 예측이 아니라 중단 한도다.

새 후보는 약230MiB의 bank를 같은 크기로 변환한다. 변환 중 원본과 새 bank가 함께 존재할 수
있으며 전체 GPU 점유는 추론 거리 행렬·모델·allocator까지 포함해 실행 때 측정한다.
사진별 완료 파일과 실행 시간 기록을 보존해 정상적인 예외 뒤 재사용한다. 강제 종료로 시간
기록이 없거나 자원 상한 초과 이력이 있으면 자동 재시작하지 않고 검토를 요청한다.
기존 결과 삭제·후보 크기 자동 축소·성능을 보고 재시도 설정 변경을 하지 않는다.

## 연구실에서 실행

배포된 커밋을 받은 뒤 다른 GPU 작업이 끝났을 때 실행한다. 이 문서 자체는 GitHub 배포 확인이 아니다.

```powershell
Set-Location 'C:\개인 프로젝트\defectops'
git pull --ff-only
powershell.exe -NoProfile -ExecutionPolicy Bypass -File '.\scripts\run_mpi_unit_feature.ps1'
```

기본 입력은 `Downloads\extracted.zip`과 기존 프로젝트의 checkpoint·handoff 자료다.
완료하면 `artifacts\handoff\mpi-unit-feature-v1.zip`을 전달한다. 이 ZIP에는 원본 이미지나 모델
파일을 넣지 않는다. 오류 시 삭제하지 말고 메시지를 보낸다.

## 근거와 검증의 한계

Anomalib2.2.0의 [PatchCore 구현](https://raw.githubusercontent.com/open-edge-platform/anomalib/v2.2.0/src/anomalib/models/image/patchcore/torch_model.py)은
결합 특징을 패치 벡터로 바꾼 다음 최근접 거리를 구하고 지도를 만든다. 이 인터페이스에
양쪽 벡터 정규화를 넣는다. 이 출처는 구현 위치를 뒷받침하며 MPI에서 개선된다는 증거는 아니다.
선정 이유와 해석은 이 프로젝트의 가설이다.

CPU 테스트는 수학·흐름·복구·손상 탐지를 확인한다. Mac의 가짜 runtime 테스트는 CUDA
정확성·성능 측정이 아니다. Windows 첫 실행의 원 모델 재현, 변환 bank 지문, 전체 정상 재로딩 검증으로
실제 경로를 확인한다. 이번 후보 결과가 없으므로 어떤 성능 향상도 아직 보고하지 않는다.
