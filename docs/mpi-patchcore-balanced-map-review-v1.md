# MPI PCB 균형 대표 모델의 저장 지도 대조

## 목적

균형 대표 모델은 55/55 검출을 유지했으나 정상 오경보가 1→3/54장, 15→20/256장으로 늘었다. 결함 포함 타일의 평균 위치 AUROC도 0.9602→0.9244로 낮아졌다. 새 학습 대신 같은 원본과 저장 지도를 대조해 정상 반응·결함 위치·보정 기준의 영향을 구분한다.

이 진단은 CPU에서 수행한다. GPU·모델파일 로딩·새 추론·학습·경고선 변경·대표 재선정은 없다. 기존 캐시와 ZIP을 읽고 별도 검토 ZIP만 만든다. 서비스 모델과 자동합격 정책도 그대로다.

## 고정 대상

| 역할 | 사진 |
| --- | --- |
| 새 정상시험 오경보3장 | good/0019,0021,0028 |
| 새 정상검증 오경보5장 | validation/0288,0975,1382,1415,1549 |
| 해소된 오경보 정상 대조1장 | good/0018 |
| grid4-1 위치AUROC 하락 상위2장 | defect/0033,0028 |
| grid4-3 위치AUROC 하락 상위2장 | defect/0025,0008 |
| 기존 약한 불량 대조1장 | defect/0024 |

총 14장×12영역=168타일이다. 하락 순서는 기존 수령 JSON의 candidate-baseline AUROC 오름차순, 동점이면 사진 ID순이다. 주요 영역을 먼저 펼쳐 보여주되 12영역을 모두 제공한다. 같은 성능 자료를 보고 고른 진단 사례이므로 새로운 일반화 성능이나 전체 위치성능 표본으로 해석하지 않는다. 알려진 GT 예외 0006과 이미지 복구 0054는 선택 대상이 아니다.

## 출력 내용

- `index.html`: 한국어 설명·사진별 점수/보정 교차표·12영역 카드. ZIP을 새 폴더에 풀어 브라우저에서 연다. 외부 통신이나 JavaScript가 없다.
- 각 타일의 `card.png`: 원본/GT, 기존 전역 대표 모델, 균형 대표 모델의 3열 비교.
- 원본 PNG, 두 모델의 원본 float32 지도 NPY, GT 원본과 bool NPY. 지도는 새로 계산하지 않는다.
- `scores.json`: 원점수·정상 중심·정상 폭·경고선·원점수 단위 경고 경계·사진 최고점 영역과 교차표.
- `review.json`: 입력·모델 지문·캐시 영수증·지도 통계·색 범위·현재 실행기 소스 지문.
- `handoff-manifest.json`: 모든 산출물의 SHA256.

## 지도를 읽는 법

두 모델의 같은 타일은 공통 원점수 min/max와 동일 색상을 쓴다. 개별 모델마다 색을 다시 늘리지 않는다. 색 범위는 카드에 표시하며, 다른 카드끼리는 범위가 다르므로 색만 직접 비교하지 않는다. 파랑이 낮고 빨강이 높다.

녹색선은 GT 경계, 자홍색선은 높은 656픽셀의 영역(경계값 동점 포함)이다. 자홍색은 운영 픽셀 판정선이 아니다. GT와 겹침 수는 동점의 가능 범위를 함께 기록한다. 원본은 왼쪽에서 색 혼합 없이 볼 수 있고 별도 PNG도 포함한다.

원점수 단위 경고 경계는 `center + scale × threshold`다. 이 경계를 그림의 픽셀 판정선으로 사용하지 않는다. 사진 결정은 영역의 상위 656픽셀 평균을 보정한 뒤 12영역 최댓값으로 계산한다.

교차표는 기존/새 원점수 벡터와 기존/새 보정계약을 2×2로 조합한다. 새 보정을 적용하면 최고점 영역도 바뀔 수 있어 사진 단위로 다시 집계한다. 같은 모델/계약 대각선은 기존 저장 판정과 정확히 일치해야 한다. 교차 조합은 산술 진단이지 재보정·운영 후보·물리적 원인 증명이 아니다. 기준 미만도 자동 합격은 아니다.

## 실행 전 검증

입력은 `mpi-patchcore-balanced-bank-v1.zip`이며 SHA256은 `823ff7b3dcde78fa6d5d2d739edea31c042c9592c5fd60e1b5db7f21c07bc09b`로 고정한다. 부모 학습 확대 ZIP과 개발 확대 ZIP, 전체 기존 소스 지문·사진 역할·보정계약·판정을 확인한다. 새 진단 파일 추가 때문에 과거 실행 identity를 다시 만들지 않으며 과거의 모든 고정 소스는 변경 없이 검증한다.

원본 ZIP 지문·선택 이미지 바이트/RGB 지문·GT의 기존 nonzero 규칙·모델별 캐시 영수증·모델 지문·사진 순서·저장 지도와 상위 1% 점수의 정확한 재현을 검사한다. 기존 location 기록이 있는 경우 통계도 대조한다. float32 통계 축약에만 CPU 차이를 위한 rtol1e-7/atol1e-6을 쓰며, 지도 파일 해시·기존 top1 재현 검사를 느슨하게 하지 않는다.

캐시가 없거나 달라지면 멈춘다. 자동 재추론·복구·대체 사진 선정은 하지 않는다. 경과시간 상한은 없고, 한 사진의 지도를 읽어 순차 처리한다. 전달 ZIP 내용은 메모리에 모아 만들므로 수백 MB 추가 RAM과 ZIP 디스크 여유가 필요하다. 실측 시간은 아직 없으며 원본 ZIP 해시와 168카드 생성이 주요 작업이다.

## 연구실 실행

```powershell
Set-Location 'C:\개인 프로젝트\defectops'
git pull --ff-only
if ($LASTEXITCODE -ne 0) { throw 'Git update failed; stop here.' }
powershell.exe -NoProfile -ExecutionPolicy Bypass -File '.\scripts\run_mpi_patchcore_balanced_map_review.ps1'
```

기본 원본은 `$env:USERPROFILE\Downloads\extracted.zip`이다. 필요하면 실행기에 `-Archive '실제 경로'`를 전달한다. 새 학습은 필요 없고 기존 모델·저장 지도·원본·handoff ZIP은 보존한다.

완료 후 전달 파일:

```text
C:\개인 프로젝트\defectops\artifacts\handoff\mpi-patchcore-balanced-map-review-v1.zip
```

본인도 확인하려면 이 새 ZIP을 별도 폴더에 풀고 `index.html`을 연다. 기존 결과 폴더에 덮어 풀지 않는다. 이미지/마스크는 허용된 개인 프로젝트 검토용으로만 사용하고 공개 저장소나 노션에 재배포하지 않는다.

동일 완료 ZIP이 있으면 내용 일치를 검사하고 보존한다. 다른 내용이면 덮어쓰지 않는다. 중단 후 동일 명령으로 처음부터 CPU 내보내기를 다시 할 수 있으며 기존 학습을 다시 하지 않는다. 오류는 삭제·우회하지 말고 전문을 전달한다.

## 다음 판단

신규 오경보 8건을 원점수 상승과 보정 경계 이동으로 구분하고, 하단 결함의 순위 하락을 원본/GT와 대조한다. 색만으로 조명·반사·위치 차이 등의 물리적 원인을 확정하지 않는다. 진단 근거를 본 뒤 대표 선정 또는 보정 중 다음 변경 하나를 정한다. 이 실행은 어떤 새 모델도 자동 채택하지 않는다.

## 준비 검증

신규 CPU 검사 17개가 통과했다. 실제 수령 ZIP으로 14장 선택·기존 판정·보정 교차표를 재현했다. 합성 원본/캐시로 두 모델의 파일 지문, 빈 GT, 카드 생성, ZIP 무결성, 반복 실행 시 동일 출력 보존, 변조 시 중단을 검사했다. 합성 카드의 글자와 색 범위도 확인했다.

전체 테스트는 1,203개와 하위 검사 52개 통과, 환경 의존 검사 11개 건너뜀이다. 실제 연구실의 원본/지도 168타일 내보내기와 Windows PowerShell 실행은 아직 수행하지 않았다. GPU 검증이 필요한 작업은 아니다.
