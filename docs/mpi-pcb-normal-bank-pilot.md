# MPI-PCB 전용 정상 기준표 파일럿 v1

상태: **준비 기능 구현·로컬 테스트 완료, 연구실 정상 데이터 준비 실행 대기** (2026-09-26).
아직 새 모델을 학습하지 않았고 새 성능 결과도 없다.

## 무엇을 확인하려는가

기존 두 모델은 다른 기판의 정상 패턴으로 만들어졌다. MPI-PCB 시험에서는 불량
55장 중 각각 2장·3장만 검출했고, 저장 맵 진단에서도 결함과 무관한 부분의 높은
반응을 확인했다. 다만 이것만으로 실패 원인이 학습 데이터 차이라고 확정할 수는 없다.

이번 질문은 **“MPI-PCB 자체의 정상 패턴으로 기준표를 만들면, 이 기판의 정상 부분과
결함을 더 잘 구분하는가?”**이다. PatchCore의 사전학습 특징 추출기는 고정하고,
정상 이미지에서 추출한 대표 특징을 memory bank(정상 기준표)로 만든다는 뜻이다.
새로운 신경망을 처음부터 학습하는 작업은 아니다.

이번 변경은 데이터 준비까지만 포함한다. 학습 실행기·보정·비교 평가 실행기는
아직 이 파일럿에 연결하지 않았다. 준비 결과로 누수 여부와 최종 명단을 확인한 뒤
이어 붙인다. 새 데이터셋이나 별도 촬영은 필요하지 않다.

## 고정한 구성과 규모

| 항목 | 이번 파일럿 |
| --- | --- |
| 정상 학습 | 원본 사진 64장 × 12영역 = 768개 영역 이미지 |
| 정상 보정 | 기존 v4 원본 169장 × 12영역 = 2,028개 이미지, 명단 변경 없음 |
| 모델 | wide_resnet50_2, layer1 + layer2, seed 42, 특징 차원 768 |
| 입력 | RGB 256×256, 기존 resize·ImageNet 정규화, augmentation 없음 |
| 패치 선택 | 64×64 격자에서 행·열 간격 2 → 이미지당 1,024개 |
| 후보 / 최종 기준표 | 786,432개 / 10% coreset 78,643개 |
| 기준표 범위 | 12영역을 함께 쓰는 기준표 하나; 영역별 12개 모델이 아님 |
| 영역 점수 / 사진 점수 | 맵 상위 1% 평균 / 12영역 점수 중 최대 |
| 새 임곗값 | 새 모델로 같은 정상 169장을 보정하여 95% 분위수(higher) 산출 예정 |

기존 VisA PCB3 v2가 학습을 완료한 후보 869,376개보다 작게 시작한다.
후보 특징 텐서만 계산하면 2.25 GiB, 최종 기준표는 약 0.225 GiB다. 이것은
**최대 GPU 메모리가 아니다.** 모델, 투영 특징, 거리 계산, 복사본이 추가되므로
8GB GPU에서 성공하거나 특정 시간 안에 끝난다고 보장하지 않는다.
이번 준비 명령은 GPU를 사용하지 않는다.

64장은 작은 파일럿의 범위를 고정하기 위한 선택이지, 최적 학습량이라는 뜻은 아니다.
VisA 모델과 학습 이미지 수·정상 패턴·기준표 크기가 함께 달라지므로, 나중에 결과가
좋아져도 “학습 출처 하나만 바꿔서 개선됐다”고 해석하지 않는다. 전체 패치를
보존하는 대용량 coreset 실험과도 다르다.

## 이번 준비에서 검사하는 내용

1. 원본 ZIP, 전체 정상 무결성 감사, v4 정상 보정 명단, 이전 평가 v2 ZIP의
   검토 완료 SHA256을 확인한다. 기존 사진이나 산출물은 변경하지 않는다.
2. 기존에 확인한 손상 사진 ID 16개는 **원본 사진 단위로 12영역 모두** 학습 후보에서
   제외한다. 고치거나 삭제하지 않는다. 남은 정상 원본 1,671장 × 12영역의
   ZIP CRC, PNG 검증, RGB 256×256 디코딩, 원시 파일·픽셀 해시를 기록한다.
3. 보정용 169장의 바이트·픽셀이 기존 v4와 같은지 다시 확인한다.
4. 학습 후보의 어느 한 영역이라도 보정 사진 또는 기존 시험 감사의 RGB 해시와
   정확히 같으면, 그 원본 사진 전체를 후보에서 제외한다. 시험 쪽은 이전 감사 JSON의
   110장·1,320영역 해시만 읽고, 시험 이미지·마스크·모델 점수는 읽지 않는다.
5. 남은 원본을 `SHA256(mpi-pcb-normal-bank-pilot-v1\0photo_id)` 오름차순으로 정렬한다.
   12영역 모두 동일한 원본 그룹에서는 이 순서의 첫 사진만 유지하고, 앞의 64장을 선택한다.
   64장이 부족하면 임의 축소하지 않고 검토 필요 상태로 결과 ZIP을 저장한다.
6. 학습 내부의 **일부 영역만 같은 중복**은 기록하되 추가로 제거하지 않는다.
   이 고정 정책은 정상 패턴의 반복을 별도로 관찰하기 위한 것이다. 영역 이미지
   768개를 독립된 기판 768개로 계산하지 않는다.
7. 보정과 시험의 기존 중복도 별도로 보고하되 보정 명단이나 기존 시험을 자동 변경하지 않는다.
   기존 v2는 보정 사진과 중복된 `good/0013`을 시험에서 제외했다. 추가 겹침이 발견되면
   학습·평가로 넘기기 전에 해석과 처리 규칙을 검토한다.

정확한 픽셀 중복이 없다는 것이 다른 기판·촬영 세션·lot의 독립성을 증명하지는 않는다.
MPI 시험은 이미 관찰했으므로 이번 작업을 “미관측 시험 봉인”으로 표현하지 않는다.
준비 보고서의 시험 디코딩 0은 **이번 실행에서 다시 열지 않았다는 뜻**이다.

## 연구실 Windows 실행

기존 `extracted.zip`과 프로젝트 내 감사·평가 산출물을 그대로 사용한다.
의존성 재설치, 수동 압축 해제, 모델 서버 실행은 필요하지 않다.

```powershell
Set-Location "C:\개인 프로젝트\defectops"
git pull --ff-only
if ($LASTEXITCODE -ne 0) { throw "Git update failed." }
powershell.exe -NoProfile -ExecutionPolicy Bypass -File ".\scripts\prepare_mpi_pcb_normal_bank.ps1"
```

입력 파일:

- `C:\Users\user\Downloads\extracted.zip` (실제 사용자 프로필의 Downloads 사용)
- `artifacts\data-audit\mpi-pcb-normal-pool-integrity-v1.json`
- `artifacts\data-audit\mpi-pcb-normal-preflight-v4.json`
- `artifacts\handoff\mpi-pcb-external-evaluation-v2.zip`

원본 ZIP이 다른 위치에 있으면 PowerShell 실행 명령 끝에 `-Archive "실제 전체 경로"`를
추가한다. 파일이 없다고 뜨면 오류에 표시된 경로를 공유하고, 기존 결과를 삭제하거나
이름을 바꿔 검증을 우회하지 않는다.

정상적인 완료 상태는 `normal_bank_preparation_ready_for_review`다.
이 상태는 학습 완료나 독립 성능 검증 통과가 아니다.

첨부할 결과:

`C:\개인 프로젝트\defectops\artifacts\handoff\mpi-pcb-normal-bank-preparation-v1.zip`

JSON 4개만 들어 있으며 사진·마스크·모델 파일은 포함하지 않는다.
동일 입력·코드로 재실행하면 완성된 ZIP의 체크섬을 검증해 재사용한다.
입력·코드가 다르거나 손상된 결과는 덮어쓰지 않는다. 최초 저장은 동일 폴더의
임시 ZIP을 검증한 뒤 원자적 하드링크로 게시한다(Windows NTFS 및 macOS).

## 검증과 다음 단계

로컬 Python 3.11.9에서 새 테스트 17개를 통과했다. 전체 명령
`.venv/bin/python -m pytest -q -p no:cacheprovider`는 **256 tests + 52 subtests**를
통과했다. 기존 경고 3개는 남아 있다. 실제 평가 v2 ZIP에서 1,320개 시험 RGB
해시를 읽는 것까지 확인했다. Windows PowerShell 실행과 실제 정상 20,052개
이미지 스캔, GPU 학습은 여기서 검증하지 않았다.

다음은 준비 ZIP 확인 → 64장 전용 기준표 학습 → 기존 정상 169장으로 새 임곗값 보정
→ 같은 시험의 탐색 비교다. 모델 파일과 기존 임곗값은 보존한다.
기존 두 모델의 임곗값을 새 기준표에 그대로 재사용하면 안 된다.
미탐·정상 오경보뿐 아니라 결함 위치 반응, 추론 시간, 최대 메모리를 함께 보고,
기존 시험의 109장 주 분석·108장 복구 사례 제외 분석·54장 위치 분석 범위를 명시한다.
이 결과만으로 자동 PASS, 생산 적용, 독립 일반화 성능을 주장하지 않는다.

이 파일럿의 검증 질문에 답한 뒤, 검사 API와 검토 UI의 통합 등 운영 시스템 개발과
연결할지 판단한다. 이번 변경에 다품목 서비스 확장이나 화면 개편은 포함하지 않았다.
