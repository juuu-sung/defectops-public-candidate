# MPI-PCB 전용 정상 기준표 파일럿 v1

상태: **연구실 학습·정상 보정·저장 재검증 결과 수령 및 검토 완료** (2026-09-27).
새 모델의 불량 시험 성능은 아직 없다. [학습 수령 보고서](../reports/mpi-pcb-normal-bank-fit-v1.md)와
[다음 연구실 실행: 비교 평가](mpi-pcb-normal-bank-evaluation.md)를 참고한다. 아래 준비·학습 명령은 완료된 단계다.

전체 관계는 [데이터와 모델 연결표](data-model-map.md)를 참고한다.

## 무엇을 확인하려는가

기존 두 모델은 다른 기판의 정상 패턴으로 만들어졌다. MPI-PCB 시험에서는 불량
55장 중 각각 2장·3장만 검출했고, 저장 맵 진단에서도 결함과 무관한 부분의 높은
반응을 확인했다. 다만 이것만으로 실패 원인이 학습 데이터 차이라고 확정할 수는 없다.

이번 질문은 **“MPI-PCB 자체의 정상 패턴으로 기준표를 만들면, 이 기판의 정상 부분과
결함을 더 잘 구분하는가?”**이다. PatchCore의 사전학습 특징 추출기는 고정하고,
정상 이미지에서 추출한 대표 특징을 memory bank(정상 기준표)로 만든다는 뜻이다.
새로운 신경망을 처음부터 학습하는 작업은 아니다.

준비 ZIP과 연구실 학습 ZIP 검증을 마쳤으며, 학습·정상 보정·저장 모델 재검증을 완료했다.
시험 비교 실행기도 별도로 연결했다. 새 데이터셋이나 별도 촬영은 필요하지 않다.
기존 모델이나 검사 서비스는 변경하지 않는다.

## 고정한 구성과 규모

| 항목 | 이번 파일럿 |
| --- | --- |
| 정상 학습 | 원본 사진 64장 × 12영역 = 768개 영역 이미지 |
| 정상 보정 | 기존 v4 원본 169장 × 12영역 = 2,028개 이미지, 명단 변경 없음 |
| 모델 | wide_resnet50_2, layer1 + layer2, seed 42, 특징 차원 768 |
| 입력 | RGB 256×256, 기존 resize·ImageNet 정규화, augmentation 없음 |
| 패치 선택 | 64×64 격자에서 행·열 간격 2 → 이미지당 1,024개 |
| 후보 / 최종 기준표 | 786,432개 / 10% coreset 78,643개 |
| 기준표 범위 | 12영역을 함께 쓰는 기준표 하나; 영역별 12개 모델이 아님 |
| 영역 점수 / 사진 점수 | 맵 상위 1% 평균 / 12영역 점수 중 최대 |
| 새 임곗값 | 같은 정상 169장의 95% 분위수(higher): 46.839376955497556 |

기존 VisA PCB3 v2가 학습을 완료한 후보 869,376개보다 작게 시작한다.
후보 특징 텐서만 계산하면 2.25 GiB, 최종 기준표는 약 0.225 GiB다. 이것은
**최대 GPU 메모리가 아니다.** 모델, 투영 특징, 거리 계산, 복사본이 추가되므로
8GB GPU에서 성공하거나 특정 시간 안에 끝난다고 보장하지 않는다.
이번 준비 명령은 GPU를 사용하지 않는다.

64장은 작은 파일럿의 범위를 고정하기 위한 선택이지, 최적 학습량이라는 뜻은 아니다.
VisA 모델과 학습 이미지 수·정상 패턴·기준표 크기가 함께 달라지므로, 나중에 결과가
좋아져도 “학습 출처 하나만 바꿔서 개선됐다”고 해석하지 않는다. 전체 패치를
보존하는 대용량 coreset 실험과도 다르다.

## 이번 준비에서 검사하는 내용

1. 원본 ZIP, 전체 정상 무결성 감사, v4 정상 보정 명단, 이전 평가 v2 ZIP의
   검토 완료 SHA256을 확인한다. 기존 사진이나 산출물은 변경하지 않는다.
2. 기존에 확인한 손상 사진 ID 16개는 **원본 사진 단위로 12영역 모두** 학습 후보에서
   제외한다. 고치거나 삭제하지 않는다. 남은 정상 원본 1,671장 × 12영역의
   ZIP CRC, PNG 검증, RGB 256×256 디코딩, 원시 파일·픽셀 해시를 기록한다.
3. 보정용 169장의 바이트·픽셀이 기존 v4와 같은지 다시 확인한다.
4. 학습 후보의 어느 한 영역이라도 보정 사진 또는 기존 시험 감사의 RGB 해시와
   정확히 같으면, 그 원본 사진 전체를 후보에서 제외한다. 시험 쪽은 이전 감사 JSON의
   110장·1,320영역 해시만 읽고, 시험 이미지·마스크·모델 점수는 읽지 않는다.
5. 남은 원본을 `SHA256(mpi-pcb-normal-bank-pilot-v1\0photo_id)` 오름차순으로 정렬한다.
   12영역 모두 동일한 원본 그룹에서는 이 순서의 첫 사진만 유지하고, 앞의 64장을 선택한다.
   64장이 부족하면 임의 축소하지 않고 검토 필요 상태로 결과 ZIP을 저장한다.
6. 학습 내부의 **일부 영역만 같은 중복**은 기록하되 추가로 제거하지 않는다.
   이 고정 정책은 정상 패턴의 반복을 별도로 관찰하기 위한 것이다. 영역 이미지
   768개를 독립된 기판 768개로 계산하지 않는다.
7. 보정과 시험의 기존 중복도 별도로 보고하되 보정 명단이나 기존 시험을 자동 변경하지 않는다.
   기존 v2는 보정 사진과 중복된 `good/0013`을 시험에서 제외했다. 추가 겹침이 발견되면
   학습·평가로 넘기기 전에 해석과 처리 규칙을 검토한다.

정확한 픽셀 중복이 없다는 것이 다른 기판·촬영 세션·lot의 독립성을 증명하지는 않는다.
MPI 시험은 이미 관찰했으므로 이번 작업을 “미관측 시험 봉인”으로 표현하지 않는다.
준비 보고서의 시험 디코딩 0은 **이번 실행에서 다시 열지 않았다는 뜻**이다.

8GB GPU 여유를 위해 검사 서버나 다른 GPU 작업은 사용자가 정상 종료한 뒤 실행하는
편이 좋다. 메모리 부족 때 후보 수를 자동 축소하지 않는다.

```powershell
Set-Location "C:\개인 프로젝트\defectops"
```

### 네 단계의 의미

1. **학습:** 정상 원본 64장의 768영역을 해시·PNG·RGB 검증 후 특징으로 바꾼다.
   공간 패치 간격 2와 coreset 10%를 적용하고 **모델을 먼저 저장**한다. 특징 추출과
   대표 특징 선택 시간을 따로 기록한다. 선택은 수 시간이 걸릴 수 있으며 전체 실행
   시간이나 8GB GPU에서의 성공을 보장하지 않는다.
2. **정상 보정:** 별도 정상 원본 169장·2,028영역을 새 모델로 계산한다. 영역 맵의 상위
   1% 평균 → 12영역 최댓값 → 정상 사진 점수의 95% 분위수(higher)로 임곗값을 정한다.
   기존 두 모델의 임곗값을 복사하지 않는다. 시험 사진과 마스크는 읽지 않는다.
3. **저장 모델 재검증:** 저장 모델을 새로 불러와 정상 169장을 한 번 더 계산한다.
   모든 사진·영역 점수와 임곗값의 최대 절대 차이가 `1e-4` 이하여야 한다.
   두 정상 계산을 합쳐 **4,056개 영역 추론**이 있으므로 보정·재검증도 시간이 걸린다.
4. **전달 자료 생성:** 설정·모델 해시·환경·시간/메모리·보정 점수·재현성을 JSON ZIP으로
   저장한다. 사진·마스크·모델 파일은 전달 ZIP에 포함하지 않는다.

완료 상태: `mpi_pcb_target_bank_fit_calibrated_exploratory`.
**학습·정상 보정 완료**이며 시험 통과·성능 개선·서비스 배포 완료를 뜻하지 않는다.
이진 픽셀 임곗값은 만들지 않으며 자동 합격도 허용하지 않는다.

첨부할 파일:

`C:\개인 프로젝트\defectops\artifacts\handoff\mpi-pcb-normal-bank-fit-v1.zip`

모델은 `artifacts/mpi-pcb-normal-bank-pilot-v1/fit/model.pt`에 남는다. 같은 폴더 아래
`calibration`·`reload`에는 정상 점수와 검증 기록이 있고, 최상위 `fit.json`은 완료 요약이다.
기존 모델 경로와 겹치지 않는다.

### 중단 후 재실행과 측정 범위

- 같은 명령은 **완료된 단계**의 설정·코드·체크섬을 확인한 후 재사용한다. 보정 중
  중단되었고 fit 저장이 완료됐다면 학습을 반복하지 않는다. 미완료 보정은 처음부터
  다시 계산한다. coreset 선택 도중 중단은 선택 인덱스 단위로 재개할 수 없어 학습부터 다시 한다.
- 미완료 시도는 `.fit-attempt-*` 같은 폴더에 보존하고, 완료 단계만 정식 경로로
  게시한다. 손상된 완료 파일·설정 변경·단계 누락은 덮어쓰기 없이 중단한다.
- 동시 쓰기를 막는 프로세스 잠금은 강제 종료 시 운영체제가 해제한다. 잠금 파일을
  수동 삭제할 필요가 없다.
- 연속 실행에서는 학습 직후 모델과 저장 후 로딩한 모델을 비교한다. 학습 후
  재시작했다면 보정도 저장 모델로 수행하며 `model_origin`에 명시한다.
- 정상 계산 시간은 ZIP 읽기·해시·디코딩·전처리·추론·맵 전송·점수 집계 포함이며 모델
  로딩은 제외한다. 서비스 전체 응답이나 정식 warm 속도 측정과 혼동하지 않는다.
- GPU 메모리는 단계별 PyTorch 할당/예약 최고치이며 전체 GPU 사용량이 아니다.
  CPU RAM은 psutil이 있을 때 순간 RSS만 기록한다(없으면 null). RAM 최고치는 아니다.
- 관련 소스는 LF 정규화 해시로 비교해 Mac LF / Windows CRLF 차이를 구분한다.
  Git 커밋도 기록하고 변경된 작업 트리에서는 실행을 막는다. 무관한 새 커밋은 관련
  코드와 설정이 같다면 완료 단계를 재사용할 수 있다.

## 준비 당시 로컬 검증과 현재 다음 단계

준비 기능 테스트 17개에 더해 학습·보정 실행기 테스트 21개를 추가했다. 로컬 Python
3.11.9 전체 명령 `.venv/bin/python -m pytest -q -p no:cacheprovider`는

준비 ZIP도 입력 검사를 통과했다. 실제 PatchCore GPU 학습 검증은 아니다.
위 내용은 실행 준비 당시 로컬 검증이다. 이후 Windows RTX 5060의 정상 실행 결과를
수령했으며 학습·정상 보정·재로딩이 완료됐다. Windows 강제 중단/동시 잠금의 모든
실패 경로까지 실제 장비에서 시험했다는 뜻은 아니다.

현재 다음은 **저장 모델을 새 프로세스에서 로드 → 짧은 정상 점검 → 같은 시험의 탐색 비교**다.
학습과 전체 정상 보정을 다시 하지 않는다. 모델 파일과 기존 임곗값은 보존한다.
기존 두 모델의 임곗값을 새 기준표에 그대로 재사용하면 안 된다.
미탐·정상 오경보뿐 아니라 결함 위치 반응, 추론 시간, 최대 메모리를 함께 보고,
기존 시험의 109장 주 분석·108장 복구 사례 제외 분석·54장 위치 분석 범위를 명시한다.
이 결과만으로 자동 PASS, 생산 적용, 독립 일반화 성능을 주장하지 않는다.

이 파일럿의 검증 질문에 답한 뒤, 검사 API와 검토 UI의 통합 등 운영 시스템 개발과
연결할지 판단한다. 이번 변경에 다품목 서비스 확장이나 화면 개편은 포함하지 않았다.
