# MPI 정상 점수 쌍의 차이를 이용한 보정 후보 설계

2026-10-03. **설계 후 CPU 비교 실행 동의 수령, 구현·잠금 단계.** 최초 동의는 설계에 한정했고,
후속 “응 진행해보자. 오래 걸릴 거 같으면 나한테 명령어 알려줘”로 실행에 동의했다.
이는 아래 고정 CPU 비교 범위이며 재학습·서비스 교체 동의로 확대하지 않는다.
실험 식별자는 `MPI-C2-01`, 기계 판독 규칙은 [설정 파일](../configs/mpi-qn-scale-v1.json)이다.
새 사이클은 **이 후보1개로 제한**한다. 과거 두 실패를 지우거나 남은 후보로 다시 세지 않는다.

## 1. 질문과 선택 근거

> 기존 정상 기준표와 원점수를 유지하고, 영역별 정상 변동 폭을 Q90−중앙값 대신
> 정상 점수 쌍의 차이로 추정하면, 기존 검출을 보존하면서 오경보와 보정 표본 민감도를 줄일 수 있는가?

기존 보정의 분모는 정상128장 중 높은 쪽 분위수와 중앙값의 간격이다. 이번 후보는 각 영역
안에서 정상 점수끼리 얼마나 다른지로 분모를 계산한다. 다른 영역의 폭을 섞지 않는다.

Qn은 관측값 쌍의 절대 차이를 정렬한 특정 순서통계량에 기반한 강건한 척도다.
여기서는 정규분포 표준편차로 환산하지 않은 **Qn 비례 척도**를 사용한다.
계산 정의와 정규분포 보정 상수의 구분은 [robustbase 공식 Qn 문서](https://search.r-project.org/CRAN/refmans/robustbase/html/Qn.html)를 따른다.

이 방법을 선택한 것은 실제 후보 성적을 비교했기 때문이 아니다. 정상 폭 추정이라는 확인된
문제에 대해, 영역 간 혼합 없이 다른 추정법 하나를 검증하기 위한 설계 판단이다.
사진 쌍8,128개는 독립 표본8,128개가 아니다. 독립 단위는 여전히 원본사진이며 표본 수가 늘어난 것이 아니다.

### 기존 실패와 어떻게 다른가

| 비교 | 바뀐 것 | 이번에 하지 않는 것 |
| --- | --- | --- |
| 사이클1 후보1 | 영역 폭과 전체 대표 폭을50%씩 혼합 | 혼합 비율 재탐색, 영역 간 폭 공유 |
| 사이클1 후보2 | 정상64장을 재선정하고 새 bank 구축 | 사진 재선정·증량·재학습 |
| 이번 제안 | 각 영역 자체의 정상 폭 추정법만 교체 | 백본·bank·원점수·중앙값·사진 max·보정 분위수 변경 |

근거: [사이클1 결론](../reports/mpi-model-cycle-1-conclusion.md),
[점수 변화 분리 진단](../reports/mpi-diversity-score-decomposition-v1-review.md),
[기존 정상 표본 영향 분석](../reports/mpi-normal-influence-v1-review.md).

### 개선이 보장되지 않는 이유

- 정상 점수가 비대칭이거나 여러 정상 외관 집단으로 나뉘면 중앙부 폭이 정상 꼬리까지 설명하지 못할 수 있다.
- 폭이 작아져 오경보가 늘 수 있다. 강건성은 미탐·오경보 감소의 보증이 아니다.
- 중앙값 자체의 변동과12영역 max가 다른 영역의 정상 반응을 사진 기준으로 끌어올리는 문제는 남는다.
- 특히 보정169장만 바꾸는 상황까지 개선될지는 미확인이다. 개발128장 안정성만 좋아져도 통과시키지 않는다.
- 원래 놓친0019·0024를 찾는다는 가설과는 다르다. 먼저 기존 검출53장을 안정적으로 보존하는 것이 목적이다.

## 2. 바꾸는 계산과 고정하는 계산

각 영역의 정상 개발 점수를 `x[0], ..., x[127]`로 둔다.

```text
n = 128
h = floor(n / 2) + 1 = 65
k = h * (h - 1) / 2 = 2080
D = 모든 i < j에 대한 abs(x[i] - x[j])  # 8128개
s_qn = D의 오름차순 2080번째 값          # 0-based index 2079
c = median(x)                          # 짝수이므로 가운데 두 값 평균

기준선 분모 s_old = quantile(x, 0.90, method="higher") - c
후보 영역 점수 = (원래 top1 점수 - c) / s_qn
후보 사진 점수 = 12영역 후보 점수의 최댓값
후보 경고 기준 = 별도 정상169장 사진 점수의 0.95 higher 분위수
경고 = 사진 점수 >= 해당 방법의 경고 기준
```

`s_qn`은 보간한25% 분위수가 아니다. 정확한2080번째 값을 사용하며 임의 k 탐색은 없다.
64비트 실수로 계산하고 동점과0거리도 보존한다. 자기 자신과의 차이는 넣지 않는다.
정상 재표집에서는 서로 다른 뽑기 위치에 같은 사진이 있으면 그0거리를 그대로 포함한다.
어느 영역의 분모든1e-6 이하·NaN·Inf이면 실패한다. floor 보정, 해당 사진 제거, 다른 표본 재추첨은 금지한다.

정규분포 보정 상수와 유한 표본 보정 계수는 넣지 않는다. 모든 영역의 n이128로 같고 모든 양의
분모에 동일 상수 a를 곱하면 사진 점수와 정상169장에서 산출한 경고 기준이 모두1/a배가 되어
판정이 같기 때문이다. 이 등가성은 양의 유효 척도에 대한 것으로, 서로 다른 n이나 영역별 상수를
허용한다는 뜻이 아니다. 점수 자체는 단위가 달라지므로 기존 threshold2.316961을 후보에 재사용하지 않는다.

고정: 기존 checkpoint·정상64장·공용 bank78,643×768·seed42·입력256·특징층layer1/2·top1%656픽셀,
개발/보정/평가 명단, 중앙값, 사진 max, threshold95% higher, >= 연산.
새 분모를 사용하므로 후보 threshold를 정상169장만으로 다시 계산한다. 기존 계약은 덮어쓰지 않는다.
특정 사진ID·결함 위치·영역ID에 따른 예외 규칙은 없다.

## 4. 성적과 안정성의 통과 조건

기존 기준선: TP53/FN2, 정상54장 FP3/TN51, 정상256장 FP14.
다음 고정 성적 조건을 **모두** 충족해야 연구 후보로 유지한다.

- 불량55장 중53장 이상 검출, 기존 검출53장의 상실0장.
- 정상54장 FP≤2, 정상256장 FP≤12. 기존보다 각각 최소1장·2장 개선해야 한다.
- 전체 점수·새/상실 검출·추가/해소FP 및 영역 폭/임곗값 변화를 공개한다. AUROC나평균만으로 판정하지 않는다.
- 결함군 별 독립 표본·현장 중요도 기준은 확보되지 않았다. 사진별 기존TP 보존은 이 연구의 회귀 조건이지
  결함군별 품질 보증을 대체하지 않는다. 생산 사용과 final 표본수 설계는 별도다.

정상 구성을 바꿔 뽑는 민감도는 이전과 같은3상황×1,000회로 고정한다.
개발128장만, 보정169장만, 둘 다를 원본사진 행 단위로 복원추출하고12영역을 항상 같이 움직인다.
각 반복에서 두 방법에 같은 인덱스를 적용하고 중앙값·분모·threshold를 다시 산출한다.
불량·평가 정상은 재표집하거나 기준 추정에 사용하지 않는다.

각 상황에서 모두 요구한다.

- 검출 수의2.5% 분위수≥50장.
- 검출 수의97.5%−2.5% 분위수 폭≤같은 반복을 쓴 기준선의 절반. 기존 폭0이면 후보도0이어야 한다.
- 정상54장 FP의97.5% 분위수≤5, 정상256장 FP의97.5% 분위수≤25.
- 무효 반복0. 무효가 있으면 해당 상황 분포 요약은 미정으로 남기고 안정성 실패 처리한다. 삭제·재추첨 금지.

난수는PCG64, seed는 개발20261001·보정20261002·동시20261003이며 동시에서는 개발 인덱스를 먼저 뽑는다.
분위수 요약은linear다. 이것은 보정 민감도이지 미래 정확도 신뢰구간이 아니다.
앞선 후보의 실패를 이유로 이 조건을 완화하지 않는다. 성적·안정성·자원을 모두 통과해도 다음 검증 대상일 뿐이다.

| 단계 | 수행 작업 | 완료 조건 | 현재 |
| --- | --- | --- | --- |
| A 설계 | 후보1개·입력·수식·성공/중단 기준 고정 | 사용자에게 차이와 위험 설명, 설정 파일 작성 | 완료 |

성적을 보고 반복 seed·k·보정 분위수·규칙을 바꾸지 않는다. 후보 성적 실패만으로D단계를 건너뛰어
진단 정보를 숨기지 않되, 입력 불일치·고정 계약의 분모 무효·자원 위반은 즉시 중단하고 보존한다.
재표집 중 분모 무효는 그 반복을 실패로 기록하고, 예산 안에서 남은 반복을 계속한다.
해당 상황은 안정성 실패이며 유효 반복만 골라 분포를 요약하지 않는다.

계산 장비는Mac CPU, Python3.11.9·NumPy2.3.3 환경을 기준으로 잠근다. CPU 분석 누적30분·peak RSS2GiB를
상한으로 둔다. 입력 검증·비교·3,000회 계산·중간 체크포인트 쓰기를 포함하고, 최종 보고서 게시 시간은 제외한다.
실패 시도 비용도 누적한다. 강제 종료 등으로 비용 기록이 없으면 자동 재개하지 않는다.
표준 n=128에서 영역당8,128거리,12영역97,536거리다. 순차 영역 계산으로 메모리를 제한하되 사진을 줄이지 않는다.
이는 분석 비용이며 GPU warm 추론이나서비스 전체 응답시간 측정은 아니다. 과거1.16초 기록을 후보의 실측 통과로 복사하지 않는다.

각 완료 단계는 입력·설정·소스·출력 해시를 갖춘 영수증으로 원자적으로 저장한다.
재개는 같은 잠금의 완료 단계만 재사용하고, 불완전 반복은 동일 인덱스로만 재계산한다. 삭제·덮어쓰기·자동 축소 금지다.
동시에1개 실행만 허용한다. 소스/입력/설정이 달라지면 자동 이어가기 금지다.

필수 합성 검증: 손계산 순서통계량, 짝수중앙값, k의0/1-based 차이, 동점·중복·분모0·NaN 거부,
전체정렬/부분선택 두 구현 일치, 위치 이동·양의배율 성질, 공통상수 판정 등가, threshold 경계의>=,
쌍 재표집 인덱스, 변조·중단/재개·기존출력 보존·자원초과 처리. 실제 후보 성적은 이 테스트에서 계산하지 않는다.

## 6. 산출물과 다음 행동

계획된 산출물은 입력/소스 지문, 두 계약, 전수 판정·FP/FN 목록, 모든 반복의 인덱스·파라미터·계수,
성적/안정성/자원 조건, 실패/재개 비용과 사람이 읽는 요약이다. 출력은 신규 `mpi-qn-scale-v1` 이름공간에만 저장한다.
실행기는 `scripts/run_mpi_qn_scale.py`다. 설계 JSON은 설계 당시 상태·지문을 그대로 보존하고,
후속 실행 동의는 이 문서와 실행 identity에 별도로 기록한다. 계산 전 실행기·설정·합성 테스트를 커밋하고,
실행기 및 재사용 함수의 커밋 바이트 일치와 Python3.11.9·NumPy2.3.3·macOS를 확인한다.

실행 동의를 받았으므로 B단계 구현·검증 후 이 카드 범위의 CPU 비교를 진행한다.
GPU·원본이미지·새 모델이 필요하지 않아 연구실 Windows 작업은 없다. 이 실행기는 Mac CPU 전용이다.
새 학습·final 개봉·서비스 교체·자동PASS는 이 카드로 승인하지 않는다.
