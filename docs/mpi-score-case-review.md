# MPI Q90 다섯 사례 원본·지도 검토

상태: 실행 코드·CPU 검증 준비. **실제 다섯 사례 GPU 재추론과 시각적 원인 검토는 아직 미실행**이다.

## 무엇을 알아보는가

[수령 검증 결과](../reports/mpi-score-validation-v1-received-review.md)에서 기존406장의 점수는
정확히 재현됐다. Q90은 기존 불량55장 중53장을 잡았지만, 미사용 정상256장에서14장을 경고했다.
정상 오경보5% 이하 목표는 충족하지 못했다. 이번에는 모델을 다시 학습하는 대신 **판정이 바뀐
정상 사례와 여전히 놓치는 불량의 위치 반응**을 확인한다.

| 고정 사례 | 확인할 질문 |
| --- | --- |
| 정상0970·0998 | 왜 두 장 모두 grid2-2에서 강하게 반응하는가? 원본의 외관·반사·위치 차이가 겹치는가? |
| 정상1415 | Q90 기준 바로 아래로 내려간 사례에서 어느 위치가 점수를 높였는가? |
| 불량0019·0024 | 정답 결함에 반응이 약한가, 다른 정상 부위가 더 강한가, 반응하지만 사진 기준 미만인가? |

이는 결과를 본 뒤 고른 **탐색용 사례 검토**다. 새 독립 불량 검증이나 실제 공정 원인 확정이 아니다.
같은 검증 정상256장으로 임곗값을 다시 맞추고 독립 검증 통과라고 하지 않는다.

## 실행 방식

1. 수령ZIP·원본ZIP·모델과 이전 준비 자료의 해시, 고정된 계산 코드·명단·기준을 대조한다.
2. 기존 모델을 불러와 정상8장으로 실행 환경과 점수를 먼저 점검한다.
3. 선택한5장 × 12영역 =60타일만 재추론한다. 이전 top1/native 점수와 최대 절대 차이
   `1e-4` 이내인지 확인하며 세 방법 중 하나라도 경고 판정이 바뀌면 중단한다.
4. 원본·같은 척도의 이상 지도·상위1% 반응·공식 결함 정답을 저장한다. 세 방법은
   같은 지도를 사용하며 점수 집계·보정 기준이 다르다. 원점수 경계는 **영역의 집계 점수 기준**이지
   지도 픽셀별 불량 기준이 아니다.
5. 전체12영역 카드2쪽과 Q90 최고점 영역 확대 카드, 숫자 비교HTML, 재분석용 지도를 묶는다.

중단된 경우 같은 명령을 실행하면 검증된 완료 사례를 재사용하고 새 실행 환경을 다시 점검한다.
완료 후 재실행은 저장 파일의 무결성을 확인하고 GPU 추론 없이 기존ZIP을 재사용한다.
기존 이미지·모델·기준은 수정하지 않는다. 실패 흔적도 남긴다.

## 연구실 Windows에서

다른 GPU 작업이 끝난 뒤 아래를 실행한다. 기존 handoff ZIP과 checkpoint는 원래 위치에 둔다.

```powershell
Set-Location 'C:\개인 프로젝트\defectops'
git pull --ff-only
powershell.exe -NoProfile -ExecutionPolicy Bypass -File '.\scripts\run_mpi_score_case_review.ps1'
```

기본 원본 경로: `C:\Users\user\Downloads\extracted.zip` (`USERPROFILE` 기준).
다른 곳에 있으면 실행 명령 뒤에 `-Archive '실제경로'`를 지정한다.

전달 파일:

```text
C:\개인 프로젝트\defectops\artifacts\handoff\mpi-score-case-review-v1.zip
```

직접 보는 화면:

```powershell
Start-Process '.\artifacts\analyses\mpi-score-case-review-v1\result\index.html'
```

조명 문제나 학습 다양성 부족이라고 단정하지 않는다. 한 가지 변경을 뒷받침하는 근거가 있을 때만
별도 탐색 실험을 제안한다. 이번 실행 자체는 재학습·임곗값 변경·서비스 모델 교체·자동 합격을 하지 않는다.

CPU 테스트는 합성 이미지로 점수 재현 실패, 실행 환경 실패, 중단·재개, 저장 파일 변조,
전체 재실행과 카드 생성을 확인한다. 실제 Windows PowerShell·CUDA 검증을 대신하지 않는다.
