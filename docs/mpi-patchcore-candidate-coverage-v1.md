# MPI PatchCore 대표 압축과 전체 후보 비교

## 목적과 현재 상태

정상 고점수 14장과 불량0024의 위치 대조를 마쳤다. 다음은 **같은 부위가 대표 기준표에서는 낯설지만, 대표 선택 전 정상 후보에는 이미 존재하는가**를 확인하는 제한 진단이다. 모델을 새로 학습하거나 전체 후보를 서비스에 적용하는 작업이 아니다. 실제 GPU 결과는 연구실 실행 후 확인한다.

현재 모델은 정상256장×12영역×1,024개 특징, 총3,145,728개 후보 중78,643개를 사용한다. 약2.5%다. 전체 후보는 이미 stride2로 보관한 후보 전체이며, 원래64×64 특징 격자의 모든 위치를 복구한다는 뜻은 아니다.

## 고정 비교 조건

| 항목 | 이번 조건 |
| --- | --- |
| 모델·전처리·원특징 | 기존 학습256장 모델 그대로, 가중치 업데이트 없음 |
| 정상 질의 | 직전 검토 정상14장의 사진 점수를 결정한 영역 각각1개 |
| 불량 질의 | defect/0024의 정답이 존재하는6개 영역 전부 |
| 정상 각 영역 | 대표 기준표에 대한 원거리 최대·중앙값 위치 |
| 불량 각 영역 | 위2개와 정답에 걸친 격자 중 원거리 최소·중앙·최대 위치 |
| 중복 위치 | 한 번만 비교하고 역할은 모두 기록, 총질의 최대58개 |
| 비교 A | 대표78,643개에서 가장 가까운 정상 특징 |
| 비교 B | 보관된 전체3,145,728개 후보에서 가장 가까운 정상 특징 |
| 동일 조건 | 같은 질의·768차원·비정규화 유클리드 거리·양쪽float64 계산 |
| 계산·메모리 | 4,096후보씩 GPU 조회, 기존 RAM20GiB·GPU reserved6GiB 제한 유지 |
| 시간 | 상한 없음, 초과 시 자동 축소나 조건 변경 없음 |

질의는 전체 후보를 조회하기 **전에** 기존 대표 모델의 출력으로 고정한다. 전체 조회에서 좋아진 위치만 고르지 않는다. 정상14장은 validation의0147·0274·0275·0276·0335·0337·0361·0656·0706·0961·0984·0998·1390·1436이다.

불량의 강한 grid3-2뿐 아니라 약한 다른 정답 영역도 포함한다. GT는 위치 진단에만 사용하고 학습이나 경고선 산출에는 쓰지 않는다. 4×4 표시 격자에 GT가 걸치는지는 CNN의 실제 수용영역이나 결함 경계를 뜻하지 않는다.

## 무결성과 수치 확인

1. 고정된 학습 확대·개발 확대·점수 중첩 ZIP, 원본ZIP, 학습 소스, 모델 해시를 확인한다.
2. 같은 환경에서 별도 정상8사진을 다시 추론한다. 저장 지도·점수 절대차이는1e-4 이내이고 기존 판정은 같아야 한다.
3. 선택20타일도 저장 지도·원점수와1e-4 이내로 일치해야 한다. 공식 추론 함수가 사용한 특징을 직접 관찰해서 추출하며 별도의 특징 계산 경로를 만들지 않는다.
4. 양쪽 조회는 float64 직접 거리로 맞춘다. 작은 난수 자료에서 전체CPU 기준과 GPU 분할 조회·동점을 먼저 검증한다. 각 최종 근접거리도 CPU float64 직접 차이의 norm으로 대조한다.
5. 공식float32 대표 거리와 진단용float64 대표 거리 차이는 별도로 남긴다. atol0.001·rtol0.0001 범위를 넘으면 중단한다. 이는 조회 수치 점검이고 기존 지도·점수1e-4 재현 허용오차는 늘리지 않는다.
6. 전체256개 원특징 파일을 학습 당시 영수증과 검증한다. 대표78,643개 모두 원후보의 기록된 선택 위치와 바이트가 같은지 확인한다. 전체 최근접거리가 대표 거리보다 커지면 중단한다.

사진별 파일을 순서대로 읽어 전체 후보를 누락 없이 검사한다. 거리가 정확히 같으면 원본 후보 순서의 첫 인덱스를 남긴다. 동일 특징에 다른 출처가 있을 수 있으므로 기록된 한 학습 사진을 유일한 출처라고 주장하지 않는다. 기존 선택 투영369차원은 조회에 쓰지 않으며 원특징768차원을 유지한다.

## 연구실 실행

준비 검증: 로컬 전체 테스트1,138개·하위검사52개 통과,7개 건너뜀. 신규14개 검사는 고정 선정, 원후보/대표 일치, 동점, 공식 특징 관찰 복원, 지도 재현 중단, 실제 파일 기반 중단·재개·내보내기·변조 거부를 다룬다. CPU 가짜 CUDA 인터페이스 검사는 분할 로직만 검증하며 실제GPU 수치 검증을 대신하지 않는다. Mac에 없는 CUDA 검사는 연구실 실행 첫 단계에서 수행한다. 실제 수령ZIP과 동결 소스 지문도 재확인했다.

다른 GPU 작업은 정상적으로 종료한다. 기존 학습 폴더·원특징 캐시 약9GiB·결과ZIP을 그대로 둔다. 특히 `artifacts/mpi-patchcore-scaling-v1/features`를 지우면 안 된다. 누락 파일을 자동 재추출하거나 재학습하지 않는다.

```powershell
Set-Location 'C:\개인 프로젝트\defectops'
git pull --ff-only
if ($LASTEXITCODE -ne 0) { throw 'Git update failed; stop here.' }
powershell.exe -NoProfile -ExecutionPolicy Bypass -File '.\scripts\run_mpi_patchcore_candidate_coverage.ps1'
```

기본 원본은 `Downloads\extracted.zip`이다. 작업은 정상 재현→20타일 질의 고정→256학습사진 특징 전체조회→근접 학습 사진 카드 내보내기 순서다. 전체 후보가 크고 float64를 사용하므로 실행시간은 연구실에서 측정한다. 314만개를 다시 대표 선택하는 학습은 하지 않는다.

Ctrl+C는 완료한 타일·학습사진 단위까지 보존하며 같은 명령으로 재개한다. 강제 종료·환경 변경·검증 실패는 자동 재개하지 않는다. 오류가 나면 결과를 지우거나 새 폴더로 우회하지 말고 오류를 전달한다. 모델·경고선·원본·이전 결과는 읽기 전용이다.

완료 후 전달:

```text

```

ZIP에는 질의별 양쪽 거리·변화율·학습사진/영역/좌표, 질의/근접 특징 배열, 무결성 기록, 원본 질의와 두 근접 학습사진을 나란히 배치한 카드가 들어간다. 이미지는 비공개 연구 검토용이며 재배포하지 않는다.

## 결과 해석과 다음 결정

| 관찰 | 해석할 수 있는 범위와 다음 판단 |
| --- | --- |
| 정상 거리가 뚜렷하게 줄고 결함 거리는 상대적으로 유지 | 선택한 위치에서 대표 압축으로 정상 예시가 빠졌다는 근거. 비용을 고려한 대표 선택·용량 변경 후보를 설계할 수 있음 |
| 정상과 결함 거리가 함께 크게 감소 | 정상 유사도가 커지는 대신 실제 결함 반응도 약해질 가능성. 전체 기준표의 자동 채택 근거가 아님 |
| 정상 거리도 거의 동일 | 해당 위치의 문제를 대표 압축만으로 설명하기 어려움. 후보 자료의 외관 다양성·특징 표현을 다시 검토 |
| 서로 다른 정상 사례에서 결과가 다름 | 원인을 하나로 합치지 않고 관찰 유형별로 정리 |

전체 후보는 더 많은 정상 예시를 포함하므로 최근접거리가 줄어드는 것 자체는 예상되는 결과다. **거리 감소는 오경보 감소나 검출 유지가 아니다.** 이번에는 전체 지도 재계산·정상 재보정·사진별 판정을 하지 않는다. 실제 성능 개선 주장은 후속 고정 후보의 별도 전체 비교가 필요하다. 이미 관찰한 사례의 제한 진단이며 독립적인 일반화 성능을 주장하지 않는다.

새 모델·bank·경고선·서비스 변경과 자동PASS는 없다. 결과를 받은 뒤 정상과 결함의 변화 및 근접 사진을 함께 보고 다음 변경 한 가지를 결정한다.
