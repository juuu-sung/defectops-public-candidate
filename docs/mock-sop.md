# 작업자 의견 → 모의 SOP 원문 검색

이 단계는 **검토 이력이 저장된 검사**에서 사람이 의심 유형을 다시 직접 선택할 때만
원문을 찾는다. 기존 자유 입력 메모, 이미지, 모델 점수·히트맵을 결함 유형이나 원인으로
자동 변환하지 않는다. 검색은 문서에서 내용을 생성하는 RAG/LLM이 아니라 품목·유형·유효
개정판이 모두 일치하는지를 확인하는 결정적 필터다.

## 맥북에서 확인

기존 [로컬 검토 화면](review-ui.md)을 열고, 사람 의견이 `이상 징후가 보임`으로 저장된
검사에서 화면 아래의 **모의 SOP 근거 찾기**를 이용한다. 초기 선택은 `모름`이다.
사람이 유형을 직접 고르고 버튼을 누르면 적용 문서의 ID, 개정판, 유효 기간, 원문 절,
각 절의 인용 ID 및 카탈로그 파일 SHA-256이 표시된다. 유형이 `모름`이거나 문서가 없거나
개정판이 중복되면 근거·조치를 임의로 만들지 않는다. 최신 의견이 `판단 보류` 또는
`눈에 띄는 이상 없음`이면 검색 양식을 표시하지 않는다.

문서 원본은 [`sops/mock-catalog-v1.json`](../sops/mock-catalog-v1.json)에 있다. 현재
transistor 4개 유형의 **가상 관찰 기록**만 포함한다. 폐기된 개정판은 결과에서 제외한다.
유형 선택과 검색 결과는 이번 단계에서 DB에 저장하지 않는다. 따라서 이 선택을 나중에
승인·티켓 발행의 증거로 사용할 수 없으며, 그 기능을 추가하기 전에 검토 revision,
선택한 유형, 문서 revision/해시를 별도 불변 기록으로 묶어야 한다.

이 문서들은 현장의 승인된 SOP가 아니며 실제 생산품의 합격·폐기·설비 조치에 사용할 수
없다. 인용 원문을 보여주는 일과 그 문서가 실제 작업을 정당화하는 일은 다르다. 승인
워크플로우 및 모의 티켓 생성은 아직 구현하지 않았다.

## 확인할 실패 조건

- 작업자 의견이 없거나 최신 의견이 `ANOMALY_VISIBLE`이 아님: 검색 비활성화.
- 유형 `UNKNOWN`, 다른 제품, 적용 시작 전·만료 후, 폐기 개정판: 결과 없음.
- 동일 제품·유형·날짜에 유효 개정판이 둘 이상: 모호성 오류, 결과 표시 금지.
- 문서 표시가 `simulation_only`가 아니거나 인용 절 ID/기간이 잘못됨: 로드 거부.
- 산출물 이미지 checksum 불일치 또는 검사 실패: 기존 검토 화면 단계에서 검색도 차단.

인용 내용은 카탈로그의 해당 절과 문자 그대로 일치해야 한다. 원문에 없는 조치 문장은
검색 결과에 생성하지 않는다.
