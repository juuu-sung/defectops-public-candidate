# 작업자 의견 → 모의 SOP 원문 검색

이 단계는 **검토 이력이 저장된 검사**에서 사람이 의심 유형을 다시 직접 선택할 때만
원문을 찾는다. 기존 자유 입력 메모, 이미지, 모델 점수·히트맵을 결함 유형이나 원인으로
자동 변환하지 않는다. 검색은 문서에서 내용을 생성하는 RAG/LLM이 아니라 품목·유형·유효
개정판이 모두 일치하는지를 확인하는 결정적 필터다.

## 맥북에서 확인

기존 [로컬 검토 화면](review-ui.md)을 열고, 사람 의견이 `이상 징후가 보임`으로 저장된
검사에서 화면 아래의 **모의 SOP 근거 찾기**를 이용한다. 초기 선택은 `모름`이다.
사람이 유형을 직접 고르고 버튼을 누르면 적용 문서의 ID, 개정판, 유효 기간, 원문 절,
각 절의 인용 ID 및 카탈로그 파일 SHA-256이 표시된다. 내용을 확인하고 별도의 확인란과
저장 버튼을 눌러야만 현재 검토 revision에 연결된다. 유형이 `모름`이거나 문서가 없거나
개정판이 중복되면 근거·조치를 임의로 만들지 않는다. 최신 의견이 `판단 보류` 또는
`눈에 띄는 이상 없음`이면 검색·저장 양식을 표시하지 않는다.

문서 원본은 [`sops/mock-catalog-v1.json`](../sops/mock-catalog-v1.json)에 있다. 현재
transistor 4개 유형의 **가상 관찰 기록**만 포함한다. 폐기된 개정판은 결과에서 제외한다.
저장 기록에는 검사 ID, 사람 검토 revision, 선택자 표기, 유형, 문서 ID/개정판,
검색 기준일, 카탈로그 SHA-256, 표시했던 원문 절을 스냅샷으로 남긴다. 동일 검토 revision에는
하나만 저장할 수 있고 기존 기록은 수정·삭제할 수 없다. 다른 유형으로 정정하려면 새 사람
검토 revision을 먼저 추가해야 한다. 선택자 표기는 인증된 신원이 아니다.

이 문서들은 현장의 승인된 SOP가 아니며 실제 생산품의 합격·폐기·설비 조치에 사용할 수
없다. 인용 원문을 보여주는 일과 그 문서가 실제 작업을 정당화하는 일은 다르다. 저장된
근거 다음의 승인 및 티켓 흐름은 [로컬 모의 워크플로우](mock-ticket-workflow.md)로만
구현했으며 실제 승인이나 외부 발행이 아니다.

2026-09-21 실제 등록 검사 1건의 사람 검토 revision 1에 `bent_lead`와
`DEMO-TR-BENT` 개정 2의 원문 스냅샷을 로컬 DB에 연결했다. 선택자 정보와 원문 관찰
내용은 Git에 넣지 않는다.

## 확인할 실패 조건

- 작업자 의견이 없거나 최신 의견이 `ANOMALY_VISIBLE`이 아님: 검색 비활성화.
- 유형 `UNKNOWN`, 다른 제품, 적용 시작 전·만료 후, 폐기 개정판: 결과 없음.
- 동일 제품·유형·날짜에 유효 개정판이 둘 이상: 모호성 오류, 결과 표시 금지.
- 문서 표시가 `simulation_only`가 아니거나 인용 절 ID/기간이 잘못됨: 로드 거부.
- 산출물 이미지 checksum 불일치 또는 검사 실패: 기존 검토 화면 단계에서 검색도 차단.
- 검색 후 다른 사람 검토가 추가됨: review revision 충돌로 저장 거부.
- 동일 review revision에 다른 유형·문서가 이미 연결됨: 덮어쓰기 거부.

인용 내용은 카탈로그의 해당 절과 문자 그대로 일치해야 한다. 원문에 없는 조치 문장은
검색 결과에 생성하지 않는다.

CLI 확인은 다음과 같다.

```sh
python scripts/review_inspections.py sop-history \
  --inspection-id <inspection_id>
```
