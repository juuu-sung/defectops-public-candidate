# MPI PatchCore 원특징 공간 대표 선정 비교

## 목적과 현재 상태

기존 전체 영역 통합 기준표와 같은 크기를 유지하되, 대표를 고르는 거리 공간만 바꾼다.
기존 369차원 투영 공간 대신 실제 검사에서 사용하는 768차원 원특징 공간에서 정상 대표를 고른다.
영역별 균등 할당, 같은 영역 검색 제한, 특징 정규화, 새 사진 추가를 함께 바꾸지 않는다.
이는 실행 준비이며 성능 개선 결과가 아니다. 기존 모델과 서비스·자동 합격 금지 정책은 유지한다.

[균등 배분 지도 검토](../reports/mpi-patchcore-balanced-map-review-v1-received-review.md)에서
새 오경보8건은 원점수와 보정 변화가 섞여 있었고, 하단 결함5영역은 GT 평균 감소·배경 평균 증가를 보였다.
균등 배분 후보는 비채택으로 보존한다. 투영이 원인이라고 확인된 것은 아니다.
이번 가설은 검사 거리와 같은 공간에서 대표를 고르면 정상의 충분한 대표성을 개선할 수 있는가이다.
greedy는 탐욕적 근사 선택이므로 최적 기준표나 모든 정상 거리 감소를 보장하지 않는다.
정상 변이를 잘 담으면 실제 결함 거리도 줄어들 수 있어 불량·위치를 반드시 같이 평가한다.

## 고정 조건

| 항목 | 직접 비교 기준선 | 새 후보 |
| --- | --- | --- |
| 정상 학습 | 고정256사진 ×12영역 | 동일 |
| 후보 | stride2 저장 원특징3,145,728개 ×768D | 동일 후보 전부 |
| 선택 거리 | 저장된369D 투영 특징의 L2 | 원특징768D의 L2 |
| 대표 수 | 78,643 | 78,643 |
| 영역별 할당 | 전역 greedy 결과 | 전역 greedy 결과, 강제 할당 없음 |
| 시작 참조점 | 기존 전역 start_index | 같은 인덱스, 재추첨 없음 |
| 추론 | 전체 bank 원특징 L2 검색, native FP32 지도 | 동일 |
| 개발·보정 | 정상256장·169장 | 동일 사진·산식, 새 모델 점수로 산출 |
| 평가 | 불량55·정상54·별도 정상256 | 동일, 기존12장 미달도 전체 비교 지속 |

초기 참조점까지의 최소거리를 계산한 후 가장 먼 후보를 첫 대표로 뽑는다. 초기 참조점 자체를 대표에 강제 포함하지 않는다.
이는 기존 선택 recurrence를 유지한 것이며 처음부터 임의 대표를 추가하지 않는다.
동률은 고정된 전역 행 순서의 첫 인덱스로 처리한다. 선택한 행을 다시 뽑는 경우 자동 대체하지 않고 중단한다.
신경망 역전파·특징 재추출·투영 재생성은 없다. 원본 RGB, 특징 캐시 및 기존 모델의 해시를 확인하고 재사용한다.
검증·오경보·실제 불량·GT를 선정 입력으로 받지 않는다. 자료 역할과 중복 분리는 기존 계약을 따른다.

## 계산 비용과 메모리

3,145,728 ×768 ×4바이트 = 정확히9GiB 원특징이다. 8GiB GPU에 전체를 올릴 수 없으므로 CPU 배열에 보관하고
65,536행씩 GPU로 전달한다. 특징 청크 하나는192MiB, 최소거리 배열은12MiB이며 중간 연산·모델·런타임 메모리는 별도다.
CPU 배열은 파일마다 채워 두 번째 전체 복사본을 만들지 않는다. 체크포인트에는 후보별 최소거리와 선택 인덱스를 저장한다.

**비용 경고: 9GiB ×78,643회 = 약691.20TiB 누적 CPU→GPU 전송이다.** 저장 공간 요구량이691TiB라는 뜻은 아니다.
첫25회 실제 전체 후보 스캔으로 남은 선정 시간의 선형 추정치를 표시하고 자동으로 이어간다.
수일이 걸릴 수 있으며 기존369D GPU상주 선택의 소요시간을 대입할 수 없다. 추정치는 보정·평가·재개 재계산 시간을 포함하지 않는다.
GPU판에서 실제 전송·메모리 비용을 아직 측정하지 않았다. 빠른 실행을 보장하거나 CPU 테스트를 GPU 성공으로 보고하지 않는다.

사용자 요청대로 경과시간 상한은 없다. 기존 RAM RSS20GiB·GPU reserved6GiB 상한과 시작GPU여유6GiB를 유지한다.
시작 디스크 여유10GiB가 필요하다. 메모리 부족 시 자동 정규화·후보 축소·FP16·투영 복귀·대표 수 변경을 하지 않는다.

## 한 실행의 단계와 재개

1. 기존 학습256·개발256 handoff와 실행 소스·모델·특징/투영 캐시·원본 지문을 검증한다. 투영은 이력 검증만 하며 후보 거리에는 쓰지 않는다.
2. 기존 정상8사진 재현 후 설치된 Anomalib의 원특징 거리 갱신과 분할 전송 계산을 3난수 ×3청크로 대조한다. 인덱스는 정확히 일치하고 최소거리 최대 절대차이는1e-5 이하여야 한다.
3. 정상 학습 후보만으로 전역 원특징 greedy78,643개를 선정한다. 매1,000개와 최종 시점에 체크포인트를 원자적으로 봉인한다.25개마다 진행 로그를 표시한다.
4. 기존 비기준표 텐서는 전부 유지하고, 저장한 bank의 각 행이 선택된 원래 특징과 정확히 일치하는지 검사한다.
5. 정상 개발256장의 영역 중앙값·Q90폭, 정상 보정169장의 사진Q95 higher 경고선을 고정한다. 별도 기존 계약을 덮어쓰지 않는다.
6. 저장 모델을 다시 불러와 정상425사진 전체 점수·판정을 확인한다. 최대 절대차이1e-4·판정 변경0을 요구한다.
7. 별도 프로세스에서 불량55·정상54/256 전부, 두 모델20정상 ×3회 warm속도, 전체 불량과 고점수 정상12사진의 지도·GT, 동일600회 정상 재표집을 비교한다.

Ctrl+C를 한 번 누르고 정리가 끝나면 같은 명령으로 마지막 봉인된1,000선택 지점부터 재개한다.
청크 중간까지 갱신된 거리는 저장하지 않는다. 최대999회와 중단된 회차는 다시 계산될 수 있다.
강제 종료·자원 초과·검산 오류는 자동 재시도하지 않는다. 오류와 모든 기존 출력을 보존한다. 실행 도중 git pull을 하지 않는다.

## 비교와 결정 기준

직접 기준선은 이전256학습·256개발 모델의 TP55, FP1/54·15/256이다. 과거64학습 Q90과 혼동하지 않는다.
55/55 검출 유지, 오경보≤2/54 및≤12/256을 그대로 적용한다. 같은600회 재표집에서 기존 안정성 기준을 유지하며 실패 반복을 제거하지 않는다.
결함 위치는 GT적합313타일의 사진별·영역별 AUROC/GT대비배경/상위656겹침을 함께 보고한다.
0006은 위치 통계에서만 제외하고 사진 검출에는 포함한다.0054는 기존 승인 복구 파일만 검증해서 사용한다.
위치 지표가 악화되거나 어느 목표라도 미달하면 자동 채택하지 않는다. 숫자 목표 통과도 운영 승인이나 독립 일반화 성능으로 해석하지 않는다.
대표 영역·사진별 분포는 결과로 보고하되 좋은 평가점수에 맞춰 몫이나 시작점을 재조정하지 않는다.
이번 자료는 이미 관찰한 탐색·회귀검증이다. 결과 확인 후 같은 시험에서 후보를 자동 추가하지 않는다.

## 연구실 실행과 전달

명령은 해당 변경이 연구실 저장소에 반영된 뒤 실행한다. 다른 GPU 작업은 정상 종료하고 수일 점유 가능성을 감안한다.

```powershell
Set-Location 'C:\개인 프로젝트\defectops'
git pull --ff-only
if ($LASTEXITCODE -ne 0) { throw 'Git update failed; stop here.' }
powershell.exe -NoProfile -ExecutionPolicy Bypass -File '.\scripts\run_mpi_patchcore_raw_bank.ps1'
```

완료 전달: `artifacts\handoff\mpi-patchcore-raw-bank-v1.zip`.
fit 완료 시 `mpi-patchcore-raw-bank-v1-fit.zip`도 남긴다. 모델·원본·전체 지도는 연구실에 보관하며 ZIP에는 계약·지문·선택·점수·비용·위치 통계를 담는다.

## 준비 검증 기록

연결된 신규·기존 검사49개 통과, CUDA 필요2개는 Mac에서 건너뛰었다.
전체 회귀 실행은1,216개 및52개 하위검사 통과·12개 건너뜀이었고, 그 실행 뒤 추가한 전체평가 지속 검사는 위49개 실행에 포함해 통과했다.
실제 전달된 두 handoff로 코호트256/256/169/256/109와 기존TP55·FP1/15를 재검산하고 고정 소스 지문이 유지됨을 확인했다.
PowerShell 및 실제 CUDA 실행은 미검증이다. 실행 시 공식 거리 갱신 대조를 먼저 통과해야 전체 선정으로 진행한다.
