# EfficientAD 저장 시점 비교: 입력·정상 외관·반응 추이

2026-10-04. 사용자 진행 동의에 따른 제한 진단이며 **새 학습·임곗값 조정·서비스 모델 교체가 아니다.**

## 질문과 현재 근거

최종70,000회 모델은 기존 검출12장을 모두 놓쳤다. 저장 지도20사례의 완전한 ZIP을 수령했고,
고반응 정상6장의 주반응이 노랑·주황 직사각형 부분 등에 집중됨을 관찰했다.
하지만 같은 외관이 있는 정상0469는 낮은 점수이며, 결함0048 등의 일부 위치에는 약한 반응이 남는다.
색 자체·학습 정상 부족·과적합 중 무엇이 원인인지 아직 확정할 수 없다.

이번에는 다음 세 질문을 묶어서 확인한다.

1. 학습과 추론에서 실제 RGB 입력 변환이 같은가?
2. 학습 정상64장의 전체12영역에는 어떤 외관이 있었는가?
3. 이미 저장한10,000·30,000·70,000회 모델의 같은 위치 반응이 어떻게 변하는가?

## 로컬 소스 감사 결과와 범위

학습의 `ProbeRuntime.tensor`와 추론의 `FinalRuntime.predict`는 RGB256×256을 요구하고
ToTensor로 CHW float32 0~1로 바꾼다. 이 입력 경로에는 추가 크기 변경·채널 교환·외부 ImageNet 정규화가 없다.
학습의 색 증강과 Imagenette 보조 입력 변환은 학습 손실 구성의 일부이지, 평가 사진에 적용할 전처리가 아니다.
teacher 통계 계산도 같은 tensor 경로를 사용한다.
[고정 Anomalib2.2.0 모델 소스](https://github.com/open-edge-platform/anomalib/blob/v2.2.0/src/anomalib/models/image/efficient_ad/torch_model.py)의
SmallPatchDescriptionNetwork 내부에서 ImageNet 정규화를 적용한다. 외부 정규화를 추가하면 중복 적용 위험이 있다.
현재 소스 검토만으로 입력 불일치를 발견하지 못했으며 이것이 전체 구현의 무결점 보장은 아니다.

실행 시 소프트웨어·Anomalib 소스 지문을 원래 fit 환경과 대조하고, 각 사진 첫 영역에서 역사적 학습 tensor 메서드와
현재 평가 ToTensor 및 독립 RGB/255 배열을 비교한다(20사진×3시점). 나머지 영역도 원본·픽셀 지문·RGB크기 검증을 거친다.
teacher 가중치와 정상 통계가 세 checkpoint에서 같은지 확인한다. 새 optimizer나 학습 호출은 없다.

## 고정 실행 계약

| 구분 | 범위 |
| --- | --- |
| 모델 | 기존 fit의10k·30k·70k checkpoint; 기존 receipt와 지문 일치 필수 |
| 순서 | 70k20사진 재현 통과 →10k20사진 →30k20사진 |
| 표본 | 지도 진단과 같은 불량12장+정상8장; 새 시험 이미지 없음 |
| 계산 | 20×12×3=720타일 추론, 두 원시 ST/AE 지도와 위치 통계 |
| 정상 외관 검토 | 기존 학습64×12=768타일, 영역별16사진씩4페이지, 총48장 모음 그림 |
| 지도 그림 | 원본·ST3시점·AE3시점,6영역/페이지, 총40페이지 |
| 색상 | ST/AE별0~최종 정상q995를 모든 사례·시점에 공통 사용; 표시만 포화 |
| 재현 허용 | 70k 원시지도·영역/사진 점수 최대절대차≤1e-4, 판정 변화0 |
| 자원 | 실행 누적1시간, RSS8GiB·GPU reserved6GiB; 축소·자동 재학습 없음 |
| 필요 공간 | 시작 시 여유5GiB, 모델 로드 시 GPU여유6GiB |

불량12장:0006,0025,0048,0000,0054,0051,0013,0033,0038,0001,0034,0042.
정상8장:개발1554·1531·1284, 보정1283·1275·1285·0217·0469.
0006은 기존 사진 전체 위치 통계 제외를 유지하며0054는 앞서 승인된 복구 타일만 검증·재사용한다.
높은 정상 점수로 선정한 사례라 전체 정상 오경보율을 계산할 표본이 아니다.

**10k·30k에는70k 경고선·지도 보정·영역 보정을 적용하지 않는다.** raw top656 mean·최대값·GT 위치 겹침은
진단 통계이며 경고 판정이 아니다. 그림 색상에 사용하는 최종 정상q995도 판정에는 쓰지 않는다.
낮은 raw 값만으로 우수한 checkpoint를 고르지 않는다. 이전 모델 채택은 별도 정상 보정과 회귀검사가 필요하다.

## 보존과 재개

원래 fit/evaluation 소스·모델·지도·경고 기준·handoff ZIP을 바꾸지 않는다.
새 결과는 `artifacts/analyses/mpi-efficientad-trajectory-v1`에 분리한다.
완료한 사진·그림은 receipt로 검증해 재사용하며 중간 폴더도 삭제하지 않는다.
Ctrl+C로 중단 기록까지 정상 저장됐으면 같은 명령으로 재개할 수 있다. 일반 오류·자원 초과나
강제 종료로 실행 비용 기록이 닫히지 않은 경우에는 검토가 필요하므로 결과를 삭제하지 말고 오류를 전달한다.
환경/지문 변경 역시 검토 없이 우회하지 않는다.
해시 확인과 ZIP 내보내기는1시간 계산 예산 밖이다. 시각 자료 생성·디스크 속도에 따라 소요시간이 달라지고 실제 시간은 미측정이다.

## 연구실 PowerShell

다른 GPU 작업을 정상 종료한 뒤 실행한다. 새 패키지 설치·새 데이터 다운로드는 없다.

```powershell
Set-Location 'C:\개인 프로젝트\defectops'
git pull --ff-only
if ($LASTEXITCODE -ne 0) { throw 'Git update failed; stop here.' }
powershell.exe -NoProfile -ExecutionPolicy Bypass -File '.\scripts\run_mpi_efficientad_trajectory.ps1'
```

완료 후 전달:

```text
C:\개인 프로젝트\defectops\artifacts\handoff\mpi-efficientad-trajectory-v1.zip
```

직접 보기:

```powershell
Start-Process '.\artifacts\analyses\mpi-efficientad-trajectory-v1\bundle\index.html'
```

ZIP은 요약JSON·계획·입력 감사·지도 지문·그림88장·HTML이다. 원시 지도와 가중치는 연구실에 남는다.
이미지는 MPI-PCB의 파생 시각 자료로 출처·가공 사실을 HTML에 표시하며 공개 저장소에 올리지 않는다.

## 결과를 받은 뒤 결정할 것

- 정상 반응이 학습 후반에 커지거나 결함 반응이 약해지는가? 동일 표본에서 방향을 확인하되 과적합을 단정하지 않는다.
- 정상64장에 관련 외관이 있더라도 색조·시점·명암 범위를 충분히 포함하는지는 별도 시각 검토가 필요하다.
- 입력 재현이 실패하면 성능 비교보다 구현 일관성부터 수정한다.
- 설명 가능한 단서가 없으면 동일 시험을 보고 checkpoint를 계속 바꾸지 않고 다음 단일 가설을 재설계한다.

현재는 실행 준비 단계이며 연구실 GPU 결과는 아직 없다. CPU 테스트와 실제 CUDA 결과를 구분한다.
