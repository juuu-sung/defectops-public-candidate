# 검사 입력의 판단 가능 여부 설계

2026-10-14. 독립 CPU 점검기를 구현했으며 서비스에는 적용하지 않는다. 입력에 검사할 정보가 없거나 충분한지 확인되지 않은 경우를 모델의 이상 경고와 별도로 기록한다. 기존 MPI 연구 결과와 transistor 검사 서비스를 바꾸지 않는다. 저장된 정상자료를 사용하는 점검기에 자동 합격이나 새로운 품질 면적 기준을 도입하지 않는다.

## 해결할 문제와 근거

데이터셋의 정상 라벨은 제품 결함 라벨이다. 모든 타일에서 필요한 검사 정보가 보인다는 인증은 아니다. 반대로 검은 부분이나 그림자가 있다는 이유만으로 제품 불량 또는 검사 불가를 확정할 수 없다.

[정상 외관 점검](mpi-normal-appearance-census-v1.md)의 전달물 `mpi-normal-appearance-census-v1.zip` SHA256은 `bbfb5c0fdd897a4cb7ca92183bf73b4cb13d00c29966171af4ec8bff949a4e59`이다. 고정 학습 정상 256장과 검증 정상 256장, 각 12타일의 기록에서 다음 차이를 확인했다.

| 관찰 | 학습 | 검증 | 해석 |
| --- | ---: | ---: | --- |
| 연결된 정확한 검은 영역을 포함하는 사진 | 19/256 | 13/256 | 검증에서 더 빈번하다는 설명은 아님 |
| 타일 최대 검은 면적 비율 | 38.30% | 100% | 관찰된 심한 정보 누락 범위가 다름 |
| grid1-2의 연결 검은 영역 포함 타일 | 0/256 | 2/256 | 특정 위치의 외관 차이이며 원인 확정은 아님 |

검증 0274/grid1-3은 RGB 전체가 0이고, 0274/grid1-2는 연결 검은 영역이 92.44%, 0276/grid4-1은 80.68%다. 뒤의 두 비율은 사례 설명이지 판단 기준이 아니다. 12타일은 겹칠 수 있어 타일 합계를 원본 고유 면적이나 독립 표본 수로 해석하지 않는다.

565개 내용 파일 해시, 6개 실행 소스 지문, 고정 명단과 6,144개 행의 집계가 일치했다. 첨부 원본 PNG 530개는 파일·RGB 해시와 검은 영역 통계를 직접 재계산했고, 32개 시트의 사진 512개는 원본 픽셀과 일치했다. 나머지 타일은 전체 원본 압축파일이 로컬에 없어 기록 검증 범위다. 현재 외관 점검에는 새 추론이 없다.

내부 부품 오경보 0147·0288·0335·0337과 관련된 원통형 부품 외관은 학습사진에도 있다. 충분한 특징 대표성이나 구체적인 부족 조건은 확인되지 않았다. 이 문제는 입력 누락과 분리하고 학습량을 자동 확대하지 않는다. [출처와 학습자료 검토](../reports/mpi-input-origin-and-training-coverage-review-2026-10-13.md).

## 현재 구현과 분리할 책임

- [입력 디코더](../src/defectops/padim_inspection.py)는 PNG, RGB, 크기, 용량을 검사한다. 현재 transistor 기본 크기는 1024×1024다.
- [검사 API](../src/defectops/inspection_api.py)는 입력·실행 오류를 `INSPECTION_FAILED`로 저장한다. 읽을 수 있는 이미지의 검사 가능 여부를 별도로 판정하지 않는다.
- 모델 출력은 `score >= threshold`이면 `REVIEW_REQUIRED`, 아니면 `PASS`다. `automatic_pass_allowed`는 항상 false이며 낮은 점수는 실제 합격이 아니다.
- [검토 저장소](../src/defectops/review_store.py)는 schema 1, transistor와 고정 점수 규칙을 검증한다. 여기에 MPI 입력 상태를 임의로 끼워 넣거나 기존 decision 값을 덮어쓰지 않는다.

MPI의 256×256 12타일 규칙은 독립 연구 프로필이다. transistor에 그대로 적용하지 않는다. 첫 점검기는 API·DB·SOP·승인·모의 티켓을 수정하지 않는 별도 산출물로 시작한다.

## 입력 상태와 모델 상태를 따로 기록

아래 이름은 새 점검 기록의 설계 값이다. 기존 inspection schema의 status와 decision을 변경하는 것이 아니다.

| 입력 상태 | 근거 | 기본 처리 |
| --- | --- | --- |
| NOT_ASSESSED | 점검 기록 또는 해당 품목의 입력 정책이 없음 | 적합으로 간주하지 않고 미점검 표시 |
| TECHNICAL_ERROR | 디코딩 실패, 파일 누락, 지문 불일치, 크기·형식 불일치 | 오류 보존, 모델 점수 생성 금지 |
| INSUFFICIENT_INFORMATION | 프로필에 필요한 타일의 전체 RGB가 0임을 확인 | 해당 타일의 정보 없음, 사진의 전체 요구 범위 확인 보류 |
| NEEDS_INPUT_REVIEW | 부분 검은 영역이나 사람의 가림 관찰 등으로 필요한 정보의 존재가 미확정 | 입력 검토 요청, 자동 정상 판정 금지 |
| NO_LISTED_ISSUE_DETECTED | 제한된 자동 점검에 걸리지 않음 | 검사 가능 보증 아님, 기존 모델·사람 검토 계속 |

한 사진의 여러 사유를 모두 보존하고 표시 우선순위만 기술 오류 → 정보 없음 → 입력 검토 필요 → 제한 점검 이상 없음으로 둔다. 점검되지 않은 필수 타일이 있으면 제한 점검 이상 없음으로 완료할 수 없다. NOT_ASSESSED를 정상이나 0점으로 변환하지 않는다.

MPI 초기 프로필은 기존 사진 점수 계산에 필요한 고정 12영역의 완전성을 확인한다. 한 타일 전체가 검으면 그 타일에는 검사 정보가 없다고 말할 수 있다. 그러나 겹치는 다른 타일에서도 같은 결함을 볼 수 없는지, 사진 전체의 모든 결함이 보이지 않는지까지 자동 확정하지 않는다. 중복 시야를 이용한 대체 검사는 별도 근거와 버전이 필요하다.

## 첫 CPU 점검의 확정 규칙

1. 원본 역할·명단·지문·12영역 완전성을 확인한다. 기술 오류는 누락시키거나 평균 통계에서 조용히 제거하지 않는다.
2. RGB 전체가 정확히 0인 필수 타일은 `ALL_ZERO_REQUIRED_TILE`로 기록한다. 검은 면적 50%·80%·90% 같은 임의 임계값은 사용하지 않는다. 파일 디코딩 성공과 시각 정보 존재는 다르다.
3. 기존 4방향 연결 규칙의 검은 영역이 1픽셀 이상이지만 전체 0은 아닌 타일은 `CONNECTED_ZERO_PRESENT`라는 관찰 사유와 NEEDS_INPUT_REVIEW를 기록한다. 이는 보수적인 검토 라우팅이며 검사 거부나 정보 손실 확정이 아니다. 작은 점·정상 배경 때문에 늘어난 검토 부담도 결과에 포함한다.
4. 연결 검은 영역이 없으면 NO_LISTED_ISSUE_DETECTED로 기록한다. 흐림, 반사, 근접 검은색, 잘못된 품목, 자연 가림은 이 규칙의 검출 범위 밖이다. 일반적인 입력 적합 판정으로 확대하지 않는다.
5. 현재 점수·지도·보정·모델은 읽기 전용 이력으로만 연결한다. 검증 오경보 목록이나 불량 점수를 입력 판단 규칙에 넣지 않는다. 새 추론·학습·복원·패딩·크롭은 하지 않는다.

이 규칙은 알려진 결과를 본 뒤 설계한 기술 점검이다. 같은 사례에서 성공해도 새로운 일반화 성능 증거는 아니다. 전부 검은 타일의 의미를 시험하는 인공 입력은 허용하지만 이미지 유효성의 통계적 검증을 대신하지 않는다.

## 사람이 확인할 질문과 처리

첫 화면은 원본과 영역 ID, 입력 관찰 사유를 보여준다. 입력 검토의 일차 기록 전에는 모델 점수·경고 여부를 숨겨 모델 판정에 끌려가지 않도록 한다. 검토 후 기존 모델 결과를 별도 칸에서 대조할 수 있다.

| 질문 | 남길 기록 |
| --- | --- |
| 검사해야 할 부품이나 위치가 무엇인가 | 품목별 요구 범위 또는 아직 정의되지 않았음 |
| 필요한 부위가 실제로 보이는가 | 관련 영역, 보이는 정보·누락된 정보, 근거 위치 |
| 검은 부분이 필요한 검사 정보를 가렸는가 | 확인됨 / 확인되지 않음 / 판단 불가와 이유 |
| 다음 행동은 무엇인가 | 다른 원본 요청, 입력 검토 완료 후 기존 검토 진행, 현재 자료로 판단 보류 |

사람 기록도 제품 합격·불량 판정과 분리한다. 검은 영역 없음은 사람 검토 생략 조건이 아니다. 필요한 검사 범위가 정의되지 않았으면 판단 불가를 허용한다. 검토자 간 의견이 다르면 불확실 상태를 유지하고 조정 근거를 추가한다. 완전히 검은 타일을 근거 없이 충분한 입력으로 덮어쓸 수 없다.

직접 촬영 불가 제약에서는 재촬영 성공을 전제하지 않는다. 대체 원본이 없으면 해당 범위는 판단 보류로 남는다. 이것은 검출 모델의 문제를 해결했다는 뜻이 아니다. 기존 입력은 삭제하지 않고, 대체 입력이 있다면 새 ID와 이전 ID 연결로 기록한다.

## 결과를 저장하고 표시하는 계약

첫 산출물은 원본·기존 검사 결과와 분리된 `input-assessment.json` 및 읽기 전용 검토 목록이다. 점검 기록은 다음을 포함한다.

- 기록 스키마 버전, 입력 정책 ID·버전·소스 해시, 점검 도구 버전
- 원본 파일·RGB 해시, 데이터 역할, 사진 ID, 12영역 ID와 순서
- 영역별 상태, 관찰 사유, 정확한 검은 면적·위치, 평가하지 않은 항목
- 사진 상태와 집계 사유, 실패 사유, 검사 시작·완료 시각
- 기존 모델 결과가 있으면 그 기록의 해시와 별도 참조; 없으면 null이며 0점으로 채우지 않음
- 사람 확인 기록은 append-only로 작성자·시각·개정·관련 요구 범위를 보존
- `automatic_pass_allowed=false`, 원본·모델·경고선 변경 없음

같은 입력 해시와 정책 버전의 반복 실행은 동일한 기술 관찰과 상태를 만들어야 한다. 실행 시각은 별도 기록한다. 다른 입력·정책을 기존 결과에 덮어쓰지 않는다. 중단 파일은 보존하고 완료 기록을 원자적으로 게시하며 손상된 부분 결과를 정상 완료로 읽지 않는다.

입력 보류와 모델 경고는 동시에 존재할 수 있다. 기존 결과가 있다면 보류 표시가 경고를 지우지 않는다. 기존 `PASS`는 화면에서 “모델 점수 기준 미만 · 합격 아님”으로 설명한다. 입력 보류 화면에 합격 배지나 조치 승인 버튼을 두지 않는다. 현재 API에는 이 UI 변경도 아직 적용하지 않는다.

미래 서비스 연결 시에는 schema 1을 소급 수정하지 않고 버전별 검증기·이관·되돌리기를 함께 설계한다. 과거 기록은 입력 미점검으로 표시하며, 새 스키마·아티팩트 조회·검토 저장·승인 조건의 회귀 테스트가 통과하기 전 자동 연결하지 않는다.

## 평가에서 보류를 숨기지 않는 규칙

기존 MPI 기준선의 불량 55/55, 시험 정상 오경보 0/54, 별도 정상 오경보 15/256은 그대로 보존한다. 입력 검토로 이동한 정상 경고를 기존 FP에서 빼거나, 보류된 불량을 TP로 계산하지 않는다. 정상 256장 중 입력 경고 사례와 모델 경고 사례를 교차 집계하되 탐색 결과로 명시한다.

| 보고 대상 | 분모와 의미 |
| --- | --- |
| 기존 모델 검출·오경보 | 원래 고정 불량·정상 명단 전체 유지 |
| 입력 점검 상태 | 원래 사진 수 전체, 영역 수는 별도; 상태별 합이 전체와 일치 |
| 모델 경고와 입력 상태의 교차표 | 경고·기준 미만·결과 없음 각각에서 입력 상태 표시 |
| 사람이 검토해야 하는 사진 | 입력 검토 필요와 모델 경고의 합집합; 중복 건 이중 집계 금지 |
| 입력 처리 후 분석 가능 비율 | 보류·오류를 포함한 전체 요청을 분모로 두고 탈락 이유 표시 |
| 보류 사례의 불량 수 | 기존 라벨과 입력 상태의 관계로 보고; 검출 성공으로 합산하지 않음 |

통과한 입력만의 성적을 추가로 계산하면 선택된 부분집합임을 표시하고 전체 결과를 나란히 둔다. 새로운 정책의 성능 주장은 적합성 요구사항, 모델 점수를 보지 않은 사람의 입력 판단, 독립 평가 자료가 있어야 가능하다. 현재 512장의 회귀 검토로 그 주장을 하지 않는다.

## 구현 순서와 완료 조건

| 단계 | 작업 | 완료 조건 |
| --- | --- | --- |
| 1 이번 설계 | 입력·모델·제품 판단 분리, 규칙·한계·분모 확정 | 기존 모델 성적과 서비스 변경 없이 문서화 |
| 2 독립 CPU 점검기 | 고정 학습·검증 512사진의 6,144타일 기록, 필요한 원본 검증, 상태·교차표·검토 목록 생성 | 정상 종료, 지문·명단 일치, 반복 일치, 모델·원본 변경 없음 |
| 3 제한 사람 검토 | 입력 사유가 있는 사진 전체와 규칙에 걸리지 않는 고정 비교 사례 확인 | 필요한 검사 범위와 판단 불가 이유 기록; 모델 개선과 혼동하지 않음 |
| 4 도입 여부 판단 | 입력 경고의 타당성·검토 부담과 기존 검출 문제를 별도 판단 | 근거 부족 시 연구 기록으로 종료; 충분할 때만 서비스 통합 별도 승인 |

단계 2에서는 현재 명단을 유지한다. 전체 검증자료에 적용하므로 특정 오경보 사진만 골라 규칙을 시험하지 않는다. 원본이 첨부되지 않은 타일까지 검증하려면 연구실의 고정 `extracted.zip`을 CPU로 읽는다. GPU 모델은 필요 없다. 현재 구현은 아래 두 실행 범위를 명시적으로 분리한다.

## 실행 방법과 검증 범위

[CPU 점검기](../scripts/assess_mpi_normal_inputs.py)는 고정 외관 점검 ZIP과 원특징 모델 결과 ZIP을 받는다. 기본 경로는 프로젝트의 `artifacts/handoff/mpi-normal-appearance-census-v1.zip`과 `mpi-patchcore-raw-bank-v1.zip`이며, CLI의 `--census`, `--baseline`으로 위치만 지정할 수 있다. 내용 해시는 고정되어 임의 입력으로 바꿀 수 없다.

- 기본 `records` 실행: 6,144개 고정 기록으로 512사진을 분류하고 첨부 원본만 픽셀 재검산한다. 각 타일에 픽셀 재검산 여부를 표시한다. 전체 원본을 새로 읽었다고 주장하지 않는다. 기존 모델은 저장된 점수로만 재계산·대조하며 학습사진의 미제공 모델 결과는 null이다.
- `archive` 실행: 같은 분류에 더해 원본 아카이브 지문과 6,144개 정상 타일의 픽셀·통계를 모두 확인한다. 입력 사유가 있는 타일의 원본도 검토 목록에 포함한다. 시험 이미지와 마스크는 읽지 않는다.

두 모드는 별도의 출력 경로를 사용하며 혼용하지 않는다. 저장 기록 기반 분류는 CPU 점검의 부분 완료이며, 전체 원본 재검산은 선택한 모드의 실제 실행 결과로만 확인한다. 입력 판단 규칙이나 점수는 모드에 따라 달라지지 않는다.

```powershell
Set-Location 'C:\개인 프로젝트\defectops'
# 저장된 기록 기반 분류
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\run_mpi_normal_input_assessment.ps1
# 전체 원본 픽셀까지 검증할 때만 실행
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\run_mpi_normal_input_assessment.ps1 -VerifyArchive
```

결과는 `artifacts/analyses/mpi-normal-input-assessment-v1-records/review/index.html`과 `artifacts/handoff/mpi-normal-input-assessment-v1-records.zip`이다. 전체 원본 모드는 경로의 `records`가 `archive`로 바뀐다. 소스 배포 여부는 실제 GitHub 업로드 확인과 구분한다.

첫 페이지와 사례 페이지는 모델 점수를 숨기고 입력 관찰만 제공한다. 모델 대조는 별도 페이지에서 열 수 있다. 이는 검토 순서를 돕는 구성이며 강제 맹검·권한 통제가 아니다. 사람 의견 저장·승인·티켓 기능은 구현하지 않으며 모든 사람 판단은 NOT_RECORDED로 남긴다. 입력 자체가 누락되거나 무결성이 깨지면 TECHNICAL_ERROR 실행 실패 기록을 남기고 분류 완료를 게시하지 않는다.

같은 소스·입력으로 다시 실행하면 동일 내용인지 검산하며 기존 ZIP을 보존한다. 중단 단계와 실패 기록은 삭제하지 않는다. 소스가 변경됐거나 기존 결과가 훼손됐으면 덮어쓰지 않고 중단한다. 시작·완료 시각은 단계 영수증에, 실패 시각은 별도 실패 기록에 남긴다. 원본·이미지 목록을 GitHub에 올리지 않는다.

## 필수 회귀 검증

필수 회귀 사례는 다음과 같다.

- 읽을 수 없는 PNG·해시 불일치·필수 타일 누락·다른 품목 프로필은 기술 오류로 끝나며 PASS나 점수 0을 만들지 않는다.
- 전체 검은 필수 타일은 정보 없음이다. 작은 검은 조각은 입력 검토 필요이지 정보 없음이 아니다.
- RGB가 1인 어두운 영상과 흐린 영상은 정확한 0 검사의 범위 밖임을 표시한다. 규칙에 걸리지 않았다는 이유로 입력 적합으로 판정하지 않는다.
- 입력 보류와 기존 모델 경고가 함께 있으면 둘 다 보존한다. 기존 기준 미만도 합격으로 바꾸지 않는다.
- 타일 중첩, 같은 사진의 12영역, 입력 경고·모델 경고의 중복이 사진 수를 부풀리지 않는다.
- 정책 변경·재실행·중단·재개·검토 개정은 이력을 유지하며 이전 승인을 새 입력에 재사용하지 않는다.
- 기존 15건의 FP를 그대로 재현하고 입력 상태만 추가한다. 보류를 FP 감소나 TP 증가로 보고하는 경로는 테스트에서 실패해야 한다.

내부 부품의 정상 외관 오경보와 정상 보정 불안정은 별도 미해결 과제로 유지한다. 입력 점검이 성공해도 모델 후보의 운영 승인이 되지 않는다.
