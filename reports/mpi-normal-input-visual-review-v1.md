## 필수 검사 범위로 정할 수 있는 것과 없는 것

현재 저장소의 [MPI 시험 계약](../docs/mpi-pcb-external-stress-test.md)과 [입력 점검 설계](../docs/inspection-input-assessability-v1.md)는 모델이 받는 12영역과 입력 형식을 정한다. 이것을 실제 기판의 승인된 검사 사양으로 확대하지 않는다.

| 항목 | 현재 정할 수 있는 범위 | 아직 정할 수 없는 범위 |
| --- | --- | --- |
| 입력 완전성 | 같은 사진 ID의 12영역, 각 RGB 256×256, 파일·픽셀 지문 일치 | 기판의 모든 필수 부위가 12영역에 충분히 담겼다는 보증 |
| 타일 정보 존재 | 전체 RGB가 0이면 해당 타일 자체의 영상 정보 없음 | 다른 타일의 중복 시야가 그 부위를 대체한다는 판단 |
| 부분 검은 영역 | 위치와 픽셀 수를 관찰로 기록하고 검토 사유 제공 | 일정 면적 이상이면 무조건 부적합이라는 새 규칙 |
| 부품 가시성 | 첨부 영상에서 보이는 커넥터·칩 등의 외형 기술 | 필수 부품 번호·필수 접합부·검사해야 할 미세 결함 범위 |
| 선명도와 배율 | 검토 시 흐림 등 추가 의문을 별도 메모 | 결함 최소 크기에 근거한 허용 흐림·해상도·반사 기준 |
| 처리 결과 | 입력 확인 상태, 모델 경고, 사람 검토를 분리 | 제품 합격, 생산 승인, 자동 검사 제외 |

필수 부품·검사 위치 목록, 허용 결함 크기와 촬영 조건, 중복 시야의 좌표·대체 규칙이 현재 검토 근거에는 없다. 따라서 부품별 검사 가능 여부는 판단 불가로 남긴다. 직접 촬영이 불가능한 상황에서 대체 원본 확보나 재촬영 성공을 전제로 다음 단계를 잡지 않는다.

## 입력 확인과 모델 오경보를 분리한 결론

| 검증 입력 상태 | 모델 경고 | 경고선 미만 | 합계 |
| --- | ---: | ---: | ---: |
| 필수 타일 정보 없음 | 1 | 0 | 1 |
| 부분 검은 영역 확인 필요 | 3 | 9 | 12 |
| 제한 규칙 이상 없음 | 11 | 232 | 243 |
| 합계 | 15 | 241 | 256 |

기존 경고 15장과 입력 확인 13장의 중복은 4장, 합집합은 24장이다. 검증 정상 256장 중 우선 확인 목록이 15장에서 24장으로 9장 늘어나는 셈이지, 9개의 불량을 추가로 검출한 것이 아니다. 나머지 사진도 자동 합격이 아니다.

입력 사유와 모델 경고가 함께 있는 사진은 0274·0275·0276·0656이다. 이 네 건도 모델 오경보 집계에서 제거하지 않는다. 나머지 오경보 11건은 이번 정확한 검은 픽셀 규칙으로 설명되지 않으며, 입력 품질이 완전히 정상임을 인증받은 것도 아니다. 모델의 정상 외관 구분 문제와 보정 불안정은 그대로 남는다.

현재 고정 모델의 관찰 데이터 성적은 불량 55/55 검출, 시험 정상 오경보 0/54, 별도 정상 오경보 15/256이다. 이번에는 새 모델 실행이 아니라 저장 결과 대조만 했다. [이전 출처·대표성 검토](mpi-input-origin-and-training-coverage-review-2026-10-13.md)의 내부 부품 0147·0288·0335·0337 문제는 이 입력 점검과 별개다.

## 이번 단계의 완료 범위와 다음 개발

완료한 것은 32사진의 관찰 정리, 입력 요구사항과 제품 요구사항의 분리, 기존 성적을 보존한 해석이다. 작업자 검토 완료나 입력 적합 판정 정책 검증을 의미하지 않는다. 원래 설계의 규칙 비해당 고정 대조군을 포함한 사람 검토와 승인된 요구 범위 확인은 아직 완료하지 않았다. 이 근거로 독립 입력 점검기를 서비스의 거부·합격 규칙으로 연결하지 않는다.

이번 검은 영역 원본 점검은 연구 기록으로 마무리한다. 같은 32장을 다시 계산하거나 면적 임계값을 탐색하기 위한 연구실 작업은 추가하지 않는다. 기존 학습자료를 삭제·교체하거나 검은 부분을 잘라내고 모델을 재학습하지 않는다.

다음 개발은 모델 변경보다 **입력 관찰과 모델 결과를 함께 확인하고 사람의 판단 근거를 저장하는 검토 기능**으로 좁히는 것을 권한다. 현재 읽기 전용 목록은 의견을 저장하지 않는다. 구현한다면 별도의 연구 검토 기록으로 시작하고, 최소한 다음 구분을 지켜야 한다.

- 관찰: 관련 사진·타일과 보이는 사실. AI 작성 메모와 작업자 기록의 작성 주체를 구분한다.
- 요구 범위: 근거 문서 또는 미정. 근거 없이 임의 부품 목록을 필수 범위로 확정하지 않는다.
- 검토 결과: 확인됨·확인되지 않음·판단 불가를 질문과 함께 기록한다. 제품 PASS와 혼동하지 않는다.
- 이력: 입력 해시, 정책 버전, 작성자, 시각, 개정 연결을 보존하고 원본 점검 기록을 덮어쓰지 않는다.
- 모델 경고: 별도 필드로 유지하며 입력 메모 변경으로 기존 경고·FP·승인이 사라지지 않게 한다.

이 기능은 현재 턴에서 구현하거나 서비스에 적용하지 않았다. 모델 개선 연구를 다시 시작할 때는 11건의 잔여 오경보에 관한 기존 근거에서 검증 가능한 가설과 비교·종료 조건을 먼저 선택한다. 입력 검토 완료 자체를 새 GPU 실험의 근거로 삼지 않는다.
