# MPI 최근접 3개 사전 검사 결과와 종료 판단

2026-10-03 수령 검토. 실행은 정상 완료됐지만 기존 검출 12장 중 2장을 놓쳐 사전 검사를 실패했다.
**이번 고정 후보는 종료하고 전체 비교로 확대하지 않는다.** 기존 Q90과 서비스는 그대로 보존한다.
이는 모든 최근접 평균 방식이 불가능하다는 결론이 아니라 이번 bank·표현·보정 조합의 회귀 실패다.

마스크·새 독립 시험은 읽지 않았고 재학습·서비스 교체·자동 합격은 없었다.

## 왜 두 장을 놓쳤는가

두 사례의 가장 높은 보정 점수는 모두 grid3-2에서 나왔다. 아래는 이 영역의 원점수와
각 방식에 해당하는 경고 경계를 비교한 것이다. 후보에 기존 숫자 임곗값을 적용한 결과가 아니다.

| 항목 | 기존 최근접1 | 최근접3 평균 |
| --- | --- | --- |
| 영역 원점수 경고 경계 | 41.695899 | 43.944019 |
| 0025 원점수 | 42.464778, 경고 | 43.082985, 경고 안 됨 |
| 0034 원점수 | 43.098305, 경고 | 43.609999, 경고 안 됨 |
| 영역 정상 중앙값 | 34.100687 | 35.160980 |
| 영역 정상 Q90 폭 | 3.278092 | 3.637584 |
| 보정된 사진 경고 임곗값 | 2.316961 | 2.414525 |

불량의 원점수가 감소해서 실패한 것은 아니다. 0025는0.618207, 0034는0.511694 상승했지만
정상 기준의 변화로 경고 경계가2.248120 상승했다. 정상 대비 경고 여유가 줄어든 것이다.
고정12장 전부에서 보정된 사진 점수와 임곗값 사이의 여유가 감소했다.

임곗값을 결정한 정상 사진도1365의 grid1-1에서1644의 grid4-3으로 바뀌었다.
1644의 grid4-3 원점수는47.260020→48.565209, 보정 사진 점수는2.084239→2.414525다.
기존1365는 후보 사진 점수2.350897로 새 임곗값 아래다. 이는 같은 정상 자료도 거리 계산이
바뀌면 순위·보정값이 바뀐다는 근거이며, 1644가 오염 또는 잘못된 정상이라고 판정하는 근거는 아니다.

경계 `중앙값 + 폭 × 사진 임곗값`의 증가를 중앙값→폭→임곗값 순서로 대입하면
1.060293 + 0.832929 + 0.354898 = 2.248120이다. 계산 경로를 설명하는 고정 순서 분해이며,
세 요인의 독립적인 인과 기여 추정이 아니다. 한 정상 사진이나 임곗값만 탓해 제외·하향하지 않는다.

이번 JSON에는 후보의 패치별 거리·출처·지도가 없다. 왜 특정 정상 패치의 거리가 더 크게
변했는지까지는 확정할 수 없다. 특징 크기는 보존했지만 정상과 불량의 상대적 분리가 개선됐다는
근거를 얻지 못했고 기존 검출 보존 조건을 실패했다.

## 파일과 수치 검증

- ZIP9개 파일, 중복·경로 이상 없음, CRC 정상. 기록된 payload8개 SHA256 일치.
- 계획·정책·표본 목록을 현재 고정 실행기와 대조해 일치. 소스·설계133개 해시 일치.
- 사진309개 receipt, 입력 사진 지문, 점수 JSON 지문, 실행 환경과 런타임 gate1개 연결 확인.
- 정상128장 중앙값·Q90과 정상169장 Q95를 별도 전체정렬로 재계산해 계약과 정확히 일치.
- 12장 사진 점수·최대 영역·판정을 별도 산술로 재계산해 보고서와 정확히 일치.
- 원 bank 지문은 기존 값과 일치하며 정규화·대표 재선정 없음. 309장 native 이미지 점수도 대조 점수와 동일.
- 원본 압축파일·checkpoint 실물·CUDA 텐서를 Mac에서 다시 실행한 것은 아니다. 실제 장치 기록과 전달 점수 검산을 구분한다.

세부 기계 판독 기록은 [검산 JSON](mpi-knn3-screen-v1-verification.json)에 보관한다.
수령 ZIP SHA256: `932b2b7ccb5841ab624ad656739ad7c75ea7029a3159a7bd6157077d83de0db6`.

## 비용과 해석 범위

샘플링 프로세스 RAM peak2.149GiB, PyTorch allocated peak2.667GiB, reserved peak2.916GiB다.
장치 전체 사용량 샘플 peak4.052GiB는 이 프로세스만의 점유가 아니다. 누적1시간·RSS20GiB·reserved6GiB 상한 내다.
실행466.530초는 로딩·원 모델 재현·양쪽 점수 계산·캐시 저장·해제를 포함하고 입력 해싱·최종 ZIP 생성은 제외한다.
정식 warm 지연시간 비교 결과가 아니다. 후보 재로딩은 실패가 아니라 **사전 검사에서 중단되어 미실행**이다.

## 결정과 다음 단계

최근접3 후보는 사전 규칙대로 종료한다. 전체 시험109장·정상256장·민감도 재표집을 추가하지 않는다.
최근접 개수를2·5 등으로 바꾸거나 두 사례를 통과하도록 임곗값을 낮추는 후속 실행도 승인·준비하지 않았다.

현재 저장 점수로 가능한 원점수·정상 보정의 분리 확인은 위에서 완료했다. 같은 확인을 위해
연구실 GPU 작업을 다시 요청할 필요는 없다. 다음은 누적 결과를 반영한 설계 재점검이다.
새 후보는 기존 미탐2장과 정상 오경보·보정 불안정을 함께 다룰 가설과 근거를 제시하고,
이미 실패한 점수 공식의 단순 변형인지 확인한 뒤에만 한 개를 선정한다. 이 문서는 새 후보를 선정한 것이 아니다.
현재 연구실 추가 명령은 없다. 실행기와 동결 실험 설계는 변경하지 않았다.
