# EfficientAD 고정 모델 검증 준비 결과

2026-10-04. 사용자 요청으로 모델 비교를 노션에 정리하고, 연구실 검증 실행기를 준비했다.
실제 검출률·GPU 속도·보정 민감도 결과는 아직 없다. 실행 준비와 모델 성능 통과를 구분한다.

## 이번 구현

- 수령한70,000회 최종 모델·원시 정상 지도·보정 계약의 실물 해시와 receipt를 확인한다.
- 정상8사진 재현을 먼저 통과해야 고정12불량을 읽는다. 승인된0054 복구 이미지도12장 밖이므로
  12/12 통과 후에만 디코딩한다. 마스크는 읽지 않는다.
- 12장 통과 시 전체109+256사진을 비교하고, 두 모델의 같은 정상20사진×3회 warm 시간을 측정한다.
- 성적·후보 속도 통과 시600회 paired 정상 재표집으로 지도 분위수부터 다시 보정한다.
  독립 성능 검증이 아니라 관찰 자료의 보정 민감도다. 이전3,000회 요약을 대신 쓰지 않는다.
- 최종 checkpoint 고정, 재학습·지도 clipping·임곗값 튜닝·자동 PASS·서비스 교체 없음.
- 사진·단계·재표집 회차별 원자적 저장, Ctrl+C 재개, 미완료 강제 종료·자원 실패의 자동 재시도 금지.
- 누적4시간·reserved6GiB·RSS20GiB 상한. 계산 범위와 입력 해싱·내보내기 제외를 기록한다.
- JSON만 전달하며 원시 지도·모델·제품 이미지는 연구실에 남긴다.

## 검증 근거

- 전체 테스트:722개 및52 subtest 통과. 의존성 경고1종과 기존 중복 ZIP 거부 시험 경고가 있었다.
- 새 실행기 테스트21개: signed score·경계값 포함, 고정12장 실패 시 추가 시험/0054 미접근,
  전체 확대·성적/속도 실패 시 민감도 생략, cache 변조·identity 변조·runtime gate 변조 거부,
  Ctrl+C 재개, 강제 종료·자원 상한 실패 보존, warm 표본 순서, whole-photo paired 재표집,
  지도 분위수 재계산·bootstrap 회차 재개, additive 안정성 폭 조건을 확인했다.
- 전체 시험 이후0054 복구 접근 순서를 강화하고 새 실행기21개 테스트를 다시 통과했다.
- 실제 수령 fit ZIP과 기존 비교 ZIP으로 정책·정상128/169 사진 순서·픽셀 지문 연결을 대조했다.
- 과거 학습 소스137개 해시는 모두 그대로다. 정상 계약 재계산 일치, 기준선 전체 점수 재현 차이0,
  TP53/FN2/FP54=3/FP256=14를 재확인했다.
- 실행 CLI 도움말과 diff 공백 검사 통과. Mac에는 torch/CUDA와 PowerShell이 없어 실제 Windows
  모델 로딩·GPU·PowerShell 실행은 하지 않았다. CPU 대역 시험을 그 증거로 대체하지 않는다.

## 연구실 전달

[실행 명령과 범위](../docs/mpi-efficientad-evaluation-v1.md)를 따른다.
실행 결과는 `artifacts/handoff/mpi-efficientad-evaluation-v1.zip`으로 받는다.
12장 또는 전체 성능 gate가 실패해도 정상적으로 내보낸 ZIP을 검토한다. 실행 오류는 파일을
지우거나 재학습하지 말고 메시지를 전달한다. 어떤 결과든 자동 서비스 채택은 하지 않는다.
