# MPI 모델 누적 결과와 다음 설계

기준일: 2026-10-03. 상태: **설계 검토 완료, EfficientAD-S 실행 가능성 점검을 다음 우선안으로 제안한다. 새 학습은 미실행이다.**

기존 Q90 연구 기준선과 transistor 서비스는 유지한다. 이번 검토는 누적 실패를 다시 설명하기 위한 GPU 재실행이 아니라, 다음 실험에서 무엇을 달리 검증할지 결정하는 작업이다. 보조 데이터 취득과 새로운 신경망 학습은 아직 승인·실행하지 않았다.

### 잔여 미탐은 신호가 전혀 없는 문제가 아니다

기준선 미탐0019·0024의 주요 영역 grid3-2 원점수는41.5497·41.0007이며, 해당 영역의 경고 경계는41.6959다. 선택 사례에서는 결함 위치에 반응하지만 사진 경고 기준에는 못 미쳤다. 다른 정답 영역의 반응까지 모두 충분하다는 뜻은 아니다.

그 경계를 사후에 낮추면 두 사진을 잡을 수 있으나 정상 오경보가3→7/54, 14→19/256으로 늘어난다. 따라서 두 사진에 맞춘 임곗값 조정은 해결책으로 채택하지 않는다. [잔여 미탐 지도 근거](mpi-spatial-miss-review-v1-received-review.md)

정상 사진에서도 커넥터·핀·부품 외관과 일부 검은 테두리가 높은 점수를 만든다. 단순 배경 제거만으로 해결된다는 근거는 없다. 높은 정상 점수를 이유로 사진을 제외하거나 실제 부품을 가리는 규칙을 만들지 않는다. [정상 지도 근거](mpi-normal-map-review-v1-received-review.md)

### 다음 질문을 바꿔야 한다

지금까지의 여러 후보는 같은 특징·지도에서 경고를 계산하는 방법을 주로 바꿨다. 최근접3도 불량 점수는 올랐지만 정상 기준이 더 올라 기존 검출을 잃었다. 따라서 다음 질문은 **“점수를 어떻게 다시 보정할까”보다 “정상 변화와 결함의 점수 분리를 다른 학습 방식으로 개선할 수 있을까”**다.

이는 설계 판단이지 특징 추출기가 유일한 원인이라는 증명은 아니다. 정상 표본 부족, 촬영 변화, 타일 구조, 보정 민감도가 함께 작용할 수 있다. 기존 Q90도 정상128장 재표집 시 검출 수2.5–97.5백분위4–55장으로 민감했다. 이는 미래 검출률 신뢰구간이 아니라 보정 표본에 대한 민감도다.

## 2. 대안을 비교한 결정

| 대안 | 확인할 수 있는 질문 | 제약 | 이번 우선순위 |
| --- | --- | --- | --- |
| k값·정상 폭·임곗값 추가 탐색 | 기존 점수 변환만으로 개선되는가 | 반복된 검출 손실, 관찰 자료 과적합 위험 | 추가하지 않음 |
| 모든 정상 패치 보존·검색 분할 | 패치 축약 때문에 정상 참조가 부족한가 | 메모리·검색 비용 증가. bank 확대는 정상뿐 아니라 불량 거리도 낮출 수 있음 | 보류 |
| 영역별 PaDiM | 위치별 정상 분포가 더 적절한가 | 영역마다 정상64개. 예를 들어100차원 표본 공분산의 rank는 최대63이며 규제·차원 선택이 중요 | 대안으로 보존, 동시 실행하지 않음 |
| EfficientAD-S | 정상 특징을 예측하도록 학습하면 정상 변화와 결함을 더 잘 구분하는가 | 새 학습·보조 데이터·별도 지도 보정·seed 민감도 확인 필요 | 실행 가능성 점검 우선안 |

PaDiM은 사전학습 특징의 다변량 정상 분포를 사용한다. 기존 MVTec PaDiM 코드가 있어도 MPI의 영역 처리·데이터 계약을 그대로 해결해 주지는 않는다. [PaDiM 원 논문](https://arxiv.org/abs/2011.08785)

EfficientAD는 고정 teacher의 정상 특징을 student가 예측하도록 학습하고 autoencoder 경로도 사용한다. 정상 패치 bank의 최근접 검색과 다른 방식이다. 이는 비교할 가치의 근거이지 MPI 성능 우위의 근거는 아니다. 논문의 다른 장비 지연시간을 RTX5060의12영역 응답 시간으로 대입하지 않는다. [EfficientAD 원 논문](https://arxiv.org/abs/2303.14535)

이 비교는 **알고리즘 파이프라인 교체 실험**이다. 특징 추출기와 학습·지도 생성까지 바뀌므로 단일 요인의 인과 효과로 주장하지 않는다. 대신 MPI 명단·입력 크기·사진 단위·평가 자료·비용 측정 범위를 고정한다.

## 3. EfficientAD-S 설계 초안

### 입력과 학습

- 기존 원본 정상64장 ×12영역 =768타일만 제품 학습에 사용한다. 원래 명단을 유지하며 다양성 후보의 다른64장을 섞지 않는다.
- 입력256×256, 모델1개가12영역 타일을 공유한다. 영역별12모델·해상도 확대·추가 정상 수 확대는 동시에 하지 않는다. 여러 영역을 함께 학습하는 어려움은 남는다.
- teacher는 고정하고 student와 autoencoder를 학습한다. seed42, 모델 크기S, batch1을 초기 단일 후보로 제안한다. 학습 횟수는 자원 점검 뒤 시험 결과를 보기 전에 고정한다.
- 보조 Imagenette는 제품 정상 자료나 MPI 시험 자료가 아니다. 표준 학습의 보조 손실에 쓰이는 별도 외부 자료이며 취득·이용조건·해시를 확인해야 한다. 현재 다운로드하지 않았다.
- 기존 PatchCore의 ImageNet 정규화를 그대로 붙이지 않는다. 지정 버전의 전처리와 지도 크기·보간 계약을 테스트로 고정한다.

### 보정과 판정

- 정상128장만 EfficientAD 두 지도 경로의 정상화와 영역 척도 계산에 사용한다. 두 용도를 공유한다는 점을 기록하며 독립 검증 자료라고 부르지 않는다.
- 초기 비교 제안은 top1% 평균 → 영역 median/Q90 간격 → 사진12영역 최대를 유지한다. 별도 정상169장으로 사진 임곗값을 다시 계산한다. 기존 숫자2.316961을 새 모델에 그대로 적용하지 않는다.
- 모델 내부 지도 정규화의 Q90/Q99.5와 기존 영역 점수 Q90을 구분해 저장한다. 지도 정규화 표본 추출은 결정적으로 고정한다.
- 기본 데이터 모듈의 시험→검증 자동 분할 및 정답을 사용하는 자동 임곗값 선택은 사용하지 않는다. checkpoint는 고정 학습 종료점으로 선택하며 시험 성적이 좋은 epoch를 고르지 않는다.
- 정상128장의 민감도를 확인할 때는 지도 정상화와 영역 척도를 함께 다시 계산해야 한다. 기존 최종 점수만 재표집하는 도구를 그대로 쓰면 불확실성을 빠뜨린다. 이를 위해 두 경로의 보정 전 지도를 보존한다.

구현 근거: [Anomalib v2.2.0 학습·보정 코드](https://github.com/open-edge-platform/anomalib/blob/v2.2.0/src/anomalib/models/image/efficient_ad/lightning_model.py), [모델 코드](https://github.com/open-edge-platform/anomalib/blob/v2.2.0/src/anomalib/models/image/efficient_ad/torch_model.py). 현재 연구실 설치 버전 기준이며 향후 최신 버전으로 자동 교체하지 않는다.

## 4. 한 번의 제한 비교로 진행한다

아래는 **제안된 실행 조건**이며 새 실행기·학습 승인이 완료됐다는 뜻이 아니다. 이번에는 설계까지 완료했다.

| 단계 | 수행 내용과 담당 | 다음 단계 조건 |
| --- | --- | --- |
| D0 설계와 의존성 | Codex: 누적 근거·공식 구현·데이터 역할·대안 비교 | 이번 문서 완료. 보조 데이터 취득과 새 학습 범위 동의 필요 |
| D1 실행기 준비 | Codex: 버전·해시·전처리·normal-only loader·저장/재개·실패 보존 테스트, 단일 Windows 진입점 | 테스트와 별도 출력 경로 확인. 자동 다운로드·전체 학습은 기본 금지 |
| D2 짧은 자원 점검 | Windows: 정상 학습 명단에서 고정8사진×12영역, optimizer100step 이내 | 15분 상한, RSS20GiB·PyTorch reserved6GiB 상한 제안. finite loss/gradient·저장/재개·추론 확인. 불량 미사용 |
| D3 고정 학습과 정상 보정 | Windows: 새 디렉터리에서 정상64장 학습,128/169장 보정 | D2 시간으로 fit+보정4시간 이내 가능성 확인 후 학습 step·학습률 일정을 잠금. 표준 설정을 예산 때문에 자동 축소하지 않음 |
| D4 고정 회귀 검사 | Windows: 기존12장 사전 검사, 통과 시 기존109장·정상256장 비교 | 12/12 유지 못 하면 중단. 통과는 성능 입증 아님. 같은 자료에서 재튜닝하지 않음 |
| D5 안정성과 비용 | Codex/Windows: paired 결과, 정상 재표집, 추가seed, 단계별 시간·메모리 | D4 성적 조건 통과 후만 실행. 안정성 수치 조건과 seed 개수는 D3 전에 잠금; 미정 상태로 학습 시작 금지 |
| D6 결론 | Codex: 채택/비채택·한계·근거 정리 | 한 후보로 이번 비교 종료. 실패하면 k·epoch·해상도 변형을 자동 추가하지 않음 |

D2는 비용·호환성 검사다.100step으로 모델 성능을 평가하거나 전체 학습 시간을 확정하지 않는다. 다운로드 시간, 초기 teacher 통계와 지도 보정 비용을 별도 합산하고 실행 중 상한도 감시한다. 중단 시 학습 횟수·표본 수를 조용히 바꾸지 않는다. D2 checkpoint를 D3의 정식 초기값으로 재사용하지 않는다.

D4의 초기 성적 조건 제안은 기존53개 검출 유지, 정상 오경보≤2/54 및≤12/256이다. 두 정상 분모 모두5% 이하에 해당한다. **미탐 개선이라고 하려면 기존 미탐0019·0024 중 적어도1장을 추가 검출해야 한다.** 53/55를 유지하고 정상 오경보만 줄면 오경보 개선 후보라고 부른다. 작은 표본의 한두 장 차이와 불확실성을 반드시 함께 표시한다.

D5의 전체사진 warm p95≤2초는 연구 비용 목표다. UI·파일 저장·API 응답 시간이 아니다. 학습 최종 모델 재로딩은 동일 환경 원점수 오차≤1e-4 및 판정 변화0을 제안한다. seed42 결과가 좋아도 우연 여부를 확인하기 전 단일 최종 모델로 승격하지 않는다.

## 5. 실행 전 남은 결정과 하지 않을 일

**다음 승인 범위는 EfficientAD-S 실행기 준비와 보조 데이터·가중치 취득 및100step 이내 자원 점검이다. 장시간 정식 학습은 자원 보고와 고정 실행 카드 확인 후 진행한다.** 아직 Windows 명령은 없다. 실행기가 준비되지 않은 상태에서 라이브러리 예제를 바로 돌리지 않는다.

훈련 step, optimizer 일정, 지도 보간, 정상화 표본 추출, 정상 재표집 수·허용폭, 추가seed 비용은 D1/D2에서 명시하고 D3 전에 동결한다. 항목이 미정이면 그 단계는 대기이며, 완료·승인으로 표시하지 않는다. 재표집 허용폭을 후보 성적을 본 뒤 정하지 않는다.

관찰한 MPI109장·정상256장은 계속 개발·회귀 자료다. 모델 종류를 바꿔도 새로운 독립시험이 되지 않는다. 직접 촬영은 요구하지 않으며, 새 독립 자료가 없으면 일반화 검증은 미완료로 남긴다. 이미지·마스크는 재배포하지 않는다.

이번 검토로 PatchCore 전체가 실패했다고 결론내리지 않는다. 잘 되는 Q90 기준선은 보존하고 비교 범위만 제한한다. 서비스 통합은 MPI 연구 성공과 별개로 진행할 수 있으며 새 모델을 자동 합격·생산 조치에 연결하지 않는다.
