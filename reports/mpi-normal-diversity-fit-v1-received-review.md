# MPI 정상 다양성 후보 학습과 보정 결과 검토

검토일: 2026-10-02. 실행 코드: `36bbc65`.
**새 모델 생성·정상 보정·저장 후 재현 검증은 완료됐다. 첫 시도의 GPU 예약7GiB 초과는 실제 제한 위반으로 남으며,전체 자원 조건까지 통과한 것은 아니다.**
재실행에서는 모델을 다시 학습하지 않고 저장 모델을 읽어 정상 점수 계산을 완료했다.
불량 시험은 아직 수행하지 않았으므로 미탐·오경보 개선이나 서비스 채택을 주장하지 않는다.

이는 모델 저장·보정 계산의 일관성 확인이지,새 불량을 더 잘 찾는다는 증거가 아니다.
경고 기준2.29726은 확률/정확도가 아니며 다른 모델의 원점수 임곗값과 숫자 크기만 비교할 수 없다.

정상 개발 집합에서는10/128장,보정 집합에서는9/169장이 경고된다.

그 판단에는 다음 단계의 고정 정상54/256장 결과가 필요하다.

## 메모리 오류와 재개 결과

전체 계산 시간은실패 시도 포함1,391.605초,약23분12초다.4시간 상한 안이지만 첫 시도의GPU예약7GiB 초과는 없어지지 않는다.
보고서의 `attempts_with_errors=1`, `resource_review_required=true`가 이를 올바르게 보존하고 있다.
원본 해시·ZIP 내보내기·오프라인 대기는 이 시간에 포함되지 않는다. 주기 표본 수를0.1초와 곱해 실행시간으로 해석하지 않는다.
GPU 전체 점유는 다른 작업/드라이버 등을 포함할 수 있어 모델 전용 메모리가 아니다.

학습 자체의 기록은 특징 추출3.829초,대표 패치 선정673.915초,학습/저장 합계679.127초다.
학습 직후까지의예약 peak는약6.514GiB로 상한 안이었다. 이후 같은 프로세스에서 보정에 들어갈 때7.715GiB로 증가했다.
재실행 기록에는 학습 시간이 없고,정상 점수/기준 계산348.314초와재로드/검증350.257초만 있다.
따라서 저장 모델 재사용이 작동했고,학습 없이 새 프로세스에서 수행한 보정·재로드는7GiB 안에서 완료됐다고 볼 수 있다.

이는 학습에서 보정으로 넘어가는 메모리 관리가 문제였다는 가설을 지지한다.
다만 두 시도의전체 peak만으로 캐시·조각화·특정 버퍼 중 무엇이 원인인지 구분할 수는 없다.
모델을축소하거나학습 사진을줄이거나7GiB 제한을높이지 않았다. 한번에끝나는 실행 흐름의자원조건은 미통과로 기록한다.
저장 모델로재개한성공을원래단일실행의자원통과로소급해해석하지 않는다.

## 결정과 다음 단계

**C단계 산출물의 학습·보정·재현성 확인은 완료,전체 자원 조건은 초과 이력 때문에 미통과/추가 검토 상태다.**
새 모델과보정계약은 연구 비교에 사용할 수 있도록 보존하며,정상64장 재선정이나재학습을 요구할 근거는 없다.

다음으로 권하는 D단계는 고정 모델·척도·임곗값을 바꾸지 않고 관찰109장과정상256장의 성적,
정상 개발/보정 재표집3,000회의민감도,별도프로세스warm처리시간을 비교하는 것이다.
기존불량53장검출보존,오경보≤2/54·≤12/256 및민감도·비용 기준은 그대로 유지한다.
이 비교는 연구 진단으로 진행할 수 있지만,성적이 좋아도 이번 메모리 위반을 지우거나 전체 후보 통과로 선언해서는 안 된다.
학습→보정 전환을 안정적으로 분리·정리하는 실행 경로의 수정과 확인은 별도 작업으로 남는다.

현재 요청에서는 D단계 코드를 구현하거나시험을실행하지 않았다. 추가 연구실 명령도 없다.
완료한 학습 명령을 다시 돌릴 필요는 없으며 자동PASS·서비스교체·새로운독립성능주장은 금지한다.
