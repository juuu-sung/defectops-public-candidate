# EfficientAD-S 사전 점검 실행 준비

2026-10-03. 상태: 실행기 준비 완료, 실제 Windows/CUDA 결과 미수령.

사용자가 동의한 범위는 보조 자료·가중치 취득 절차와 최대100회 정상-only 자원 점검이다.
장시간 정식 학습·불량 평가·서비스 교체는 포함하지 않는다.

## 구현과 검증

- 공식 배포 두 파일의 SHA256을 고정하고, 이미지96개와small teacher만 안전한 로컬 경로로 준비한다.
- 검산된 기존 normal-bank 준비 ZIP에서 원래 정상64장 중8장·96타일을 선정한다. Mac에서 명단과 경로를 확인했다.
- 실제 GPU 모듈은 Windows 연구실 환경에서만 실행한다. Mac 로컬에서는 가짜 runtime으로 orchestration을 검증했다.
- checkpoint·난수 상태·optimizer 복원, 보정 전 정상 지도 비교, 최대100회 시도 제한, 누적15분 감시, 실패 보존, JSON-only 전달을 구현했다.
- 완료 결과의 재사용, 변조·경로 탈출·중복·부분 실행·재로딩 차이·자원 실패·경계 재개·archive 선택 추출을 테스트했다.

신규 테스트19개 통과. 최종 전체 테스트는683개와52 subtest 통과,103.45초이며 기존 경고3개가 남았다.
Python 문법 검사와 diff 공백 검사도 통과했다. Mac에 CUDA와PowerShell이 없어 실제 학습·다운로드·PowerShell 실행은 하지 않았다.
기존 설치 라이브러리의 API는 공식 Anomalib2.2.0 소스와 대조했으며 이것이 GPU 실행 성공을 대신하지는 않는다.

## 결과 해석

이번 ZIP은 모델 정확도 보고서가 아니다. 손실이 유한하고 재로딩이 일치해도 미탐 감소를 주장하지 않는다.
예비12타일 시간은1회 측정이며 p95·서비스 SLA로 쓰지 않는다. 보조96장·제품8장만 사용하는
resource probe와 이후 정식 학습의 표본 구성·통계·학습 일정은 구분한다.

불량 이미지·마스크 접근0, 정상128/169장 보정0, 임곗값 산출0, 기존 모델 변경0을 실행 범위로 고정했다.
실제 범위 준수와 자원 사용량은 연구실 handoff 수령 후 다시 검산한다.

## 다음 행동

[실행 안내](../docs/mpi-efficientad-probe-v1.md)에 따라 연구실에서 실행하고
`artifacts/handoff/mpi-efficientad-probe-v1.zip`을 전달한다. 오류 시 출력물을 삭제하지 않고 오류를 전달한다.
결과를 본 뒤 정식 학습 시간과 안정성 기준을 고정하며, 실행기가 자동으로 다음 학습을 시작하지 않는다.
