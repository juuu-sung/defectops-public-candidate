# SuperSimpleNet 잡음 강도 비교 실행 준비 검토

2026년 10월 5일. 사용자 승인 범위인 **같은 8타일과 500회 조건에서 합성 잡음 강도만 바꾸는 비교**를 구현했다. 새 후보는 0.03과 0.06 두 개로 제한했다. [실험 조건과 연구실 명령](../docs/mpi-supersimplenet-noise-strength-v1.md)에 입력, 해석 범위, 자원 상한, 재개 방식을 고정했다.

## 구현 및 검증

- 직전 varying500 0.015 모델을 읽기 전용 기준으로 사용한다. 별도 새 복사본에서 두 후보를 각각 학습한다.
- 모든 모델을 같은 0.015·0.03·0.06 강도 및 다섯 난수로 평가한다. 참고42를 평균에서 제외한다.
- 정상 대조, 같은 위치 구분력, 합성을 넣지 않은 점수에 합성 label을 붙인 대조 지표를 함께 기록한다.
- 매 step 마스크가 직전 baseline과 일치해야 하며 실제 잡음 RMS도 검증한다. 잡음 설정은 오류 시에도 원복한다.
- 원본·baseline·후보 checkpoint 목적과 해시, 다른 후보 오재개, optimizer step, 최종 세 강도 재현을 확인한다.
- 완료된 단계만 재사용한다. 정상적인 중단 후 같은 난수로 재개하며 실패·강제 종료·예산 초과는 자동 재시도하지 않는다.
- ZIP에는 원시 출력 배열·수치·receipt만 포함하며 원본 이미지와 가중치는 포함하지 않는다.

전체 pytest 실행은 **928개와 52 subtest 통과**였다. 이후 정상 사진 점수의 반사실 대조 집계를 명시하고 후보 혼동 방어 테스트를 보완한 뒤, 전용 **18개 테스트가 다시 통과**했다. 이 마지막 소규모 보완 후 전체 suite를 다시 실행한 것으로 주장하지 않는다. Python 구문 검사와 변경 공백 검사도 통과했다.

별도 검산에서 기존 varying ZIP에 기록된 동결 코드·문서 **16개 hash가 모두 그대로**였다. 기존 재현 코드를 수정하지 않고 신규 실행기와 프로토콜을 추가했다.

## 아직 확인하지 않은 내용

Mac에는 해당 torch/CUDA 환경이 없어 실제 0.03·0.06 학습과 GPU 재로딩은 실행하지 않았다. CPU 테스트는 가짜 runtime으로 실행 순서·저장·보호 장치를 확인하는 것이며 합성 이상 구분 성능이나 GPU 자원 통과를 입증하지 않는다. PowerShell 래퍼도 실제 Windows에서는 다음 실행으로 확인해야 한다.

학습량·데이터 확대, 실제 불량 시험, 임곗값 변경, Q90 및 기존 서비스 교체는 하지 않았다. 결과 수령 후 먼저 원래 강도 0.015에서 정상 대조 대비 개선이 있는지 검토한다. 합성 강도 확대만으로 실제 결함 문제가 해결됐다고 해석하지 않는다.
