## 한 줄 결론

PatchCore는 세 seed에서 고정 임곗값 판정이 완전히 동일했고 PaDiM보다 불량 유출을 크게 줄였다.
현재 정확도 우선 주력 후보는 PatchCore가 맞다. 그러나 같은 test를 반복해서 본 탐색 결과이므로
가장 높은 AUROC를 낸 seed 44를 새로 고르지 않고, 이미 API·UI에 연결해 검증한 seed 42 bundle을
유지한다.

## 속도 해석

평가 과정의 p95 지연시간 평균은 PaDiM 39.26 ms, PatchCore 72.40 ms였다. PatchCore의 seed별
p95는 123.24 / 47.36 / 46.60 ms로 seed 42만 높아 실행 당시 장비 상태가 섞였을 가능성이 있다.
따라서 이 세 수치로 seed나 모델을 고르지 않는다. 모델을 한 번 로드한 별도 warm benchmark의
전체 sample p95 95.91 ms와 처리량 12.56 images/s를 현재 PatchCore 운영 속도 기준으로 유지한다.

## 결정

1. 정확도 우선 주력 후보는 PatchCore로 유지한다.
2. 현재 검사 API·UI는 PatchCore seed 42 bundle을 계속 사용한다.
3. seed 44의 AUROC가 가장 높더라도 현재 test를 근거로 bundle을 교체하지 않는다.
4. PaDiM은 더 빠르고 작은 비교 baseline으로 보존한다.
5. PatchCore도 FN 3개가 있으므로 자동 PASS 또는 실제 제품 합격 판정에는 사용하지 않는다.

## 한계와 다음 검증

- 같은 MVTec test 100장을 모든 seed에서 재사용했다.
- seed 42 결과를 본 뒤 PatchCore 반복 실행을 설계했다.
- 공개 데이터 한 품목의 100장 결과로 실제 공장 성능이나 domain shift를 알 수 없다.
- 현재 결과를 보고 임곗값, ROI 또는 후처리를 바꾸지 않는다.
- 다음 모델 변경은 새 미관찰 validation/holdout에서 규칙을 먼저 고정한 뒤 검증한다.
- 데이터가 당장 없다면 두 번째 MVTec 품목으로 파이프라인 일반화를 먼저 확인하되, 그 결과도
  실제 생산 성능이 아닌 포트폴리오용 공개 데이터 검증으로 구분한다.
