# EfficientAD 두 저장 모델 평가 실행 준비

2026-10-04. 사용자 진행 동의에 따라 [실행 계획](../docs/mpi-efficientad-checkpoint-evaluation-v1.md)을 구현했다.
목표는 학습 연장이 아니라10k·30k 저장 모델의 별도 정상 보정과 제한 회귀검사다.
결과 수령 전에는 이전 모델의 성능 우위나 서비스 채택을 주장하지 않는다.

## 구현 범위

- 원본archive, reviewed fit·trajectory ZIP, checkpoint 영수증과137/141/149개 역사적 소스 지문 검증.
- 정상128/169장 모델별 새 지도·보정 계약 저장, 재로딩 첫8사진 재현 통과 후12장 검사.
-12장 탈락은 해당 모델 확대 생략, 다음 고정 모델 진행. 실행 오류와 자원 초과는 전체 중단·보존.
- 통과 시 관찰109장·정상256장 비교와 기준선/후보 순차 warm 측정. 성적·속도 통과 시600회 민감도.
- 사진 단위 원자적 저장·파일 지문·실행 잠금·Ctrl+C 이어가기·강제 종료/실패 자동 재시도 거부.
- JSON 전용 handoff에는 두 모델의 계약·점수·검사 단계·자원·지도 영수증을 보존한다.
- 새 학습·추가 저장 시점 탐색·자동 모델 선택·서비스 교체·자동 PASS는 없다.

## 검증

신규 CPU 테스트16개 통과. 가짜 추론기를 사용해 실제 파일 저장·내보내기와 중단 재개를 검사했다.
전체 CPU 테스트777개·52 subtest도 통과했다. 기존 의존성 경고1건과 중복 ZIP 거부 테스트의 예상 경고2건이 있다.
두 모델 독립 보정값,12장 전 확대 차단, 성적/속도별 민감도 gate, 완료 재실행,
map·sample·보정 계약 지문, 실패 재로딩 시 불량 접근0, 실패/강제 종료 거부,
자원 초과 시 해제, 고정 두 시점 CLI 경로, trajectory 지문·목록·모델 연결을 확인했다.
내보내기 JSON을 모델별 하위 폴더로 쓰던 초기 문제를 테스트에서 발견해 평면 파일명으로 수정했다.
자원 중단 중 모델을 중복 해제하지 않도록 정리했다.

기존 fit137개·evaluation141개·trajectory149개 소스 지문 변경0을 전달 ZIP과 대조했다.
CLI 도움말·Python 구문·git 공백 오류 검사를 통과했다.
실제 Windows PowerShell·CUDA 실행은 Mac에서 검증하지 않았으며 연구실 실행 결과가 필요하다.
CPU 가짜 추론 테스트는 학습 성능·실측 비용 증거가 아니다.

## 인계

다른 GPU 작업을 정상 종료하고 원본·기존 결과를 보존한다. 여유 디스크30GiB·GPU6GiB가 필요하다.
모델별 계산4시간·RAM20GiB·GPU reserved6GiB 상한이다. 초기 입력 해싱과 ZIP 내보내기는 계산 시간 밖이다.
오류 시 새 학습·결과 삭제·경고선 수정 없이 전체 오류를 전달한다.
전체 절차가 완료되면 `mpi-efficientad-checkpoint-evaluation-v1.zip`을 검토한다.
