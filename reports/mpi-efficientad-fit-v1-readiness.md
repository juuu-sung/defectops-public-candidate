# EfficientAD 정식 학습 실행기 준비 검증

2026-10-04. 사용자 요청에 따라70,000회 학습과 정상 보정·재로딩을 준비했다.
실제 장시간 Windows/CUDA 실행은 아직 하지 않았다. [실행 안내](../docs/mpi-efficientad-fit-v1.md)

## 구현과 검증

- 기존64사진·768타일, 개발128사진·1536타일, 보정169사진·2028타일을 수령 ZIP으로 재구성했다.
  정상 경로·사진 ID·픽셀 중복 분리 검사를 통과했다. 불량 이미지는 열지 않았다.
- EfficientAD 사전 점검 ZIP을 고정 SHA256으로 잠그고 환경·설치 모델 소스 지문을 이어받는다.
- 모델 초기화·통계는 새로 시작하며70,000회 최종 모델만 선택한다. 후반5% 학습률0.1배.
- 매1,000회 저장, 단계별 원자적 공개·체크섬, 정상 중단 재개, 누적 시간·시도량 제한을 구현했다.
- 지도·보정 계약을 분리 저장한다. 원시 ST/AE 지도를 보존하고 음수 보정값을 임의로 자르지 않는다.
- 정상297사진 재로딩 지도·점수·판정을 첫 고정 계약과 비교한다. 실패 시 기준을 다시 맞추지 않는다.
- 전달 ZIP은 JSON만 포함한다. 원본·보조 이미지·가중치·지도는 연구실 로컬에 남는다.
- 다음 회귀12장 명단·전체 성적·지도 보정을 포함한 정상 재표집 조건도 실행 정책에 미리 고정했다.
  후속 평가·bootstrap은 이번 실행기에 포함하지 않는다.

## 테스트 결과

- 전체 `python -m pytest -q`: **701 passed, 52 subtests passed**,93.70초. 기존 경고3개.
- 정식 학습·사전 점검 집중 테스트: **37 passed**. 이 중 정식 경로 신규18개.
- Python 구문 검사·CLI `--help`·`git diff --check` 통과.
- 고정 학습률 경계, 독립 입력 순서, train-only 보조 자료, 음수 지도 보정, 정확 분위수,
  정상 코호트 분리, 저장·재개·누적 예산, 체크포인트 공백·변조·강제종료 흔적 거부,
  재로딩 차이 실패, 전달 ZIP 재사용·변조 거부를 검사했다.

CPU 대역 런타임은 작업 흐름 검증일 뿐 EfficientAD 수렴·정확도·CUDA 호환성의 새 증거가 아니다.
PowerShell 실행기는 Mac에서 직접 실행하지 못했다. 기존 정상 작동 실행기와 같은 경로 처리·호출
형식을 사용했으며 실제 Windows 결과를 받아 확인한다. RTX5060에서의 짧은 실제 연산 근거는
[D2 수령 결과](mpi-efficientad-probe-v1-received-review.md)이고 장시간 비용은 미확정이다.

## 보호한 범위

기존 실험 실행기·모델·서비스·데이터는 변경하지 않았다. 관련 없는 프로젝트 검토 초안2개도 보존했다.
자료 삭제·자동 재선정·학습량 자동 축소·불량 조기평가·시험 기반 checkpoint 선택은 하지 않는다.
학습 데이터 한도가 바뀐 것이 아니라 같은64장으로 학습 업데이트를 충분히 수행하는 새 후보1개다.
