# MPI PatchCore 지도 수치 차이 진단 결과

2026년 10월 8일. **이번 중단은 모델 학습 실패가 아니라, 서로 다른 정밀도로 계산한 지도의 차이가 기존 교차정밀도 허용오차를 넘은 수치 검증 문제다.** 실제 영역 점수의 변화는 작지만 지도 일부 픽셀 차이는 기존 기준을 넘는다. 허용오차만 늘려 통과시키지 않고, 진단용 지도 계산의 정밀도를 통일하는 수정이 적절하다. 기존 학습 모델·경고선·서비스는 유지한다.

## 핵심 결과

| 확인 항목 | 결과 |
| --- | --- |
| 진단 대상 | 기존20타일, 총81,920개 특징 위치 |
| 저장 지도와 저장 patch 거리로 재생성한 지도 | 20타일 모두 최대 차이0 |
| 기존 지도 대 고정밀 거리로 만든 지도 | 19/20타일이 기존 지도 허용오차 초과 |
| 지도 최대 절대차이 | 0.0270984, 정상0275의 grid1-3 |
| 지도 허용오차 밖 픽셀 | 5,029/1,310,720, 약0.384% |
| 상위656평균 영역 점수 최대 절대차이 | 0.000493625 |

| 선택된 근접 대표 인덱스 변화 | 3/81,920위치 |

19개 타일이라는 숫자는 불량 검출 실패율이 아니다. 지도 중 한 픽셀이라도 `atol0.001 + rtol0.0001×비교지도값`을 넘으면 그 타일이 실패로 집계된다. 5,029개 픽셀 중4,083개는 정상0275다.

## 가까운 특징 거리에서 수치 상쇄가 확인됨

정상0275의 grid1-3에서 같은 근접 대표320을 비교했다.

| 특징 위치 인덱스 | 공식float32 거리 | 고정밀 행렬식 거리 | 독립 직접 거리 |
| --- | ---: | ---: | ---: |
| 2764 | 0 | 0.072211925900 | 0.072211925915 |
| 3340 | 0.044194173068 | 0.000372022227 | 0.000372025712 |

질의 벡터의 크기는 약86.37이다. 기존 거리 함수는 `sqrt(max(||x||² − 2x·y + ||y||², 0))` 형태다. 서로 거의 같은 벡터에서는 큰 항들을 빼서 작은 차이를 얻는 과정이 float32 반올림의 영향을 크게 받는다. 첫 위치는 이웃을 잘못 고른 것이 아니라, 같은 이웃까지의 거리를0으로 계산한 사례다. 독립 직접 차이의 norm이 고정밀 결과를 지지한다.

저장된 공식 patch 거리와 이를 따로 다시 조회한 공식 patch 거리도0275에서 최대0.03125,0274에서0.000115395,0656에서0.000382483 차이가 났다. 나머지17타일은1e-4 이내다. 이는 이미지 전체 public forward를 다시 실행한 비교가 아니라, 저장된 특징으로 nearest-neighbor 함수를 별도 호출한 비교다. 따라서 이 결과를 기존 전체 모델 재현 실패로 바꾸어 말하지 않는다. 저장 patch 거리로 지도를 재생성한 결과는20타일 모두 정확히 같았다.

## 지도 생성 단계에서도 차이가 커짐

예를 들어 불량0024 grid2-2는 공식 재조회 거리 대 고정밀 거리 최대차이가0.000429인데 저장 지도 대 고정밀 거리 지도 차이는0.004543이다. 공식 patch 거리의 재조회 차이0.0000324를 고려해도 지도 차이가 훨씬 크다. 0961은 지도 차이가0.008102다.

Anomalib2.2.0의 지도 생성은 기본 nearest 보간 후33×33, sigma4 Gaussian 평활화다. 수학적으로 양의 정규화 가중치 평균은 입력의 최대차이를 이렇게 증폭하지 않는다. 따라서 이 현상은 최근접 특징 선택의 변화만으로 설명되지 않으며 지도 계산의 수치 정밀도를 따로 확인해야 한다.

현재 실행기는 백본 재현을 위해 `cudnn.allow_tf32=True`를 유지한다. 이 설정이 지도 평활화의 convolution에도 적용될 수 있다. PyTorch2.8 문서는 TF32 convolution의 입력 유효 숫자가 제한될 수 있음을 설명한다. **TF32가 유력한 원인 후보지만, 이번 ZIP에는 지도 연산의 TF32 on/off 대조가 없으므로 직접 확정한 원인은 아니다.**

첨부 배열만으로 nearest 확대와 같은 sigma/반사경계의 Gaussian 평활화를 NumPy float64로 독립 재구성했다.0274·0275·0656을 제외한17타일에서 두 거리 배열의 CPU 지도 차이는0.000124 이하였지만 GPU 저장 지도 차이는0.002274~0.008102였다. 이는 지도 계산 단계의 추가 수치 영향을 뒷받침한다. CPU 커널은 공식 설정을 따라 별도로 계산했으며 설치된 GPU 커널 버퍼를 직접 읽은 것은 아니다.

TF32형 입력·커널 반올림 모사도 확인했다. GPU 지도와의 최대차이는타일별 약0.000337~0.004279로, 고정밀 CPU 기준의 약0.006992~0.010574보다 작았지만 일치하지는 않았다. 이 모사를 실제 CUDA 연산의 비트 단위 재현이나 TF32 원인 확정으로 사용하지 않는다.

## 실제 영역 점수 영향은 작음

| 사례 | 저장 상위656평균 | 고정밀 거리 지도 상위656평균 | 변화 |
| --- | ---: | ---: | ---: |
| 불량0024 grid3-2 | 41.69211658 | 41.69261021 | +0.00049363 |
| 정상0706 grid3-2 | 42.86016119 | 42.86016119 | 0 |
| 정상0275 grid1-3 | 43.29044180 | 43.29043757 | −0.00000423 |

0275는 차이가 큰 저점수 부분이 있어도 최상위1%에는 영향이 거의 없었다. 따라서 지도 전체 픽셀의 교차정밀도 일치 여부와 실제 영역 점수의 재현성은 분리해야 한다. 반대로 상위 점수 영향이 작다는 이유로 모든 지도 차이를 무시해서도 안 된다.

이번에는 전체후보3,145,728개를 조회하지 않았다.0706의 정상 점수가 실제로 개선되는지,0024 결함 반응이 유지되는지는 여전히 미확인이다. 기존 대표 모델의55/55 검출·정상오경보1/54와15/256을 변경하지 않는다.

## 무결성과 검증 범위

ZIP SHA256은 `b5e521f5fb3f511829697dad299b90d3660f44b75c1b45af60edefcb4098e08a`다. ZIP CRC·중복 파일명 없음·184개payload 해시·새 진단/이전 실행 소스 지문·실패 실행 identity·이전20타일 선정 연결을 확인했다.20개 저장 지도는 이전 점수 중첩 ZIP의 지도 배열과 정확히 같았다.

첨부160개 배열의 유한값과 보고서의 거리 차이·지도 차이·초과 픽셀수·인덱스 변경·상위656평균을 다시 계산했다. 저장 공식 patch 거리 자체는 이번 ZIP에 없으므로 `saved_native_vs_public_repeat` 통계는 연구실 기록이다. 또한 모델 실물·원질의 특징·전체 bank가 없어40개 전수조회나81,920개 이웃 벡터 norm을 Mac에서 재실행한 것은 아니다.

RAM 표본최대2.877GiB, GPU allocated peak2.660GiB·reserved peak2.908GiB, 장치 전체 사용량 표본최대4.043GiB다. 메모리 초과에 따른 중단은 아니다. 기록된74.817초는 이전 실패 실행의 시간이며 이번 진단의 소요시간이 아니다. 이번 ZIP에는 현재 진단 완료 시간이 없으므로 sampling 횟수로 추정하지 않는다.

## 다음 수정 방향

재학습·대표 기준표 확대·경고선 변경은 필요하지 않다. 다음은 모델 수정이 아니라 진단용 수치 계산의 정리다.

1. 기존 이미지 전처리·백본·모델 재현 설정은 그대로 보존한다. TF32를 모델 전체에서 끄면 특징 자체가 달라질 수 있으므로 그렇게 하지 않는다.
2. 저장된 거리 배열로 지도 생성만 제한해 TF32 on/off 및 독립 float64 기준을 대조한다. 검증에는 같은 Gaussian 커널과 보간·경계 설정을 사용한다.
3. 대표 bank와 전체후보의 진단 지도는 같은 안정적인 고정밀 경로로 통일한다. 기존 공식 지도는 이력 대조로 보존하고, 교차정밀도 차이·영역 점수 영향을 별도 보고한다. 기존 공식 출력 재현 기준과 고정밀 계산 검증 기준을 섞지 않는다.
4. 새 수치 계약과 검사 조건을 먼저 고정한 수정판에서 기술 점검 후 동일20타일 전체후보 비교로 이어간다. 기존 실패 폴더를 바꾸거나 단순 허용오차 확대만으로 재개하지 않는다.

현재는 결과 검토와 수정 방향 제안까지 완료했다. 운영 코드·지도 비교 실행기·허용오차는 변경하지 않았으며 기존 실행 명령을 다시 실행할 단계는 아니다.
